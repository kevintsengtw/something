# VS Code 1.139 重點摘要

> 來源：[Visual Studio Code 1.139](https://code.visualstudio.com/updates/v1_139)｜發布日期：2026 年 9 月 23 日（Stable）
> 本文件依據「全文翻譯」逐項整理。

## 版本主軸

此版本聚焦三件事：大型 agent 工作階段清單更快、Dev Container 支援擴展到遠端專案、改善日常編輯體驗。

---

## 一、Agents

### 背景：Agent host

- Agent host 在以 Agent Host Protocol（AHP）為基礎的專用處理程序中執行 agent harness。
- 因此可從多個 VS Code 視窗連線到同一個工作階段。
- 架構與工作流程詳見 agent host 部落格文章。

### 1. 在遠端主機上的 Dev Container 中執行 agent 工作階段

- **設定**：`chat.agentHost.devContainer.enabled`（僅限 Agents 視窗）
- **用途**：讓 agent 以正確的工具與相依套件建置、測試遠端專案，不必在筆電或遠端主機上重複設定工具鏈。
- **變更範圍**：Dev Container 工作階段從「本機資料夾」擴展到 **SSH、Tunnel、WSL 主機**上的專案。
- **使用方式**：
  1. 啟用 `chat.agentHost.devContainer.enabled`。
  2. 在 Agents 視窗的資料夾選單中選取 **Use Dev Container**。
- **前提條件**：
  - 遠端資料夾必須具備受支援的 Dev Container 設定。
  - 遠端主機上必須有可用的 Docker。
- **推出狀態**：逐步推出中，設定可能尚未預設啟用，可手動啟用立即試用。

### 2. 更快的工作階段清單載入

- **做法改變**：agent host 將輕量的工作階段與聊天中繼資料保存在集中式目錄（catalog），不再於每次建立清單時開啟每個對話資料庫。
- **資料隔離**：完整對話內容仍隔離存放在各自的工作階段與聊天資料庫中。
- **效益特性**：先前做法的工作量與工作階段數量成正比，因此工作階段越多，改善越明顯；工作階段少的話差異較小。
- **實測數據**（開發機、約 645 個工作階段）：

| 操作 | 之前 | 之後 | 改善幅度 |
| --- | --- | --- | --- |
| 啟動後第一次列出工作階段 | 1.3 秒 | 0.1 秒 | 約快 12 倍 |
| 重新整理工作階段清單 | 0.6 秒 | 0.15 秒 | 約快 4 倍 |

- **移轉**：此版本之前建立的工作階段會在背景自動移轉。

### 3. 精簡工作階段清單（Compact View）

- **啟用位置**：Agents 視窗的工作階段清單檢視 → **Compact View**。
- **顯示行為**：
  - 靜止時只顯示工作階段標題。
  - 滑鼠停留或焦點移到該列時，顯示工作區詳細資訊。
  - 工作階段需要輸入或核准時，該列會展開，確保請求保持可見。
- **進度顯示**：
  - 進度顯示在負責該工作的聊天所在列上。
  - 摺疊工作階段時，父列會彙總其隱藏聊天的進度。

### 4. 篩選空的工作階段群組

- **操作**：在 **Filter Sessions** 中停用 **Empty Groups**。
- **效果**：隱藏空的自訂群組與空的 Chats 區段。
- **儲存與重設**：偏好設定儲存在設定檔（profile）中，並隨其他工作階段清單篩選條件一起重設。

### 5. 就地重新命名工作階段與聊天

- **對象**：工作階段或巢狀聊天，直接在工作階段清單中重新命名。
- **操作方式**（三選一）：
  - 按兩下標題。
  - 使用 **Rename** 內容功能表動作。
  - 將焦點移到該列後，工作階段按 F2、巢狀聊天按 F2。
- **防呆**：內嵌驗證防止空白標題；取消時還原為先前的標題。

### 6. 選擇聊天在工作階段中的呈現方式（Preview）

- **設定**：`sessions.showChatTabs`（僅限 Agents 視窗）
- **背景**：一個 agent 工作階段可包含多個聊天，每個聊天代表不同的對話或情境。
- **切換位置**：當工作階段包含多個聊天時，從工作階段標頭選單中選擇。
- **兩種模式**：
  - **Multiple**：每個聊天各自顯示在一個索引標籤上。
  - **Single**：只顯示作用中的聊天，隱藏索引標籤列。
- **狀態保留**：切換時會保留已開啟的聊天、作用中的聊天與對話狀態。
- **Single 模式例外**：明確開啟到側邊的聊天，仍是具有各自標頭動作的獨立窗格。

## 四、提議的 API（Proposed APIs）

### 驗證工作階段上的存取權杖存留期（`authSessionExpiration`）

- **問題**：
  - `AuthenticationSession` 公開存取權杖，但沒有權杖有效期限的資訊。
  - 將認證傳給具有自有 refresh callback 的 SDK 時，擴充功能無法區分「永不過期」與「即將過期」的權杖。
  - 結果：不是不必要地重新整理認證，就是讓長時間執行的作業在權杖過期時失敗。
- **提議內容**：為 `AuthenticationSession` 新增選用屬性 `readonly expiresAfter?: number`。
- **值的語意**：
  - 驗證提供者傳回工作階段當下，存取權杖的**剩餘存留期（毫秒）**，而非絕對的過期時間戳記。
  - 理由：擴充功能主機可能與用戶端在不同機器上執行，兩者時鐘可能不一致。
- **提供者行為**：
  - 傳回快取工作階段的驗證提供者，每次都會重新計算此值。
  - 權杖過期時間未知時，保留為 `undefined`。
  - 內建的 Microsoft 帳戶提供者會提供此值。
- **回饋管道**：可在 API 提議 issue（#335184）回饋；開發方式參閱「使用提議的 API」文件。
