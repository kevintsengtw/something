## [版本回顧](https://code.visualstudio.com/updates/v1_144#_release-recap)

通往 GitHub Universe（[歡迎線上參加！](https://githubuniverse.com/)）的路，是由大量的 pull request 鋪成的！所以，讓我們退一步，回顧一下最近推出了哪些功能。

- 還記得以前只要關閉用戶端，agent session 就會跟著停止嗎？我們打造了 [Agent Host](https://code.visualstudio.com/docs/agents/concepts/agent-host)，這是一個獨立的處理程序，讓你的 agent 可以在本機或遠端持續執行。

- 借鏡 language server 的思路，我們設計了 [Agent Host Protocol（AHP）](https://microsoft.github.io/agent-host-protocol/)，讓任何用戶端都能與 agent session 互動。一下子，VS Code、Copilot CLI、GitHub Copilot App 與 github.com 之間就有了 session 延續性，讓你可以從上次中斷的地方繼續。

- Agents 視窗讓你從單一介面，管理跨工作區與環境的 agent，不論是你自己啟動工作，或是使用[自動化](https://code.visualstudio.com/docs/agents/run/automations)來處理重複性任務。

- Agent 現在預設由 [Copilot harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses) 驅動，這與 Copilot Code Review、Copilot CLI、Copilot App 及 Copilot Cloud session 所使用的是同一個 harness。Agent 自訂只要撰寫一次，就能在所有這些體驗中一致地使用。

- 如果你偏好 [Anthropic 的 Claude Code harness 或 OpenAI Codex 的 harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses?id=requirements-and-setup)，只要改用它們並搭配你的 Copilot 訂閱，就能享受熟悉的 VS Code 開發體驗。

- 隨著我們持續提供來自不同供應商的新模型，你要如何判斷哪一個最適合你的任務？透過[模型比較](https://code.visualstudio.com/docs/agents/run/compare-models)（又稱 Agent Bake-Off），你可以對多個模型與 harness 執行同一個提示詞，看看哪一個表現最好。偏好放手交給系統處理？使用 [Copilot Fusion](https://code.visualstudio.com/docs/agents/concepts/language-models#_copilot-fusion) 為你的任務選擇最佳模型，並協調多個模型協同作業。

- 我們提供視覺能力已有一段時間，但你們一直要求更多。等待結束了，現在你也可以提示 agent 直接在聊天中[產生圖片](https://code.visualstudio.com/docs/chat/chat-overview#_generate-and-edit-images-experimental)。

- 聊天並不總是每項任務的最佳介面。透過 [canvas 支援](https://code.visualstudio.com/docs/agents/run/canvases)，你可以建立豐富的互動式 UI 來與 agent 互動，並將它們的輸出視覺化。

- 與 agent 一起寫程式，可以不只是撰寫程式碼。讓 agent 與瀏覽器互動來驗證結果，或讓它們[操作你電腦上的應用程式](https://code.visualstudio.com/docs/agents/run/tools#_control-desktop-applications-experimental)來進行自動化與任務執行。

- 有需要，就動手打造！所以我們打造了全新且美觀的 [Markdown 編輯器](https://code.visualstudio.com/docs/languages/markdown#_markdown-editor)。你可以直接編輯渲染後的 Markdown，而不必編輯原始 Markdown。當然，如果你偏好，仍然可以編輯原始碼。

- 如果你還沒注意到，我們也[翻新了 VS Code 的整體外觀與風格](https://code.visualstudio.com/blogs/2026/10/15/modern-ui)，讓它在淺色與深色主題下都顯得清新美觀。

在我們的 [VS Code Wrapped 部落格文章](https://code.visualstudio.com/blogs)中，閱讀這一切以及更多內容。

## [Session 延續性](https://code.visualstudio.com/updates/v1_144#_session-continuity)

### [在雲端執行並延續 Copilot 任務](https://code.visualstudio.com/updates/v1_144#_run-and-continue-copilot-tasks-in-the-cloud)

Cloud session 讓你從 VS Code 執行 Copilot 任務，而不必讓你的開發機器保持上線。你的存放庫與工具會在 GitHub 基礎架構上的受管理環境中執行。

從編輯器視窗的 **Chat 檢視**或 **Agents 視窗**，你可以：

- 選取 **Cloud** 並選擇一個 GitHub 存放庫來開始任務。
- 傳送後續指示、回應核准要求，並檢閱 agent 的變更。
- 從 session 清單重新開啟既有的 cloud session，以延續同一段對話。

你的 cloud session 也可以從其他 Copilot 用戶端存取。例如，你可以在 GitHub.com 或 **GitHub Mobile app** 上查看進度，然後回到 VS Code 繼續工作。

Cloud session 使用獨立的工作區。本機尚未提交的變更不會自動複製過去。新的雲端體驗需要付費的 Copilot 方案，並受組織原則約束。

### [管理遠端環境](https://code.visualstudio.com/updates/v1_144#_manage-remote-environments)

VS Code 讓你能在不同的（遠端）環境中執行 agent 並進行開發工作。為了讓這些環境更容易管理，我們推出了 **Remote Environments** 對話方塊，把你的 GitHub Environments、Dev Tunnels、WSL 發行版與 SSH 主機集中在同一處。

在環境選擇器底部選取 **Manage Remote Environments**，即可查看每個遠端的狀態、連線或中斷連線，並選擇哪些遠端要顯示在選擇器中。

![圖：Remote Environments 對話方塊，顯示 GitHub Environments、Dev Tunnels、WSL 與 SSH 群組、每個遠端的狀態，以及已連線通道的內嵌動作。](https://code.visualstudio.com/assets/updates/1_144/remote-environments.webp)

進一步了解[遠端 agent session](https://code.visualstudio.com/docs/agents/run/remote-agent-sessions)。

### [Cloud Automations（預覽）](https://code.visualstudio.com/updates/v1_144#_cloud-automations-preview)

**設定：** `chat.automations.cloud.enabled`

直接在 Agents 視窗中建立與管理 Copilot 雲端自動化。此功能預設啟用，雲端自動化會在 GitHub 基礎架構上依排程或因應存放庫事件而執行，即使你的電腦關機也一樣。

要建立雲端自動化，你可以請 agent 幫你設定，或使用 Agents 視窗中 Automations 檢視的 **Create Automation** 按鈕。

透過雲端自動化，你可以：

- **設定因應 issue 或 pull request 事件而執行的自動化**：在存放庫發生活動時自動採取行動。例如，在 issue 指派給你時自動進行分類（triage）。
- **與團隊在雲端建立共用工作流程**：建立對所有可存取該存放庫的人都可見、並以 Copilot 身分行動的自動化。
- **精確控制 agent 何時執行以及能做什麼**：限制允許的工具並加入篩選條件，精確控制你的自動化。例如，在你被指派帶有特定標籤的 issue 時觸發自動化。

![圖：建立雲端自動化的介面。](https://code.visualstudio.com/assets/updates/1_144/cloud-automations.webp)

若要深入了解，請參閱 Visual Studio Code 文件中的[建立與管理 agent 自動化](https://code.visualstudio.com/docs/agents/run/automations)。

### [Agent Host Protocol v1.0](https://code.visualstudio.com/updates/v1_144#_agent-host-protocol-v10)

我們已發布 [Agent Host Protocol](https://microsoft.github.io/agent-host-protocol/) 的第一個版本，這是 VS Code 用來與其本機及遠端機器上的 agent 通訊的協定，也用於[雲端自動化](https://code.visualstudio.com/updates/v1_144#_cloud-automations-preview)。它是一個開放、可擴充的協定，目的是讓你能輕鬆為 agent 打造自訂 UI，或打造能接入任何支援此協定之 UI 的 agent 平台。

你可以在 Agents 視窗中透過 **Agents: Add Remote Agent Host...** 命令，將以 websocket 為基礎的 agent host 加入你的 VS Code 執行個體，並執行 `code agent endpoints` 取得你的編輯器中正在執行的 agent host 端點。我們以六種語言發布了函式庫，並發現 agent 很擅長使用這些函式庫來製作用戶端與 host。

你可以在 [Agent Host Protocol 網站](https://microsoft.github.io/agent-host-protocol/)上閱讀更多關於此協定的內容，並找到其他資源。

## [模型](https://code.visualstudio.com/updates/v1_144#_models)

### [使用 GitHub Copilot Fusion 路由與協調模型](https://code.visualstudio.com/updates/v1_144#_route-and-orchestrate-models-with-github-copilot-fusion)

與其為每項任務挑選模型，不如在模型選擇器中選取 **Copilot Fusion**，讓 Copilot 為你智慧地路由請求並協調模型。Copilot Fusion 結合了 [Project HydraFusion](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/) 的多模型協調，以及 [Copilot 自動模型選擇](https://docs.github.com/copilot/concepts/models/auto-model-selection)的任務感知模型選擇，以平衡效能與成本效益。

對於每個請求，Copilot Fusion 會為你的任務選擇模型、推理強度（reasoning effort）與執行模式。例如，簡單任務由一個模型完成；較困難的任務則由一個模型起草解決方案，再由其他模型審查或評論。將滑鼠停留在回應下方的強度層級上，即可查看使用了哪些模型。

選擇強度層級來平衡品質與成本：**Standard** 適用於日常程式開發工作，**High** 適用於要求較高的任務，**Max** 則適用於最複雜的任務。

Copilot Fusion 使用的每個模型都會依其標準費率計費。在 2026 年 11 月 30 日之前，付費 Copilot 方案使用 Copilot Fusion 可享 30% 折扣。

GitHub Copilot Fusion 現已正式推出（generally available），其中 Copilot Fusion High 與 Max 提供給 Copilot Pro+、Max、Business 與 Enterprise 方案。若要深入了解，請參閱我們的 [GitHub Copilot Fusion](https://aka.ms/vscode-copilot-fusion) 文件。

### [預設比較模型與 harness，並支援更多專案](https://code.visualstudio.com/updates/v1_144#_compare-models-and-harnesses-by-default-and-in-more-projects)

**設定：** `sessions.chat.compareAgents.enabled`

[模型比較](https://code.visualstudio.com/docs/agents/run/compare-models)會在多個模型上執行同一個提示詞，供你並排檢閱。對於 Agents 視窗中符合資格的新 session，此功能預設啟用，除非被使用者設定或實驗所覆寫。

![圖：Compare Models 選擇器，已選取四個模型，並有 Done 與 Configure Judge 按鈕。](https://code.visualstudio.com/assets/updates/1_144/compare-models-picker.webp)

在本版中，我們將模型比較擴展到更多情境：

- **不需專案即可探索想法：** 從無資料夾的 **Chat** 執行獨立嘗試，不需要 Git 存放庫、judge 或 synthesizer。
- **從本機或空的存放庫開始：** 不再需要 Git 遠端與初始提交。對於沒有任何提交的存放庫，每個隔離的嘗試會從未被忽略之工作檔案的快照開始，不會變更你的來源分支或索引。

若要從鍵盤開啟比較設定，請在符合資格的聊天輸入框或模型選擇器中按 Ctrl+Alt+M。

在設定流程中，導覽按鈕會標示其目的地，例如 **Configure Judge**、**Configure Attempts** 與 **Configure Synthesis**，而不是使用通用的「下一步」與「上一步」標籤。

> **注意**：Dev Containers 不支援模型比較。

### [Copilot 中的圖片產生（預覽）](https://code.visualstudio.com/updates/v1_144#_image-generation-in-copilot-preview)

**設定：** `chat.copilot.imageGeneration.model`、`chat.copilot.imageGeneration.watermark`

Agent 可以使用 GPT Image 2.5 Flare，根據你的提示詞產生圖片。請 agent 為你的網站建立圖片、聊天背景、新圖示或網站線框圖（wireframe）。你也可以把既有圖片加入為聊天情境，請 agent 修改它或產生變化版本。

預設的圖片模型是 GPT Image 2.5 Flare。若要停用圖片產生，請將 `chat.copilot.imageGeneration.model` 設為 `off`。圖片產生需要能存取所選模型，且除了對話模型所使用的 AI 點數（AI credits）之外，還會額外使用 AI 點數。

此外，將 `chat.copilot.imageGeneration.watermark` 設為 `true`，即可在圖片上加入可察覺的 `Made with AI` 浮水印。

## [Agents](https://code.visualstudio.com/updates/v1_144#_agents)

### [Assisted permissions 正式推出](https://code.visualstudio.com/updates/v1_144#_assisted-permissions-are-generally-available)

Agent 可能會進行許多工具呼叫來完成一項任務。核准每一個工具呼叫，可確保每個動作都經過明確授權，但對於頻繁或低風險的呼叫，這可能會變得繁瑣。而給予 agent 完全自主，則可能有風險，並導致非預期的動作或安全性問題。

透過 assisted permissions（現已對 Copilot session 正式推出），agent 會對每個工具呼叫進行以 LLM 為基礎的風險評估，並自動核准低風險的呼叫。當某個呼叫被判定為較高風險，或無法判定其風險時，該工具呼叫仍需要使用者明確核准。這種做法讓你在便利性與安全性之間取得平衡。

在權限選擇器中選取 **Assisted permissions**，讓 LLM 評估工具呼叫的風險。它核准的呼叫會直接執行而不提示，其他呼叫則仍需你確認。Assisted permissions 需要 Folder isolation，且可能受到你的組織限制。請閱讀 [GitHub 關於 assisted permissions 正式推出的公告](https://github.blog/changelog/2026-10-26-github-copilot-assisted-permissions-generally-available/)。

### [Session 撰寫器控制項（實驗性）](https://code.visualstudio.com/updates/v1_144#_session-composer-controls-experimental)

開始新的 agent session 是你經常做的事，因此我們把關鍵設定集中到頂端，並加入快速鍵以便快速存取。

#### [先選擇環境](https://code.visualstudio.com/updates/v1_144#_choose-the-environment-first)

其他設定選項會依所選環境而改變。例如，在本機建立 session 時，可以指定分支與 worktree 程式碼隔離選項。

若要隱藏環境選擇器，請停用 `sessions.chat.experimental.environmentPicker`。

#### [不需專案即可聊天](https://code.visualstudio.com/updates/v1_144#_chat-without-a-project)

**設定：** `sessions.chat.experimental.workspaceOptOut`

有時你只是想開始一段不與特定工作區或資料夾關聯的 agent 對話（無工作區聊天）。你不必在工作區選擇器中捲動尋找，只要將滑鼠停留在選擇器上（或以鍵盤聚焦），然後選取 `X`，即可取消目前的選擇。

如果你對進行中的 session 取消已選取的工作區，你的提示詞與附件會被保留。此動作只適用於支援無工作區聊天的 harness 與環境。

#### [減少雜亂](https://code.visualstudio.com/updates/v1_144#_reduce-clutter)

為了減少視覺上的雜亂，你可以把每個關鍵設定選項縮減為只顯示圖示。在 UI 控制項上按右鍵，並選取 **Collapse to Icon**。每個選擇器都會保留其工具提示與無障礙名稱，你的選擇也會在重新載入與 Settings Sync 之間保留。

#### [使用鍵盤](https://code.visualstudio.com/updates/v1_144#_use-the-keyboard)

#### [使用工作集檢閱 Copilot 檔案編輯（實驗性）](https://code.visualstudio.com/updates/v1_144#_review-copilot-file-edits-with-the-working-set-experimental)

### [Copilot harness 中的 Copilot Memory](https://code.visualstudio.com/updates/v1_144#_copilot-memory-in-the-copilot-harness)

Copilot harness session 現在可以使用 [Copilot Memory](https://docs.github.com/copilot/concepts/agents/copilot-memory)，也就是 Copilot CLI、Copilot cloud agent 與 Copilot code review 等其他 Copilot 介面同樣使用的雲端記憶服務。

Agent 會在 session 開始時回想相關的存放庫事實與你的偏好，並在你工作時儲存新學到的內容，讓你不必在每一段新對話中重複相同的情境。

記憶會儲存為存放庫事實（與其他可存取該存放庫的人共享），或儲存為使用者偏好（套用於你所有的存放庫）。請 agent 記住某個慣例或偏好，並在範圍很重要時說明範圍：

```
Across all my repositories, remember that I prefer concise commit message subjects.
```

（中譯：在我所有的存放庫中，記住我偏好簡潔的提交訊息主旨。）

Copilot Memory 預設啟用，並遵循你[在 GitHub 上的 Copilot Memory 設定](https://github.com/settings/copilot/memory)與組織原則。你可以隨時在 GitHub 上檢閱與刪除你的記憶。

進一步了解[在 agent 中使用記憶](https://code.visualstudio.com/docs/agents/run/memory)。

### [GitHub Copilot 自訂 agent 的更豐富編輯體驗](https://code.visualstudio.com/updates/v1_144#_richer-editing-for-github-copilot-custom-agents)

當你為 GitHub Copilot harness 自訂 agent 時，自動完成、滑鼠停留提示與驗證會協助你選擇可用的模型、工具與 skill，並在執行 agent 之前發現設定錯誤。

- **模型**：`model` 屬性會提供 Copilot 模型 ID，可以是單一值，或依偏好排序的清單。
- **工具**：`tools` 屬性會提供 Copilot 工具別名（例如 `read`、`edit` 與 `execute`），以及限定名稱的用戶端與擴充功能工具。
- **Skills**：`skills` 屬性會提供可用的 skill，並在自動完成與滑鼠停留提示中顯示描述與來源資訊。
- **設定驗證**：Copilot 專屬屬性與巢狀結構（包括 hooks 與 agent 範圍的 MCP 伺服器）都有自動完成、滑鼠停留提示與驗證。未知的模型、工具與 skill 只會在探索完成後才被標示，因此在清單仍在載入時，有效的值不會被標示為錯誤。
- **內文功能**：在 GitHub Copilot agent 檔案中，像 `` 與 `` 這類預留位置（placeholder）會被辨識並顯示滑鼠停留提示。未知的預留位置，以及僅限 Local 的 `#tool:` 與 `#file:` 參照會被標示出來。（譯註：原文此處兩個預留位置範例的內容為空白。）

### [自訂 agent 編輯的 harness 感知預設值](https://code.visualstudio.com/updates/v1_144#_harness-aware-defaults-for-custom-agent-editing)

## [Session 管理](https://code.visualstudio.com/updates/v1_144#_session-management)

### [在 session 之間移動聊天（預覽）](https://code.visualstudio.com/updates/v1_144#_move-chats-between-sessions-preview)

**設定：** `chat.agentHost.moveChats.enabled`

[Agents 視窗](https://code.visualstudio.com/docs/agents/run/agents-window)讓你把相關的對話組織到 session 中。隨著工作演進，你可以重新安排這些對話，而不必重新開始或遺失其歷程。

- 將巢狀聊天拖曳到另一個 session，或放到該 session 的巢狀聊天之間，以選擇它的位置。
- 在巢狀聊天上按右鍵並選取 **Promote to Session**，讓它成為獨立的 session。你也可以將它拖曳到 session 清單的空白處。
- 將只有單一聊天的 session 拖曳到另一個 session 上，即可將它巢狀放入該 session。
- 拖曳巢狀聊天來重新排序，或從其內容功能表使用 **Move Up** 與 **Move Down**。當焦點在 session 清單中時，使用 Shift+Alt+Up 與 Shift+Alt+Down。

移動會保留聊天的工作資料夾，包括既有的 worktree，或無工作區聊天的暫存資料夾。當另一個 session 仍在使用共用的 worktree 時，該 worktree 會保持可用。在 session 之間移動需要相同的 agent 與供應者，且目的地必須支援多個聊天。Subagent 對話會隨其父聊天一起移動，而不會單獨移動。

Session 清單會顯示移動進度，並在移動後提供 **Undo**。在 Stable 中啟用此設定即可試用此功能；在 Insiders 中則預設開啟。

進一步了解[在 Agents 視窗中組織 session](https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions#_organize-sessions)。

### [為巢狀 session 選擇工作區](https://code.visualstudio.com/updates/v1_144#_choose-a-workspace-for-nested-sessions)

先前，巢狀 session 會繼承其父 session 的工作區。現在，你可以為每個巢狀 session 選擇不同的工作區。這讓你可以跨存放庫工作，同時把相關的對話保留在同一個 session 中。例如，前端聊天與後端聊天可以在不同資料夾中工作，而不必把任務拆分到不同的 session。

在 Agents 視窗中選取 **New Nested Session**，即可開啟一個附有資料夾選擇器的撰寫器，資料夾預設為父 session 的資料夾。你可以選擇最近使用的資料夾、瀏覽到其他資料夾，或選取 **No Workspace**，讓聊天擁有自己的暫存資料夾。

對於 Git 存放庫，選擇 **New Worktree** 與一個分支，即可隔離巢狀聊天的檔案變更。巢狀聊天會使用其父 session 的 agent 與 host。不支援多個工作目錄的 agent，只會提供父 session 的資料夾。

### [快速聊天中的巢狀 session](https://code.visualstudio.com/updates/v1_144#_nested-sessions-in-quick-chats)

在快速聊天上進行後續追問，而不會把不同的問題混在同一段對話中，或失去相關討論的脈絡。例如，在同一個快速聊天底下的不同巢狀 session 中探索兩種做法，而不需要開啟專案資料夾。

Agents 視窗中的快速聊天支援巢狀 session：在快速聊天上選取 **+**，或從其內容功能表使用 **New Nested Session**。

每個巢狀 session 一開始都會選取 **No Workspace**，並取得自己的暫存資料夾，與父快速聊天分開。快速聊天會留在 **Chats** 區段中，讓相關的對話保持在一起。

### [Session 群組的自訂圖示與顏色](https://code.visualstudio.com/updates/v1_144#_custom-icons-and-colors-for-session-groups)

使用自訂圖示與佈景主題感知的顏色，讓工作區群組、環境群組（包括遠端主機）與自訂群組更容易辨識。在 Agents 視窗中，開啟群組的內容功能表，並選取 **Change Icon...** 或 **Change Color...**。你的選擇會在重新載入與 host 重新連線之間保留，而 **Reset to default** 可以分別還原圖示或顏色。_[#343576](https://github.com/microsoft/vscode/pull/343576)_

## [聊天](https://code.visualstudio.com/updates/v1_144#_chat)

### [具備 session 情境的語音對話（實驗性）](https://code.visualstudio.com/updates/v1_144#_voice-conversations-with-session-context-experimental)

[語音模式](https://code.visualstudio.com/docs/configure/accessibility/voice)（`agents.voice.enabled`，此設定可由組織原則設定）讓你在程式設計 agent 工作時，以口語討論任務。搭配你自己的 API 金鑰使用 OpenAI 即時模型（`agents.voice.useBYOKVoiceModel`），即可詢問「我們剛才進行到哪裡？」或「哪個 session 需要我輸入？」這類問題，而不會啟動程式設計請求。

![圖：藍色的語音模式指示器，滑鼠停留說明顯示 OpenAI GPT Live 為即時語音供應者。](https://code.visualstudio.com/assets/updates/1_144/voice-mode-connection-hover.webp)

預設啟用的 `agents.voice.sessionAwareness`，會與 OpenAI BYOK 語音模式分享一份有範圍限制的簡報，內容涵蓋追蹤中的 session 與最近作用中聊天的情境。其中包括 session 標題、回應摘要、待處理提示詞的詳細資料、所選模型與附件名稱，但不包括附件內容。

語音模式的動畫使用單一顏色，營造更具對話感的感覺：你可以隨時插話發言。

GPT Live 對話也能更可預期地處理後續追問與進行中的工作：

- 在 agent 工作時提問並聽取回答，其他更新會排入佇列，之後再朗讀。
- 單一問題表單會朗讀完整的問題，多問題表單則一次收集一個編號的答案。
- 在進行中的工作期間，新的口語程式設計指示會以引導（steering）的方式送出，而不是排入佇列等到任務完成。引導會在供應者所支援的下一個時機套用，並不保證立即中斷。進行中工作期間的純語音交流，不會保留給之後的請求使用。

### [在地化語音核准與更清楚的連線狀態（實驗性）](https://code.visualstudio.com/updates/v1_144#_localized-voice-approvals-and-clearer-connection-status-experimental)

以你選擇的語音語言（`agents.voice.language`）核准或拒絕 GPT Live 的工具請求，支援 25 種語言，並以英文作為後援。你可以用顯示的選項標籤、數字，或在允許時以自由文字回答問題。模稜兩可的核准仍需要明確的回答或聊天控制項。

語音語言設定不會翻譯 agent 所提供的問題或選項。「skip」與「other」等命令仍僅限英文。

### [Issue 回報工具](https://code.visualstudio.com/updates/v1_144#_issue-reporter)

**設定：** `issueReporter.wizard.enabled`、`issueReporter.wizard.openLocation`、`issueReporter.additionalRepositories`

附有清楚步驟、螢幕擷取畫面與記錄的 issue，能讓我們更快重現與修正。[新的 issue 回報工具](https://code.visualstudio.com/updates/v1_122#_improved-issue-reporting-flow)（透過 `issueReporter.wizard.enabled` 開啟）讓你更容易建立高品質的 issue。你可以不離開 VS Code，從擷取列，或使用 kb(workbench.action.issueReporter.captureScreenshot) 與 kb(workbench.action.issueReporter.toggleRecording)，擷取螢幕畫面與螢幕錄影。

本版對新的 issue 回報工具做了以下變更：

- 表單整合在單一頁面上，而不是分成三個步驟。
- 可附加其他有助於我們偵錯你的 issue 的檔案，例如記錄檔或 zip 封存檔。你也可以將圖片與影片貼上或拖放到表單中。

## [終端機](https://code.visualstudio.com/updates/v1_144#_terminal)

### [在 Windows 上，終端機命令開啟的對話方塊會顯示在 VS Code 前方](https://code.visualstudio.com/updates/v1_144#_dialogs-from-terminal-commands-open-in-front-of-vs-code-on-windows)

**設定：** `terminal.integrated.windowsReparentConsoleWindow`

在 Windows 上，部分命令列工具開啟的對話方塊，在從終端機執行時可能會出現在 VS Code 後方。例如，Azure PowerShell 的 `Connect-AzAccount` 登入選擇器會在 VS Code 視窗後方開啟，因此在你移動或最小化 VS Code 之前，命令看起來就像卡住了一樣。

VS Code 現在會讓顯示每個本機終端機的視窗，成為該終端機隱藏主控台視窗的擁有者，就像 Windows Terminal 的做法一樣。工具附加到其主控台視窗的對話方塊，現在會在該終端機所在的 VS Code 視窗前方開啟。

這需要 `terminal.integrated.windowsUseConptyDll`，此設定預設啟用。若要關閉此行為，請將 `terminal.integrated.windowsReparentConsoleWindow` 設為 `false`。

## [擴充功能撰寫](https://code.visualstudio.com/updates/v1_144#_extension-authoring)

### [使用 OIDC 與 Trusted Publishing 發布擴充功能](https://code.visualstudio.com/updates/v1_144#_publish-extensions-with-oidc-and-trusted-publishing)

你現在可以從 GitHub Actions 將擴充功能發布到 Visual Studio Marketplace，而不必將個人存取權杖（PAT）儲存為存放庫祕密。`vsce publish --oidc` 命令會向 GitHub Actions 要求一個短期的 OpenID Connect（OIDC）權杖，並將它交換為有效期最長 15 分鐘的暫時 Marketplace 認證。若權杖交換失敗，`vsce` 不會退回使用 PAT。

要開始使用，請在 Visual Studio Marketplace 發行者管理頁面中，為你的存放庫與工作流程建立 Trusted Publishing 原則，授予發布作業 `id-token: write` 權限，並在工作流程中執行 `vsce publish --oidc`。請使用支援 OIDC 的 `@vscode/vsce` 版本，例如 `4.0.2` 或更新版本。

Trusted Publishing 目前僅支援 GitHub Actions。對於 Azure Pipelines，請繼續透過服務連線使用 Microsoft Entra ID。由於 Azure DevOps 中的全域 PAT 將於 2026 年 12 月 1 日淘汰，我們建議你將擴充功能的發布移轉到上述其中一種安全方法。

進一步了解[使用 vsce 發布擴充功能](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#publish-with-github-actions-and-trusted-publishing)。

在 [Visual Studio Marketplace 部落格文章](https://aka.ms/vsm/trustedpublishing/blogpost)中進一步了解 Trusted Publishing。
