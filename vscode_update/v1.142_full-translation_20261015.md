## 版本亮點

本版新增供 agent 工作流程使用的共用 canvas、讓你在不遺失脈絡的情況下移動聊天、擴充 Markdown 編輯器，並讓系統管理員對 agent 權限擁有更多控制。

- [Canvases（預覽）](https://code.visualstudio.com/updates/v1_142#_canvases-preview)：透過視覺化、可互動的 canvas，在聊天之外與 agent 協作。
- [移動聊天](https://code.visualstudio.com/updates/v1_142#_move-chats-between-folders-and-worktrees)：在另一個資料夾或新的 Git worktree 中延續聊天，不會遺失對話歷程。
- [Markdown 編輯器](https://code.visualstudio.com/updates/v1_142#_markdown-editor)：透過貼上圖片、重新命名檔案連結、階層連結（breadcrumb）導覽等功能，更有效率地處理 Markdown 檔案。
- [企業管理](https://code.visualstudio.com/updates/v1_142#_enterprise)：強制執行 agent 沙箱與權限原則，同時控制開發人員可使用哪些權限模式。
- [重新設計的模型選擇器](https://code.visualstudio.com/updates/v1_142#_redesigned-model-picker)：快速在 Copilot 與 BYOK 提供的模型之間切換，並更直覺地管理投入程度（effort level）與上下文視窗。

## Agents

### Copilot harness

Copilot harness 由 Copilot SDK 驅動。Copilot SDK 是一個共用基礎，有助於讓各個 Copilot 產品的行為、功能與改進保持一致。在 VS Code 中，Copilot harness 透過 [Agent Host](https://code.visualstudio.com/docs/agents/concepts/agent-host) 執行 session，讓 session 能在背景持續進行，並且可以同時從 VS Code 編輯器視窗與 Agents 視窗存取。

Copilot harness 先前已可從聊天輸入框的 harness 選擇器中選用。基於壓倒性的正面且有價值的回饋，我們正逐步將它推出為 VS Code 新 session 的預設 harness。當你開始新的 session 時，harness 選擇器中的 **Copilot** 表示該 session 將使用 Copilot harness。

> 圖：harness 選擇器，顯示 Local 與 Copilot harness 的滑鼠停留說明。

感謝所有分享回饋的人，我們正積極運用這些回饋來形塑使用體驗。其中一個例子是在 Copilot harness 中重新加入 **Ask** 作為內建 agent。你們的回饋顯示，專屬的唯讀體驗仍然有其價值。從 agent 選擇器中選取 **Ask** 即可使用。

了解如何[使用 Copilot harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses#use-the-copilot-harness)，或在 [agent host 部落格文章](https://code.visualstudio.com/blogs/2026/08/26/agent-host-architecture)中探索其架構與工作流程。如果你有回饋或需求，[請提交 issue](https://github.com/microsoft/vscode/issues)。

### Canvases（預覽）

**設定**：`chat.canvases.enabled`

Canvas 是與 agent 協作的互動式介面。Canvas 會在聊天旁開啟，你和 agent 可以在其中檢視並更新同一個成品（artifact），而不必只透過提示詞來協調。

例如，使用 Kanban canvas 來規劃並追蹤實作工作。你可以直接建立與移動卡片，而 agent 可以把一項功能拆解成多個任務、更新任務狀態，或加入新發現的工作。Canvas 在 VS Code 編輯器視窗與 Agents 視窗中都能使用，[GitHub Copilot app](https://docs.github.com/en/copilot/how-tos/github-copilot-app/working-with-canvas-extensions) 也支援 canvas 擴充功能。

> 圖：編輯器中的 Kanban canvas，顯示任務與欄位。

Canvas 目前以預覽形式，提供給 VS Code 桌面應用程式中使用 Copilot harness 的本機 session。請啟用 `chat.canvases.enabled`，然後使用 Copilot harness 開始新的 session。

每個 canvas 都由一個 canvas 擴充功能提供。若要開始使用，你有兩種選擇：

- **建立 canvas 擴充功能**：在聊天輸入框中輸入 `/create-canvas`，並描述你希望專案使用的使用者介面。該技能（skill）接著會在你的工作區中建立一個 canvas 擴充功能，並開啟其 canvas。
- **安裝聊天外掛**：目前請透過 GitHub Copilot app 安裝[包含 canvas 擴充功能的聊天外掛](https://docs.github.com/en/copilot/how-tos/github-copilot-app/working-with-canvas-extensions)。接著切換到 VS Code，請 agent 列出可用的 canvas，並讓它開啟其中一個。

安裝 canvas 擴充功能之後，你也可以在 Agents 視窗中透過 **Add Tab (+)** > **Canvas** 開啟可用的 canvas。

探索並安裝[社群提供的範例 canvas 擴充功能](https://awesome-copilot.github.com/extensions/)。

在 VS Code 文件中進一步了解 [canvas 支援](https://code.visualstudio.com/docs/agents/run/agent-harnesses#_use-canvases-with-the-copilot-harness)。

### 在資料夾與 worktree 之間移動聊天

先前，如果你在某個資料夾中開始調查一項任務，之後想在 Git worktree 中實作，或改在不同的儲存庫中繼續，你就必須開始新的聊天並重新建立脈絡。

現在在 [Agents 視窗](https://code.visualstudio.com/docs/agents/run/agents-window)中，你可以要求 agent 把目前的聊天移動到另一個資料夾或新的 Git worktree，而且對話歷程會完整保留。對於已經有工作區的聊天，變更工作區同樣適用，agent 也能把工作隔離到新的 worktree 中。

用自然語言提示詞請 agent 處理，例如：

```
Continue this task in a new Git worktree of the current repository before implementing it.
```

（中譯：在實作之前，先在目前儲存庫的新 Git worktree 中繼續這項任務。）

Agent 會完成目前這一輪（turn），移動聊天，並在工作區變更時顯示通知。接著它會在新位置自動繼續任務。編輯與命令會在新位置執行，而你原本的 checkout 保持不變。

此移動功能適用於使用 Codex harness 或 Interactive 模式下的 Codex，且只包含一個聊天與一個本機資料夾的 agent session。關於前提條件，以及新位置中可以使用哪些檔案的詳細資訊，請參閱[將聊天移動到另一個資料夾或 worktree](https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions#move-a-chat-to-another-folder-or-worktree)。

### Agents 視窗中以 session 為範圍的版面配置（實驗性）

**設定**：`sessions.experimental.layoutScope`（僅限 Agents 視窗）

先前，當你在 Agents 視窗中切換 session 時，VS Code 會在各個 session 之間共用版面設定，例如編輯器可見度、詳細資訊（details）與面板可見度。如果你習慣 VS Code 為每個工作區記住版面配置，跨 session 共用版面可能會造成干擾。

透過新的實驗性設定 `sessions.experimental.layoutScope`，你可以選擇每個 session 要記住多少版面配置。變更設定後，請重新載入視窗。此設定支援下列值：

- `session-shared`（預設）：目前的行為。一個 session 與其巢狀 session 共用相同的編輯器與選取的面板檢視。編輯器、詳細資訊與底部面板的可見度，會在現有的工作區 session 之間共用。
- `chat-shared`：一個 session 與它的每個巢狀 session 各自保有自己的編輯器與選取的面板檢視，而編輯器、詳細資訊與底部面板的可見度，則仍在現有的工作區 session 之間共用。
- `chat`：一個 session 與它的每個巢狀 session 也各自保有自己的編輯器與詳細資訊組合，以及底部面板可見度。

視窗幾何尺寸、窗格大小與側邊欄目前仍在整個視窗中共用。

### 自訂 Agents 視窗的面板版面配置

現在你可以選擇 Agents 視窗中底部面板的對齊方式。在面板分頁上按右鍵，選取 **Align Panel**，然後選擇下列其中一種版面：

- `Center`：將面板對齊在聊天區域下方，為側邊窗格保留更多空間。
- `Justify`：將面板延伸至整個視窗的寬度。

你的選擇會依設定檔（profile）儲存，並在最大化或還原面板時保留。

## 聊天

### 快速辨識作用中的 harness

聊天標題會顯示作用中 harness 的名稱，例如 **Copilot** 或 **Codex**，讓你不必開啟 harness 選擇器，也不必將滑鼠停在 session 清單上，就能辨識它。

> 圖：兩個編輯器視窗中的聊天 session，每個聊天標題前方分別顯示 Codex 與 Copilot harness 名稱。

### 停止背景 shell

在 [Copilot harness](https://code.visualstudio.com/updates/v1_142#_copilot-harness) session 中，聊天輸入框上方的[背景 shell 標籤（pill）](https://code.visualstudio.com/updates/v1_141#_keep-track-of-background-shells)會列出 agent 仍在背景執行的命令。當其中某個命令已不再有用時，例如你想重新啟動的測試執行，或是執行時間超出預期的命令，你可以停止它，而不必等它完成。

選取 **Background Shells** 標籤，選取某個 shell 以開啟其詳細資訊，然後選取其命令旁邊的 **Stop Shell**。只有該命令會結束，而該 shell 會從清單中移除。你可以用鍵盤操作 **Stop Shell**，螢幕閱讀器也會在 shell 停止時發出通知。

停止 shell 僅適用於**附加的 shell（attached shells）**，也就是 agent 在目前請求中執行的 shell。分離的 shell（detached shells）獨立於 agent 執行，無法從這個介面停止。

Shell 詳細資訊也會在命令上方顯示每個 shell 的完整描述，即使清單中的描述被截斷也一樣。長輸出不再被截斷，而且你可以在 shell 的詳細資訊中，以及聊天回應的終端機輸出中，向上捲動查看較早的輸出。

### BYOK 自訂端點的具狀態回應

如果你的自備金鑰（bring-your-own-key，BYOK）模型使用無狀態的 Responses API，請在 `chatLanguageModels.json` 中該模型的項目上設定 `"statefulResponses": false`，以便在每次請求時傳送完整的對話歷程。

詳情請參閱[自訂端點設定](https://code.visualstudio.com/docs/agent-customization/language-models#stateful-responses-api-endpoints)。

### 不再支援 Local harness 的 Windows 沙箱

Local agent session 中終端機命令的 Windows 沙箱已棄用。若要在 Windows 上以沙箱方式執行命令，請使用 Agent Host session。詳情請參閱 [Agent Host 沙箱文件](https://code.visualstudio.com/docs/agents/run/agent-sandboxing)。

### 重新設計的模型選擇器

Copilot 與自備金鑰（BYOK）提供者提供許多模型，每個模型各自擅長不同的任務。重新設計的模型選擇器，讓你在工作內容改變時更容易選擇與切換模型。

模型選擇器使用分頁式介面來區分 Copilot 與 BYOK 模型。

> 圖：重新設計的模型選擇器，已選取 Copilot 分頁並顯示模型清單，所選的模型會顯示其思考層級與上下文大小。

當你將滑鼠停在清單中的某個模型上時，可以進一步設定它的思考層級（thinking level）與上下文視窗大小。

> 圖：模型選擇器中的模型詳細資訊檢視，提供選取思考層級與上下文大小的選項。

## Markdown 編輯器

### 更貼近 Markdown 原始碼的編輯模式

編輯 Markdown 時，每一行原始碼都會顯示在獨立的視覺行上，讓文件結構更容易掌握。唯讀模式則仍與以往一樣轉譯（render）Markdown。

### 貼上圖片

若要在 Markdown 文件中加入圖片（例如螢幕擷取畫面），只要直接貼到 Markdown 編輯器中即可，就像先前在文字編輯器中已經可以做到的一樣。這讓你更容易加入視覺內容，而不必手動儲存再插入檔案。

### 重新命名檔案連結

Markdown 編輯器現在支援 **Rename Symbol**（F2），讓你可以就地重新命名檔案連結，並讓變更反映到整份文件中。

### 大綱與階層連結

Markdown 編輯器與大綱（Outline）檢視及階層連結（breadcrumbs）整合，讓你更容易檢視標題結構並跳到某個段落。

### 複製程式碼區塊

如同 Markdown 預覽，Markdown 編輯器中的程式碼區塊在滑鼠停留時會顯示複製按鈕。這讓你能輕鬆複製多行程式碼片段，而不會不小心編輯到內容。

## 語言

### Python

本版包含 Python Environments 擴充功能在環境探索、直譯器選擇與終端機啟用方面的修正。

- **環境探索**：由 `uv` 管理的 Python 安裝現在會出現在 **Global** 底下。依路徑選取直譯器時，會將其虛擬環境加入環境清單；在 VS Code 之外刪除虛擬環境時，會更新選取狀態。
- **專案專屬環境**：自動選取現在會優先使用專案本身的虛擬環境，而非巢狀環境。Conda 環境選取與 Poetry 套件操作會遵守專案範圍，背景重新整理也不再覆寫較新的直譯器選取。
- **直譯器設定**：修正 `python.defaultInterpreterPath` 中 `${workspaceFolder}`、相對路徑，以及 `python3` 這類命令的解析。專案檢視的環境選取器現在包含 **Enter Interpreter Path**。
- **終端機啟用**：當全域直譯器變更時，shell 啟動時的啟用會隨之更新，並在環境檔案變更時予以保留。環境檔案的通知包含 **Enable for Workspace** 或 **Enable for Folder** 動作。
- **Python 安裝**：當需要 `uv` 但尚未安裝時，設定流程會提議安裝它，並在不需要重新整理 PATH 的情況下，繼續進行 Python 版本選擇。

## 企業

### 自動將受原則管理的聊天移至 Copilot Agent Host

企業受管理設定讓系統管理員能管理 agent 權限與沙箱。當你的組織設定了非空的 `permissions` 物件，或將 `sandbox.enabled` 設為 `true` 時，VS Code 現在會要求完整的聊天 session 使用 Agent Host 中的 [Copilot harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses)，以便能強制執行這些原則。

開啟現有、未封存的 **Local** 聊天時，會自動將它移至 **Copilot**，並保留對話記錄與未送出的草稿（包括附件）。不會自動送出任何內容。新的聊天會在目前的組織原則下，使用其一般的模型與權限預設值。

VS Code 只有在新的聊天成功開啟之後，才會封存原始聊天。如果你在移動進行中切換離開，原始聊天會保持不變，而尚未開啟的目的地會被移除。

在這些原則生效期間，Claude、Codex 與終端機聊天無法使用。編輯器內嵌聊天仍可用於有限的讀取與編輯任務。單獨的空 `permissions` 物件或舊版原則，並不會觸發此遷移。系統管理員可以[暫時選擇退出自動遷移](https://code.visualstudio.com/updates/v1_142#_temporarily-keep-the-local-harness)。

### 暫時保留 Local harness

需要更多時間轉換到 Copilot Agent Host 的系統管理員，可以在[統一受管理設定](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)中將 `vscode.temporaryDefaultToLocalHarness` 設為 `true`：

```json
{
  "vscode": {
    "temporaryDefaultToLocalHarness": true
  }
}
```

這會讓 **Local** harness 保持可用，並停止自動切換到 **Copilot**，同時保留明確指定、已記住與目前的 harness 選擇。將受管理值設為 `false` 或將其移除，即可恢復正常的路由。

> **注意**：此暫時選擇退出也會覆寫受管理沙箱與權限設定所要求的路由。Local 不會強制執行這些僅限執行階段的規則。Copilot Agent Host session 中的強制執行則維持不變。

### 個別管理 Copilot 權限模式

系統管理員可以允許 **Assisted**，同時封鎖 **Allow All**，讓開發人員獲得輔助核准，而不會略過權限檢查。Copilot 權限選擇器會反映組織受管理設定所允許的模式。

例如，將此設定合併到你的[統一受管理設定](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)中：

```json
{
  "permissions": {
    "disableBypassPermissionsMode": "disable",
    "disableAssistedPermissionsMode": false
  }
}
```

> 圖：Copilot 權限選擇器，可使用 Manual 與 Assisted 權限，而沒有 Allow All。

使用 `permissions.disableAssistedPermissionsMode` 可個別限制 **Assisted**。`permissions.defaultMode` 提供的是起始預設值，而不是對使用者可選模式的限制。

舊版的 `ChatToolsAutoApprove: false` 原則仍會同時封鎖 **Allow All** 與 **Assisted**，除非你設定了明確的受管理模式限制。只設定 `permissions.defaultMode` 並不會取代該舊版限制。

> **注意**：Assisted Permissions 目前與 `permissions.{allow,ask,deny}` 不相容。
> 如果你正在使用 `permissions.allow`、`permissions.ask`、`permissions.deny` 其中任何一個，請設定 `"disableAssistedPermissionsMode": true`。
> 在下一個版本中，兩者將能同時支援。

### Windows 數值原則支援 DWORD 值

在 Windows 上，接受數值的原則支援 DWORD 與 QWORD。

## 對擴充功能的貢獻

### GitHub Pull Requests

[GitHub Pull Requests](https://marketplace.visualstudio.com/items?itemName=GitHub.vscode-pull-request-github) 擴充功能又有更多進展，它讓你能處理、建立及管理 pull request 與 issue。新功能包括：

- 預設啟用堆疊式（stacked）pull request 支援。

  > 圖：堆疊式 pull request。
