### [Copilot harness 成為預設](https://code.visualstudio.com/updates/v1_143#_copilot-harness-as-the-default)

**Copilot harness 現在是 VS Code 中新 session 的預設。** 這是我們最新的 harness，建構於 Copilot SDK 之上；Copilot SDK 是一個共用基礎，有助於讓各 Copilot 產品的行為、功能與改進保持一致。

當你開始新的 session 時，harness 選擇器中的 **Copilot** 表示該 session 使用 Copilot harness：

![圖：harness 選擇器中已選取 Copilot，滑鼠停留說明顯示其 Copilot SDK 與 Agent Host 整合。](https://code.visualstudio.com/assets/updates/1_143/harness-copilot-description.webp)

在 VS Code 中，你可以讓 Copilot harness session 在背景持續執行，並同時從 VS Code 編輯器視窗與 Agents 視窗存取它們。這些 session 透過 [Agent Host](https://code.visualstudio.com/docs/agents/concepts/agent-host) 執行。

非常感謝每一位分享寶貴回饋的人。本版包含更多直接依據你們的回饋所做的改進。

我們持續依據你們分享的情境與環境設定，改善效能並降低延遲。例如，[聊天回應前長時間等待的回報](https://github.com/microsoft/vscode/issues/341543#issuecomment-6202370962)，幫助我們減少了因 MCP 伺服器未完成載入工具而造成的延遲。

我們也持續依據你們分享的回饋與問題，讓文件更清楚。了解如何[使用 Copilot harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses)，或在 [agent host 部落格文章](https://code.visualstudio.com/blogs/2026/08/26/agent-host-architecture)中探索其架構與工作流程。

請持續[提交 issue](https://github.com/microsoft/vscode/issues)，讓我們知道 Copilot harness 對你來說運作得如何。你的回饋幫助很大，並會直接形塑 harness 的使用體驗。

#### [初步的檔案層級工作集支援（實驗性）](https://code.visualstudio.com/updates/v1_143#_initial-file-level-working-set-support-experimental)

**設定：** `chat.editor.workingSet.enabled`

你們回饋說，使用 Copilot harness 時，在編輯器中核准或拒絕 agent 的編輯並不容易。從本版開始，我們推出_初步的_檔案層級工作集支援，協助你更有效地管理與檢閱變更。

編輯器視窗中的 Copilot harness session，現在在聊天輸入框上方的實驗性工作集中支援檔案層級的 **Keep**。啟用 `chat.editor.workingSet.enabled` 即可試用。

在某個檔案上選取 **Keep**，或在所有檔案的標題列選取 **Keep**，即可將變更標記為已檢閱，並將其從工作集中移除。編輯內容仍保留在磁碟上；若 agent 再次變更這些檔案，它們會重新出現在工作集中。

**後續規劃：** 我們計劃在工作集中加入檔案層級的 **Undo**，並把針對個別變更的 **Keep** 與 **Undo** 帶回編輯器中。這些功能預計在之後的版本推出，會先在 [Insiders](https://code.visualstudio.com/insiders/) 上線，再進入 Stable。

### [在 Agents 視窗中從更多變更集捨棄變更](https://code.visualstudio.com/updates/v1_143#_discard-changes-from-more-changesets-in-the-agents-window)

Agents 視窗中的 **Changes** 檢視可讓你查看 agent 所做的所有修改。在此之前，只有 **Uncommitted Changes** 變更集能捨棄待處理的變更。

![圖：Uncommitted Changes 變更集中的 Discard Changes 選項。](https://code.visualstudio.com/assets/updates/1_143/discard-branch-changes.webp)

在本版中，**Branch Changes**、**Session Changes** 與 **Last Turn Changes** 變更集也提供捨棄變更的功能。在 **Changes** 檢視或多檔案差異編輯器中，於檔案上選取 **Discard Changes**。VS Code 捨棄的內容取決於變更集：

- **Branch Changes**：將檔案還原為該分支從其基底分支分出時的版本，並刪除該分支新增的檔案。
- **Session Changes**：還原該 session 對檔案所做的編輯，並保留在 session 之外所做的變更，例如你自己的編輯。
- **Last Turn Changes**：只還原最近一輪對檔案所做的編輯，並保留該檔案的其他所有變更。

### [比較模型結果（預覽）](https://code.visualstudio.com/updates/v1_143#_compare-model-results-preview)

**設定：** `sessions.chat.compareAgents.enabled`（僅限 Agents 視窗）

比較不同模型與 harness 處理同一項程式設計任務的方式。平行執行多次嘗試、檢閱結果，並把各種想法合併成一個解決方案。

要開始使用，請在 Agents 視窗中啟用 `sessions.chat.compareAgents.enabled`，然後在模型選擇器中選取 **Compare Models**。

- **選擇要比較的做法：** 選取兩個以上的模型，各自獨立嘗試你的任務。你可以混用 Copilot、Claude 與 Codex harness，並設定不同的推理層級。

  ![圖：為 Agent bake off 選取了四個不同推理層級的模型。](https://code.visualstudio.com/assets/updates/1_143/bake-off-picker.webp)

- **執行嘗試：** 輸入一個提示詞，即可同時啟動所有選取的嘗試。

  ![圖：一個準備執行、包含四個 Agent bake off 嘗試的提示詞。](https://code.visualstudio.com/assets/updates/1_143/bake-off-multiple-attempts.webp)

- **並排追蹤進度：** 每個嘗試都在自己的 session 中執行，因此你可以比較其做法，並隨時開啟其 worktree 或變更。

  ![圖：四個 Agent bake off 嘗試以格狀並排執行。](https://code.visualstudio.com/assets/updates/1_143/bake-off-grid.webp)

- **評估並合併結果：** 你可以選擇性地選取一個 Judge 模型來評估各嘗試並推薦解決方案。其評分表會顯示時間與 token 使用量，並提供可展開的理由說明、驗證證據，以及前往各嘗試的連結。接著你可以選取 **Synthesize**，以推薦的嘗試為基礎，融入其他嘗試的想法。合成只會在你要求時才開始。

  ![圖：Agent bake off 結果，顯示推薦的嘗試、評分表與 Synthesize 動作。](https://code.visualstudio.com/assets/updates/1_143/bake-off-results.webp)

### [空白側邊窗格中的分頁捷徑](https://code.visualstudio.com/updates/v1_143#_tab-shortcuts-in-an-empty-side-pane)

當你關閉 [Agents 視窗](https://code.visualstudio.com/docs/agents/run/agents-window)側邊窗格中的所有分頁後，編輯器區域會一片空白，你必須找到 **Add Tab (+)** 功能表，才能回到 session 的變更或檔案。

現在，空白的編輯器區域會列出可新增的分頁，例如 **Changes**、**Files**、**Browser** 與 **Search**，每個都附有圖示與鍵盤快速鍵。選取某個項目即可開啟該分頁。若你已安裝 canvas 擴充功能，**Canvas** 項目會列出可用的 canvas。當你切換到編輯器區域為空白的 session 時，VS Code 會顯示此清單，而不是自動重新開啟 **Changes** 與 **Files** 分頁。

### [Session 活動列（實驗性）](https://code.visualstudio.com/updates/v1_143#_session-activity-bar-experimental)

**設定：** `sessions.showSessionActivityBar`、`sessions.sessionActivityBar.showLayoutActions`

Session 活動列把 session 的 **Changes**、**Files**、**Browser** 與可用的 canvas 放在側邊窗格旁，讓這些編輯器與成品在視覺上與它們開啟的位置保持關聯。你仍然可以從 session 頂端的膠囊按鈕開啟 session 成品。

Session 活動列是位於作用中聊天右側邊緣、一條細長的垂直圖示列。選取某個圖示，即可在側邊窗格中開啟該分頁。若側邊窗格已關閉，會以該分頁為作用中分頁開啟。若該分頁已開啟，VS Code 會將焦點移到它，而不是再開啟第二個副本。若你已安裝 canvas 擴充功能，**Canvas** 項目會開啟列出可用 canvas 的子功能表。

你可以拖曳握把，將 Session 活動列上下移動以免擋路，並按兩下握把重設其位置。當你分割聊天區域時，只有取得焦點的群組會顯示活動列。

若要將 session 相關的版面配置動作集中在一起，請在活動列上按右鍵並選取 **Show Layout Actions**。這會把 **Toggle Side Panel** 與 **Toggle Panel** 動作從標題列移到活動列中。

在 Stable 版中，Session 活動列預設為關閉。選取 **View** > **Appearance** > **Session Activity Bar** 即可開啟。若要再次隱藏，請在活動列上按右鍵並選取 **Hide Session Activity Bar**。

你也可以使用 `sessions.showSessionActivityBar` 與 `sessions.sessionActivityBar.showLayoutActions` 設定這些選項。若你先前設定過 `sessions.showSessionToolbar`，VS Code 會將你的設定值沿用到 `sessions.showSessionActivityBar`。

### [從空白的 Files 分頁尋找與建立檔案（實驗性）](https://code.visualstudio.com/updates/v1_143#_find-and-create-files-from-the-empty-files-tab-experimental)

**設定：** `sessions.experimental.emptyFileEditorActions`

在 Agents 視窗中，沒有開啟任何檔案時 **Files** 分頁會是空白的，因此你必須切換到 Files 檢視，才能在 session 的資料夾中尋找或建立檔案。

啟用 `sessions.experimental.emptyFileEditorActions` 後，空白的 **Files** 分頁會顯示一個搜尋框與一個 **New File** 動作。搜尋的運作方式與 [Quick Open](https://code.visualstudio.com/docs/editing/getting-started/tips-and-tricks#_quick-open)（Ctrl+P）相同，具有相同的排序、醒目提示與檔案圖示，而且只會尋找目前 session 資料夾中的檔案。選取某個結果即可在編輯器中開啟，或選取 **New File** 在 session 的資料夾中建立檔案。關閉檔案後，搜尋框會再次出現。

### [改善開啟大型聊天時的效能](https://code.visualstudio.com/updates/v1_143#_improved-performance-when-opening-large-chats)

在 Agents 視窗中開啟一段很長的 [Agent Host](https://code.visualstudio.com/docs/agents/concepts/agent-host) 聊天時，過去在還原聊天歷程期間，視窗最多會凍結半分鐘。在本版中，歷程改為以小區塊分段還原，而不是一個長時間的阻塞工作，因此視窗能保持回應。開啟、切換回來以及重新載入大型聊天都明顯變快。

| 情境 | 聊天 | 開啟時間：1.142 → 1.143 | 視窗無回應時間：1.142 → 1.143 |
| --- | --- | --- | --- |
| 冷啟動開啟 | 聊天 A（約 1,150 個請求，約 530 MB 歷程） | 35.6 秒 → 9.0 秒 | 28.3 秒 → 0.6 秒 |
| 冷啟動開啟 | 聊天 B（約 1,450 個請求，約 200 MB 歷程） | 20.3 秒 → 3.0 秒 | 20.3 秒 → 0.4 秒 |
| 重新開啟 | 聊天 A | 26.7 秒 → 0.6 秒 | 26.8 秒 → 0.3 秒 |
| 重新開啟 | 聊天 B | 16.4 秒 → 0.4 秒 | 16.4 秒 → 0.2 秒 |
| 重新載入視窗 | 聊天 A | 26.7 秒 → 2.9 秒 | 25.3 秒 → 0.9 秒 |
| 重新載入視窗 | 聊天 B | 22.3 秒 → 2.2 秒 | 20.8 秒 → 0.4 秒 |

_在 macOS 上執行三次取中位數，使用的是日常開發中的真實聊天。「冷啟動開啟」指視窗啟動後第一次開啟某個聊天。「重新開啟」指切換到另一個聊天再切回來。「視窗無回應時間」是開啟期間視窗無法回應輸入的最長時間。_

### [從非作用中的 worktree 回收儲存空間（實驗性）](https://code.visualstudio.com/updates/v1_143#_reclaim-storage-from-inactive-worktrees-experimental)

**設定：** `chat.agentSessions.sessionStorageCleanupSuggestion.enabled`（僅限 Agents 視窗）

Worktree 非常實用，能讓 agent 同時處理多個功能，而不會干擾彼此的變更。但隨著時間累積，非作用中的 worktree 可能會越積越多，並佔用大量磁碟空間。

從命令選擇區執行 **Chat: Open Worktree Cleanup**，即可查看非作用中的 agent session worktree 使用了多少磁碟空間，並移除你不再需要的 worktree。你可以依 session 非作用中的時間長短篩選、檢視每個 worktree 的大小，並選取要清除的 worktree。

清除會將選取的 session 標記為已完成，並刪除其 worktree。你之後可以還原 session 以重新建立其 worktree。作用中、執行中、需要輸入以及已釘選的 session 都受到保護，不會被清除。

清除編輯器可讓你為 pull request 已合併的 session 設定自動清除，並控制當 session 儲存空間變大時，VS Code 是否建議清除。

![圖：worktree 清除編輯器，顯示清除設定與非作用中的 session worktree。](https://code.visualstudio.com/assets/updates/1_143/worktree-cleanup-editor.webp)

啟用 `chat.agentSessions.sessionStorageCleanupSuggestion.enabled` 時，當非作用中的 worktree 累積過多，或其使用的磁碟空間多到值得清除時，Agents 視窗會通知你。

![圖：Agents 視窗中的 worktree 清除建議。](https://code.visualstudio.com/assets/updates/1_141/worktree-cleanup.webp)

### [在你的裝置上執行 Copilot 模型（實驗性）](https://code.visualstudio.com/updates/v1_143#_run-copilot-models-on-your-device-experimental)

像新款 [Surface Laptop Ultra](https://www.microsoft.com/en-us/surface/devices/surface-laptop-ultra) 這類筆電，搭載 NVIDIA RTX Spark 並具備最高 128 GB 的統一記憶體，擁有足夠的 GPU 記憶體在本機執行一個能力不錯的程式設計模型。裝置端模型讓你能搭配 Copilot 運用這類硬體：從模型選擇器中新的 **On This Device** 分頁下載 MAI Code 1.1 Flash，並在 Copilot harness session 中與它聊天，模型處理在你的裝置上進行。

VS Code 會為你下載並管理模型。在你的裝置上執行的回應會標示為 **On-device**，且不會使用 AI 點數。若要讓 Auto 將合適的請求路由到裝置端模型並以雲端作為備援，請在模型的詳細資料頁面開啟 **Use in Auto**。

要開始使用：

- 安裝支援此模型的 [llama.cpp 建置版本](https://github.com/ggml-org/llama.cpp/releases)
- 將 `chat.copilot.localModel.llamaServerPath` 設定為其 `llama-server` 執行檔
- 啟用 `chat.copilot.localModel.enabled`

裝置端模型需要登入 GitHub，以及具備 96 GB 以上 GPU 記憶體的 NVIDIA GPU。

進一步了解[裝置端模型](https://code.visualstudio.com/docs/agent-customization/language-models#_use-on-device-models-experimental)。

### [在語音模式中使用自己的 OpenAI 模型（預覽）](https://code.visualstudio.com/updates/v1_143#_bring-your-own-openai-model-to-voice-mode-preview)

**設定：** `agents.voice.enabled`（此設定可由組織原則設定）、`agents.voice.useBYOKVoiceModel`

使用你自己的 OpenAI API 金鑰與即時（live）模型進行語音驅動的程式設計對話，取代代管的語音模式後端。在 Language Models 編輯器中新增你的 OpenAI 金鑰、啟用 `agents.voice.enabled`，並將 `agents.voice.useBYOKVoiceModel` 設定為你的金鑰可存取的即時模型 ID，例如 `gpt-live-1`。

## [沙箱](https://code.visualstudio.com/updates/v1_143#_sandboxing)

### [管理沙箱憑證信任](https://code.visualstudio.com/updates/v1_143#_manage-sandbox-certificate-trust)

沙箱憑證信任管理適用於在 Windows 或 macOS 上執行的 agent host。

沙箱認證代理（credential proxy）讓工具能向已核准的服務進行驗證，而不會將真正的驗證權杖暴露給沙箱中的處理程序。它會提供工具預留位置用的認證，然後在將請求轉送到已核准的目的地時，替換成真正的認證。對於 HTTPS 請求，這需要代理出示自己的 TLS 憑證，而工具必須信任這些憑證。

Copilot 會為支援的工具提供憑證套件。有些工具則依賴作業系統的憑證信任存放區，當代理的憑證授權單位（CA）未受信任時，可能會遇到憑證錯誤。安裝 CA 可改善與這些工具的相容性。**單純的網域篩選不需要安裝 CA：**內建的本機代理可以檢查目的地，並在不解密的情況下以通道傳輸 HTTPS 流量。

當缺少信任且支援安裝時，VS Code 會顯示可關閉的 **Sandbox trusted CA is not installed** 通知，並附有 **Install** 選項。安裝會將本機產生的 CA 公開憑證加入 Windows 全機器信任存放區，或 macOS 使用者的登入鑰匙圈（login Keychain），且可能需要作業系統授權。

你也可以從命令選擇區執行 **Sandbox: Manage Trusted CA**，為最後取得焦點的聊天所使用的 agent host（無論是本機或遠端）安裝、輪替或移除信任。每項操作都會要求確認，並標明目標 host。**Remove** 會移除作業系統信任，但保留已儲存的憑證與私密金鑰。憑證變更後，執行中的工具可能需要重新啟動。

安裝是選擇性的。缺少信任不會阻擋聊天啟動或傳送訊息，而開啟聊天也絕不會變更憑證信任。

更多詳細資訊，請參閱[在 Windows 與 macOS 上信任沙箱 CA 憑證](https://code.visualstudio.com/docs/agents/run/agent-sandboxing#_trust-the-sandbox-ca-certificate-on-windows-and-macos)。

### [在原則允許時變更 session 的沙箱設定](https://code.visualstudio.com/updates/v1_143#_change-session-sandboxing-when-policy-permits)

若你組織的受管理原則允許略過沙箱，你可以針對單一 Copilot harness session 關閉[沙箱](https://code.visualstudio.com/docs/agents/run/agent-sandboxing)，而不必變更全域設定。在編輯器或 Agents 視窗中，使用 session 權限功能表中的 **Sandboxing for terminal** 切換開關。系統管理員仍可透過不允許略過來要求沙箱，這會讓該切換開關保持開啟並鎖定。

變更仍需經過 agent 執行階段的核准。若變更被拒絕，VS Code 會顯示錯誤，並還原上一次套用的沙箱狀態。收合的權限控制項與重新開啟的功能表都會反映該狀態。

### [診斷醒目提示上限](https://code.visualstudio.com/updates/v1_143#_diagnostic-highlight-limits)

為了改善回報大量問題的檔案中診斷資訊的可見度，編輯器醒目提示上限已從每個檔案 500 個診斷提高到 5,000 個。

當診斷或其醒目提示因效能考量而受到限制時，編輯器語言狀態指示器中會出現警告：

若兩個上限都達到，警告會同時回報兩種狀況。將滑鼠停留在狀態列的語言狀態指示器上即可檢視詳細資訊。

## [企業](https://code.visualstudio.com/updates/v1_143#_enterprise)

### [受管理 OpenTelemetry 的動態標頭](https://code.visualstudio.com/updates/v1_143#_dynamic-headers-for-managed-opentelemetry)

系統管理員可以使用新的 `telemetry.headersProvider` 受管理設定，為 OpenTelemetry（OTel）匯出產生並重新整理 HTTP 標頭。例如，使用輔助程式為你的收集器提供短效期的驗證權杖，而不必要求開發人員手動更新標頭，或透過個人 OTel 設定自行選擇加入。

此設定**僅適用於 Copilot Agent Host session**。請在[企業受管理設定](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)中設定，而非使用者設定：

```json
{
  "telemetry": {
    "enabled": true,
    "endpoint": "https://<collector-host>:4318",
    "protocol": "http",
    "headersProvider": {
      "path": "<absolute-path-to-header-helper>",
      "args": [],
      "refreshIntervalMs": 5000
    }
  }
}
```

輔助程式會將一個由標頭名稱與字串值組成的 JSON 物件寫入標準輸出。

輔助程式的需求與更多詳細資訊，請參閱[設定動態標頭](https://code.visualstudio.com/docs/agents/guides/monitoring-agents#_configure-dynamic-headers)。

### [受管理的模型預設值](https://code.visualstudio.com/updates/v1_143#_managed-model-defaults)

新的 Copilot harness 聊天會使用你組織的受管理預設值，即使你已將 `chat.defaultModel`（此設定可由組織原則設定）設定為其他偏好也一樣。模型選擇器與該設定現在會說明套用的是哪些預設值。你仍然可以針對每個聊天變更模型與支援的選項。

![圖：模型選擇器標示出組織預設值，並說明你可以為此聊天選擇其他模型。](https://code.visualstudio.com/assets/updates/1_143/managed-model-default-picker.webp)

例如，以下在[企業受管理設定](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)中的組態，會讓新聊天預設使用 Auto 搭配 Intelligence 層級：

### [Local 為何被停用](https://code.visualstudio.com/updates/v1_143#_why-local-is-disabled)

當企業原則要求使用 [Copilot harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses) 時，Local harness 現在會在 harness 選擇器中保持可見但呈停用狀態，並附有 [**Learn why**](https://aka.ms/vscode-copilot-harness-policy) 連結說明此限制。

![圖：harness 選擇器中 Local 因原則而停用，並附有 Learn why 連結，說明組織要求使用 Copilot。](https://code.visualstudio.com/assets/updates/1_143/local-harness-disabled-by-policy.webp)

若要強制執行非空的受管理 `permissions.deny` 規則或 `sandbox.enabled: true`，就必須使用 Copilot，除非適用下方的暫時覆寫。其他 `permissions.*` 設定以及空的拒絕清單不會觸發此要求。

系統管理員可以使用以下企業受管理設定（而非使用者設定）禁止 Local：

```json
{
  "vscode": {
    "temporaryAllowLocalHarness": false,
    "temporaryDefaultToLocalHarness": false
  }
}
```

| 設定 | 說明 |
| --- | --- |
| `vscode.temporaryAllowLocalHarness` | `false` 會禁止 Local、Claude 與 Codex harness，並覆寫下方的暫時預設。`true` 不會覆寫其他原則。 |
| `vscode.temporaryDefaultToLocalHarness` | `true` 會讓 Local 保持可用，並抑制自動路由到 Copilot，包括拒絕清單與沙箱的要求。明確選擇與已記住的選擇會被保留。 |

當要求使用 Copilot 時，開啟未封存的 Local 聊天會將其移至 Copilot。編輯器內嵌聊天以及其他 Claude 與 Codex 的限制維持不變。

> **注意**：這些控制項是 Local 退役期間的暫時措施。Local 無法強制執行僅限執行階段的權限與沙箱控制。若你需要這些控制，請勿啟用 Local 的暫時覆寫。若 Copilot 在你的企業環境中無法運作，請[回報問題](https://github.com/microsoft/vscode/issues)。

### [組織設定載入期間的中斷減少](https://code.visualstudio.com/updates/v1_143#_fewer-interruptions-while-organization-settings-load)

Copilot harness session 與模型變更現在會等待載入緩慢的組織設定完成，並顯示進度，失敗時提供重試選項。等待期間你仍可選取 **Stop**。組織限制會在請求執行前套用。

### [受管理工具的核准提示減少](https://code.visualstudio.com/updates/v1_143#_fewer-approval-prompts-for-managed-tools)

[Assisted 權限](https://code.visualstudio.com/updates/v1_142#_manage-copilot-permission-modes-independently)對於它所核准的合格受管理工具請求，不再重複提示。一次性限制、受管理的拒絕以及沙箱限制仍然適用。

### [受管理外掛自動安裝](https://code.visualstudio.com/updates/v1_143#_managed-plugins-install-automatically)

Copilot harness session 現在會在使用前，先安裝或更新你組織所要求的 [agent 外掛](https://code.visualstudio.com/docs/agent-customization/agent-plugins)。

例如，在[企業受管理設定](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)中要求某個外掛：

```json
{
  "enabledPlugins": {
    "my-plugin@my-marketplace": true
  }
}
```

由受信任存放庫的設定所啟用的外掛，以及你的組織指派給你團隊的外掛，會在背景安裝，不會阻擋聊天。

- 受管理設定優先，其次是受信任存放庫的設定，然後才是你自己的選擇。
- 團隊指派只在沒有其他選擇時才套用。
- 自動安裝的外掛只在該 session 中啟用，不會加入你的使用者設定。

### [Claude 與 Codex session](https://code.visualstudio.com/updates/v1_143#_claude-and-codex-sessions)

當原則要求使用 Copilot harness 時，既有的 Claude 與 Codex session 仍會在 session 清單中保持可見，因此你仍可用 Copilot harness 繼續這些 session。在此情境下，建立新的 Claude 或 Codex session 仍維持停用。
