# Visual Studio Code 1.143 重點摘要

- 版本：1.143.0（Stable）
- 發行日期：2026 年 10 月 19 日
- 原文連結：https://code.visualstudio.com/updates/v1_143

---

## 一、版本亮點

本版讓 Copilot harness 成為新 session 的預設，並新增比較模型、回收儲存空間、在本機執行模型，以及瀏覽檔案變更的工具。五項亮點：

- **預設使用 Copilot harness**：新 session 的預設，建構於 Copilot SDK，可在編輯器與 Agents 視窗之間切換。
- **比較模型（預覽）**：在 Agents 視窗以多個模型執行同一任務，再比較並合併解決方案。
- **回收 worktree 儲存空間（實驗性）**：檢視並移除非作用中的 agent session worktree，釋放磁碟空間。
- **裝置端模型（實驗性）**：在本機執行 MAI Code 1.1 Flash 處理 agent 任務。
- **多檔案差異檔案清單（實驗性）**：在多檔案差異編輯器中掌握變更檔案概觀並跳轉。

## 二、Agents

### 1. Copilot harness 成為預設
- Copilot harness 現在是 VS Code 中**新 session 的預設**；建構於 Copilot SDK——各 Copilot 產品共用的基礎，讓行為、功能與改進保持一致。
- 新 session 的 harness 選擇器顯示 **Copilot**，即代表使用 Copilot harness。
- Session 可在背景持續執行，並可同時從編輯器視窗與 Agents 視窗存取；透過 Agent Host 執行。
- 依回饋持續改善效能、降低延遲：例如依「聊天回應前長時間等待」的回報，減少了 MCP 伺服器未完成載入工具所造成的延遲。
- 持續依回饋改善文件；相關資源：Copilot harness 使用文件、agent host 架構部落格文章；歡迎持續提交 issue。

### 2. 初步的檔案層級工作集支援（實驗性）
- 設定：`chat.editor.workingSet.enabled`
- 背景：使用者回饋在 Copilot harness 中，於編輯器核准或拒絕 agent 編輯不容易。
- 編輯器視窗的 Copilot harness session，在聊天輸入框上方的實驗性工作集中支援檔案層級 **Keep**。
- 對單一檔案或在所有檔案標題列選取 **Keep**：將變更標記為已檢閱並從工作集移除；編輯仍保留在磁碟上，若 agent 再次變更該檔案，會重新出現。
- 後續規劃：工作集加入檔案層級 **Undo**，並把個別變更的 **Keep**／**Undo** 帶回編輯器；之後的版本先在 Insiders 推出，再進入 Stable。

### 3. 在 Agents 視窗中從更多變更集捨棄變更
- 以往只有 **Uncommitted Changes** 變更集能捨棄待處理變更。
- 本版 **Branch Changes**、**Session Changes**、**Last Turn Changes** 也可捨棄；在 **Changes** 檢視或多檔案差異編輯器中對檔案選取 **Discard Changes**。
- 各變更集捨棄的內容不同：
  - **Branch Changes**：將檔案還原到分支從基底分支分出時的版本，並刪除該分支新增的檔案。
  - **Session Changes**：還原該 session 對檔案的編輯，保留 session 之外的變更（例如你自己的編輯）。
  - **Last Turn Changes**：只還原最近一輪的編輯，保留該檔案的其他所有變更。

### 4. 比較模型結果（預覽）
- 設定：`sessions.chat.compareAgents.enabled`（僅限 Agents 視窗）
- 目的：比較不同模型與 harness 處理同一程式設計任務的方式，平行執行、檢閱結果，並把想法合併成一個解決方案。
- 開始方式：在 Agents 視窗啟用設定，於模型選擇器選取 **Compare Models**。
- 流程：
  - **選擇做法**：選取兩個以上模型各自獨立嘗試；可混用 Copilot、Claude、Codex harness，並設定不同推理層級。
  - **執行嘗試**：輸入一個提示詞，同時啟動所有嘗試。
  - **並排追蹤**：每個嘗試在各自的 session 中執行，可隨時開啟其 worktree 或變更。
  - **評估與合併**：可選擇性指定 **Judge** 模型評估並推薦解法；評分表顯示時間與 token 使用量，並有可展開的理由、驗證證據與各嘗試連結。選取 **Synthesize** 可以推薦嘗試為基礎融入其他嘗試的想法；合成只在你要求時才開始。

### 5. 空白側邊窗格中的分頁捷徑
- 以往關閉 Agents 視窗側邊窗格所有分頁後，編輯器區域空白，需找 **Add Tab (+)** 功能表才能回到變更或檔案。
- 現在空白編輯器區域會列出可新增的分頁：**Changes**、**Files**、**Browser**、**Search**，各附圖示與鍵盤快速鍵；選取即開啟。
- 已安裝 canvas 擴充功能時，**Canvas** 項目會列出可用 canvas。
- 切換到編輯器區域為空白的 session 時，顯示此清單，而不再自動重新開啟 **Changes** 與 **Files** 分頁。

### 6. Session 活動列（實驗性）
- 設定：`sessions.showSessionActivityBar`、`sessions.sessionActivityBar.showLayoutActions`
- 將 session 的 **Changes**、**Files**、**Browser** 與可用 canvas 放在側邊窗格旁，讓編輯器與成品在視覺上與開啟位置保持關聯；仍可從 session 頂端的膠囊按鈕開啟成品。
- 位於作用中聊天右側邊緣的細長垂直圖示列：
  - 選取圖示即在側邊窗格開啟該分頁；側邊窗格關閉時會以該分頁開啟；分頁已開啟則改為聚焦，不開第二份。
  - 已安裝 canvas 擴充功能時，**Canvas** 項目開啟列出可用 canvas 的子功能表。
- 可拖曳握把上下移動，按兩下握把重設位置；分割聊天區域時，只有取得焦點的群組顯示活動列。
- 在活動列按右鍵選 **Show Layout Actions**：把 **Toggle Side Panel** 與 **Toggle Panel** 從標題列移到活動列。
- Stable 版預設關閉；以 **View** > **Appearance** > **Session Activity Bar** 開啟，右鍵 **Hide Session Activity Bar** 隱藏。
- 先前設定過 `sessions.showSessionToolbar` 者，其值會沿用到 `sessions.showSessionActivityBar`。

### 7. 從空白的 Files 分頁尋找與建立檔案（實驗性）
- 設定：`sessions.experimental.emptyFileEditorActions`
- 以往 Agents 視窗中沒有開啟檔案時 **Files** 分頁空白，需切到 Files 檢視才能尋找或建立檔案。
- 啟用後，空白 **Files** 分頁顯示搜尋框與 **New File** 動作：
  - 搜尋運作同 Quick Open（Ctrl+P），具相同排序、醒目提示與檔案圖示，但只搜尋目前 session 的資料夾。
  - 選取結果在編輯器開啟，或以 **New File** 在 session 資料夾建立檔案；關閉檔案後搜尋框會再出現。

### 8. 改善開啟大型聊天時的效能
- 以往在 Agents 視窗開啟很長的 Agent Host 聊天，還原歷程時視窗最多凍結半分鐘。
- 本版歷程改以小區塊分段還原，不再是單一長時間阻塞工作，視窗保持回應；開啟、切回與重新載入大型聊天都明顯變快。
- 實測（macOS、三次取中位數、日常開發真實聊天）：
  - 冷啟動開啟：聊天 A（約 1,150 請求、約 530 MB 歷程）開啟 35.6 秒 → 9.0 秒、無回應 28.3 秒 → 0.6 秒；聊天 B（約 1,450 請求、約 200 MB）開啟 20.3 秒 → 3.0 秒、無回應 20.3 秒 → 0.4 秒。
  - 重新開啟：聊天 A 開啟 26.7 秒 → 0.6 秒、無回應 26.8 秒 → 0.3 秒；聊天 B 開啟 16.4 秒 → 0.4 秒、無回應 16.4 秒 → 0.2 秒。
  - 重新載入視窗：聊天 A 開啟 26.7 秒 → 2.9 秒、無回應 25.3 秒 → 0.9 秒；聊天 B 開啟 22.3 秒 → 2.2 秒、無回應 20.8 秒 → 0.4 秒。
  - 名詞定義：「冷啟動開啟」為視窗啟動後首次開啟；「重新開啟」為切到其他聊天再切回；「視窗無回應時間」為開啟期間無法回應輸入的最長時間。

### 9. 從非作用中的 worktree 回收儲存空間（實驗性）
- 設定：`chat.agentSessions.sessionStorageCleanupSuggestion.enabled`（僅限 Agents 視窗）
- 背景：worktree 讓 agent 同時處理多個功能互不干擾，但非作用中的 worktree 會累積並佔用大量磁碟空間。
- 從命令選擇區執行 **Chat: Open Worktree Cleanup**：查看非作用中 agent session worktree 佔用的空間，依非作用時間篩選、檢視每個 worktree 大小，選取要清除的項目。
- 清除會把 session 標記為已完成並刪除其 worktree；之後可還原 session 以重建 worktree。
- 受保護不會被清除：作用中、執行中、需要輸入、已釘選的 session。
- 清除編輯器可為 pull request 已合併的 session 設定自動清除，並控制 session 儲存空間變大時是否建議清除。
- 啟用設定後，非作用中 worktree 累積過多或佔用空間值得清除時，Agents 視窗會通知。

## 三、模型

### 1. 在你的裝置上執行 Copilot 模型（實驗性）
- 背景：如搭載 NVIDIA RTX Spark、最高 128 GB 統一記憶體的新款 Surface Laptop Ultra，有足夠 GPU 記憶體在本機執行能力不錯的程式設計模型。
- 從模型選擇器新的 **On This Device** 分頁下載 **MAI Code 1.1 Flash**，在 Copilot harness session 中聊天，模型處理在本機進行。
- VS Code 負責下載與管理模型；本機執行的回應標示 **On-device**，**不使用 AI 點數**。
- 在模型詳細資料頁開啟 **Use in Auto**，可讓 Auto 將合適請求路由到裝置端模型，並以雲端作為備援。
- 開始使用：
  - 安裝支援此模型的 llama.cpp 建置版本。
  - 將 `chat.copilot.localModel.llamaServerPath` 設為其 `llama-server` 執行檔。
  - 啟用 `chat.copilot.localModel.enabled`。
- 需求：登入 GitHub，且具備 **96 GB 以上 GPU 記憶體的 NVIDIA GPU**。

### 2. 在語音模式中使用自己的 OpenAI 模型（預覽）
- 設定：`agents.voice.enabled`（可由組織原則設定）、`agents.voice.useBYOKVoiceModel`
- 以自己的 OpenAI API 金鑰與即時（live）模型進行語音驅動的程式設計對話，取代代管的語音模式後端。
- 步驟：在 Language Models 編輯器新增 OpenAI 金鑰 → 啟用 `agents.voice.enabled` → 將 `agents.voice.useBYOKVoiceModel` 設為金鑰可存取的即時模型 ID（例如 `gpt-live-1`）。

## 四、沙箱

### 1. 管理沙箱憑證信任
- 適用於在 Windows 或 macOS 上執行的 agent host。
- 原理：沙箱認證代理讓工具向已核准服務驗證，而不把真正的權杖暴露給沙箱處理程序——先給工具預留位置認證，轉送到已核准目的地時再替換為真正認證；HTTPS 請求需代理出示自己的 TLS 憑證，工具必須信任它。
- Copilot 會為支援的工具提供憑證套件；但依賴作業系統信任存放區的工具，在代理 CA 未受信任時可能出現憑證錯誤，安裝 CA 可改善相容性。
- **單純網域篩選不需安裝 CA**：內建本機代理可檢查目的地，並在不解密的情況下以通道傳輸 HTTPS。
- 缺少信任且支援安裝時，顯示可關閉的 **Sandbox trusted CA is not installed** 通知與 **Install** 選項；會把本機產生的 CA 公開憑證加入 Windows 全機器信任存放區或 macOS 使用者登入鑰匙圈，可能需要作業系統授權。
- 命令 **Sandbox: Manage Trusted CA**：為最後取得焦點聊天的 agent host（本機或遠端）安裝、輪替或移除信任；每項操作都要確認並標明目標 host。**Remove** 移除作業系統信任但保留已儲存的憑證與私密金鑰；變更後執行中的工具可能需重新啟動。
- 安裝為選擇性：缺少信任不會阻擋聊天啟動或傳送訊息，開啟聊天也絕不會變更憑證信任。

### 2. 在原則允許時變更 session 的沙箱設定
- 若組織受管理原則允許略過沙箱，可針對單一 Copilot harness session 關閉沙箱，不必改全域設定。
- 位置：編輯器或 Agents 視窗中 session 權限功能表的 **Sandboxing for terminal** 切換開關。
- 系統管理員可不允許略過來要求沙箱，切換開關會保持開啟並鎖定。
- 變更仍需 agent 執行階段核准；被拒絕時顯示錯誤並還原上次套用的狀態，收合的權限控制項與重新開啟的功能表都會反映該狀態。

## 五、聊天

### 1. 從聊天功能表開啟 canvas（預覽）
- 設定：`chat.canvases.enabled`
- Canvas 於 1.142 推出（預覽），是與 agent 協作的共用互動式介面。
- 本版可在編輯器視窗從 **New Chat (+)** > **Canvas** 直接開啟可用 canvas，不必請 Copilot 開啟。
- 出現條件：已啟用 canvas 支援、已安裝 canvas 擴充功能，且在 Copilot harness session 中**送出第一則訊息之後**。
- Agents 視窗也可從 `+` 功能表開啟 canvas。

### 2. 查看已分離背景 shell 的輸出
- 在 Copilot harness session 中，agent 可在已分離的背景 shell 啟動需在回應後持續執行的命令（如開發伺服器、檔案監看程式）。
- 以往無法查看已分離 shell 的輸出（例如確認開發伺服器是否啟動成功）；現在會像已附加 shell 一樣串流輸出。
- 選取 **Background Shells** 膠囊按鈕，再選已分離的 shell 即可即時觀看輸出；agent 完成回應後，聊天回應中的終端機輸出仍持續更新。
- 命令結束時 shell 從清單移除，聊天回應保留命令的輸出與結束狀態。
- 現在也可停止已分離的 shell（先前僅限已附加的 shell）：在 shell 詳細資料中選取 **Stop Shell**。

## 六、編輯器體驗

### 1. 診斷醒目提示上限
- 編輯器醒目提示上限從每檔案 **500 提高到 5,000** 個診斷。
- 因效能限制時，編輯器語言狀態指示器會出現警告：
  - **診斷來源上限**：每個擴充功能的診斷集合每檔案最多 1,000 個；超過時警告部分診斷未顯示。
  - **編輯器醒目提示上限**：每檔案跨所有來源最多醒目提示 5,000 個；超過時警告只醒目提示 5,000 個。
- 兩者都達上限時同時回報；將滑鼠停在狀態列的語言狀態指示器上查看詳細資訊。

## 七、原始檔控制

### 1. 多檔案差異編輯器檔案清單（實驗性）
- 設定：`multiDiffEditor.experimental.fileList`
- 在多檔案差異檢視旁顯示檔案清單，瀏覽來自 commit、stash 與 agent session 的變更。
- 每個檔案有狀態字母：A（新增）、M（修改）、D（刪除）、R（重新命名）。
- 捲動時清單醒目提示目前檢視的檔案；選取清單中的檔案即跳到其差異。
- 編輯器工具列 **More Actions**（**...**）> **Files View & Position**：可選 **View as List**／**View as Tree**，以及清單放在差異的左側（**On the Left**）或右側（**On the Right**）。

## 八、企業

### 1. 受管理 OpenTelemetry 的動態標頭
- 新的受管理設定 `telemetry.headersProvider`：為 OTel 匯出產生並重新整理 HTTP 標頭（例如以輔助程式提供收集器所需的短效期驗證權杖），不需開發人員手動更新標頭或透過個人 OTel 設定選擇加入。
- **僅適用於 Copilot Agent Host session**；須在企業受管理設定中設定，而非使用者設定。
- 設定欄位：`telemetry.enabled`、`endpoint`、`protocol`，以及 `headersProvider` 的 `path`（輔助程式絕對路徑）、`args`、`refreshIntervalMs`（範例為 5000）。
- 輔助程式需將標頭名稱與字串值組成的 JSON 物件寫入標準輸出；需求細節見「設定動態標頭」文件。

### 2. 受管理的模型預設值
- 新的 Copilot harness 聊天會使用組織的受管理預設值，即使你將 `chat.defaultModel`（可由組織原則設定）設為其他偏好亦然。
- 模型選擇器與該設定會說明套用了哪些預設值；仍可針對每個聊天變更模型與支援的選項。
- 範例：受管理設定 `"model": "auto"`、`"autoTier": "intelligence"`，讓新聊天預設使用 Auto 搭配 Intelligence 層級。

### 3. Local 為何被停用
- 企業原則要求 Copilot harness 時，Local harness 在 harness 選擇器中保持可見但停用，並附 **Learn why** 連結說明限制。
- 觸發條件：要強制執行**非空**的受管理 `permissions.deny` 規則或 `sandbox.enabled: true` 時，就必須使用 Copilot（除非適用暫時覆寫）；其他 `permissions.*` 設定與空的拒絕清單不會觸發。
- 系統管理員可用企業受管理設定（非使用者設定）禁止 Local：
  - `vscode.temporaryAllowLocalHarness`：`false` 禁止 Local、Claude 與 Codex harness，並覆寫下方暫時預設；`true` 不會覆寫其他原則。
  - `vscode.temporaryDefaultToLocalHarness`：`true` 讓 Local 保持可用，並抑制自動路由到 Copilot（含拒絕清單與沙箱要求）；明確選擇與已記住的選擇會保留。
- 要求使用 Copilot 時，開啟未封存的 Local 聊天會移至 Copilot；編輯器內嵌聊天及其他 Claude、Codex 的限制不變。
- 注意：這些是 Local 退役期間的暫時控制；Local 無法強制執行僅限執行階段的權限與沙箱控制，需要這些控制時請勿啟用 Local 暫時覆寫；Copilot 在企業環境中無法運作時請回報問題。

### 4. 組織設定載入期間的中斷減少
- Copilot harness session 與模型變更會等待載入緩慢的組織設定，顯示進度，失敗時可重試；等待期間仍可選取 **Stop**。
- 組織限制會在請求執行前套用。

### 5. 受管理工具的核准提示減少
- Assisted 權限對其已核准的合格受管理工具請求，不再重複提示。
- 一次性限制、受管理的拒絕與沙箱限制仍然適用。

### 6. 受管理外掛自動安裝
- Copilot harness session 會在使用前先安裝或更新組織要求的 agent 外掛（例如在受管理設定的 `enabledPlugins` 中設 `"my-plugin@my-marketplace": true`）。
- 受信任存放庫設定所啟用的外掛、組織指派給團隊的外掛，會在背景安裝，不阻擋聊天。
- 優先順序：受管理設定 > 受信任存放庫設定 > 你自己的選擇；團隊指派只在沒有其他選擇時套用。
- 自動安裝的外掛只在該 session 啟用，不會加入使用者設定。

### 7. Claude 與 Codex session
- 原則要求 Copilot harness 時，既有 Claude 與 Codex session 仍在 session 清單中可見，可用 Copilot harness 繼續。
- 此情境下仍無法建立新的 Claude 或 Codex session。

## 九、VS Code 安裝設定

### 1. 隨 VS Code 安裝 GitHub Copilot CLI
- 可透過 VS Code 安裝程式安裝 GitHub Copilot CLI；組織可透過 Managed AI Settings 停用此選項。
- **Windows**：安裝程式新增安裝 GitHub Copilot CLI 的選項；已安裝者不會顯示。
- **Linux**：安裝程式在使用者路徑加入 `copilot` 執行檔；執行 `copilot` 時，未安裝則提示安裝，已安裝則直接執行 GitHub Copilot CLI。
- **macOS**：透過命令選擇區將 VS Code 加入 `$PATH` 時，會提示安裝 GitHub Copilot CLI。
