# Visual Studio Code 1.146 重點摘要

- 版本：1.146.0（Stable）
- 發行日期：2026 年 11 月 11 日
- 原文連結：https://code.visualstudio.com/updates/v1_146

---

## 一、版本亮點

本版主旨：把腦力留給真正需要的工作——Inbox 模式讓你掌握該關注的 session，agent 代為進行模型比較；再以聊天視窗與擴充功能，依任務打造 agent 工作區。

- **Inbox 模式（實驗性）**：跨所有專案聚焦需要關注的 session，其他可延後處理。
- **模型比較（預覽）**：可將 Copilot Fusion 納入比較，或讓 agent 代為執行比較。
- **聊天視窗（預覽）**：聊天可擁有獨立視窗，並重新排列聊天、編輯器與終端機。
- **Agents 視窗中的擴充功能（實驗性）**：可在 Agents 視窗中尋找並安裝擴充功能。
- **Local harness 淘汰**：須在 2027 年 2 月 Local harness 移除前改用 Copilot harness。

## 二、Agent

### 1. Copilot harness 與 Local harness 的淘汰
- Copilot harness 自 VS Code 1.143 起即為新 session 的預設值，建構於 Copilot SDK（讓各 Copilot 產品行為、功能與改進一致的共用基礎）。
- Copilot harness session 透過 Agent Host 執行：可在背景持續執行，並同時從編輯器視窗與 Agents 視窗存取。
- 對組織而言，Copilot harness 會強制執行 Local harness 所不具備的受管理沙箱與權限原則。
- **自本版起 Local harness 已淘汰，三個月後（2027 年 2 月）移除**：
  - **接下來三個月**：仍可使用，但功能已凍結；新功能與改進以 Copilot harness 為重心，不保證 Local harness 支援。
  - **三個月之後**：Local harness 不再提供；VS Code 1.142 引入、用來將 Local harness 保留為預設值的企業管理設定 `vscode.temporaryDefaultToLocalHarness` 也將一併移除。
- 因 Copilot harness 已是預設值，多數人可能不需採取新動作；開始新 session 時在 harness 選擇器看到 **Copilot** 即可確認。
- 仍使用 Local harness 者應規劃在 2027 年 2 月前完全改用 Copilot harness；「Local 轉換至 Copilot harness 指南」涵蓋自訂項目相容性、延續既有 Local 對話，以及組織推行與驗證。

### 2. Session 的 Inbox 模式（實驗性）
- **設定**：`sessions.list.inboxEnabled`（預設關閉）。
- 不必逐一查看工作區，就能在單一檢視中看到需要關注、仍在執行、已可合併的 agent 工作。
- 啟用設定後，在 Agents 視窗 sessions 清單選取 **Grouping > Inbox Mode**。
- 需要關注的 session 顯示在最上方，位於 **Working**、**Ready to merge**、**On hold**、**Done** 群組之上。
- 可延後的 session 可用 **Dismiss from Inbox**、**Put on Hold** 或 **Snooze** 擱置；改變主意可選 **Undo**。
- 從 Inbox 移除不等於封存；要封存須選 **Mark Session as Done**。

### 3. Session 清單的內嵌動作（實驗性）
- **設定**：`sessions.list.inlineActions`（預設關閉）。
- 可直接在 Agents 視窗 sessions 清單修正失敗的檢查、處理審查意見，或兩者兼具。
- 每個動作會在背景將要求送給該列的 session 或巢狀 session，不會開啟它。
- 限制：此設定不會啟用 Agent Merge，也不會變更動作的權限。

### 4. 聊天視窗（預覽）
- **設定**：`sessions.chatWindows.enabled`；Insiders 預設啟用，Stable 預設關閉。
- 解決多個聊天擠在同一個 Agents 視窗、需來回切換而看不到正在等待的那一個的問題；可在獨立視窗開啟聊天，並安排聊天、其編輯器與終端機。
- **開啟方式**：在 sessions 清單的 session 或聊天上按右鍵 → **Open in** > **New Window**；或將聊天拖出 Agents 視窗。以 **Move to Main Window** 命令移回。
- 一個聊天視窗可容納來自一個或多個 session 的多個聊天：可在標題列切換 session、從其他視窗拖入聊天，或按標題列左側 **New Session**（Ctrl+N）開新 session。
- 重新啟動 VS Code 後，聊天視窗會連同聊天與編輯器一起重新開啟。
- 視窗內容以「部分（part）」組織，可自由排列：
  - **移動部分**：拖曳卡片頂端抓取點到視窗另一側或其他部分旁；或用 **Move Part Left / Right / Up / Down**。
  - **在部分間移動索引標籤**：拖到另一部分，或放在邊緣以分割；命令選擇區可用 **Move Editor to Part**、**Move Editor into New Part Left/Right/Above/Below**；將編輯器索引標籤拖到聊天輸入框可作為內容附加。
  - **放置終端機**：拖到編輯器或聊天下方會將 **Terminal Position** 設為 **Under Editor** 或 **Under Chat**；放在視窗底部邊緣設為 **Full Width**；也可從終端機的 **...** 選單變更。
  - **切換版面配置**：標題列 **Configure Layout** 可顯示聊天、編輯器或兩者，並排或堆疊；堆疊配置下 **Agents: Toggle Chat Conversation** 可將聊天收合到只剩輸入框。
- **Developer: Reset Chat Window Layout** 可將視窗恢復為最初開啟的樣子。
- 原文附兩段影片：在獨立視窗開啟聊天、重新排列並重設版面配置。

### 5. 在 Agents 視窗中安裝與管理擴充功能（實驗性）
- Agent Customizations 的 **Extensions** 區段可選擇哪些已安裝擴充功能在 Agents 視窗執行，不影響其在編輯器視窗的啟用狀態。
- 過去新增擴充功能需切換到編輯器視窗安裝；本版可在 Agents 視窗內尋找、安裝與解除安裝。
- **從 Marketplace 安裝**：搜尋也會查詢 Marketplace，列出尚未安裝的相符擴充功能及其發行者、安裝次數、評分；安裝後加入 VS Code 並在 Agents 視窗啟用；要裝其他版本（如發行前版本）可用 **Install** 旁的下拉選單。
- **安裝前先知道哪些無法運作**：提供檢視、偵錯工具、狀態列項目或逐步解說但未宣告支援 Agents 視窗的擴充功能，會顯示警告並列出不支援的功能；無法安裝者（如組織不允許）會顯示原因。
- **快速鍵**：Ctrl+Shift+X 或執行 **Extensions: Manage Extensions** 開啟此區段；若曾自訂編輯器視窗 Extensions 檢視的快速鍵，在 Agents 視窗同樣有效。

### 6. 模型比較改進（預覽）
- **設定**：`sessions.chat.compareAgents.tools.enabled`。
- Compare Models 可在多個模型上執行相同提示，以評審（judge）評估結果，並以綜合器（synthesizer）結合優點；本版讓比較更易設定、整理與自動化。
- **評審並綜合僅限聊天的回應**：不必選取工作區即可加入評審與綜合器；選取 **Synthesize** 時才開始綜合，並建立新聊天，不變更原本的嘗試結果。
- **比較 Copilot Fusion**：可為某次嘗試、評審或綜合器選取 Fusion 及其支援的推理強度層級。
- **讓 agent 執行評估（實驗性）**：啟用上述設定後，agent 可探索模型、啟動比較，並讀取結果與對話參考，彙整跨情境的發現。
  - 這些工具預設關閉，且需先啟用 Compare Models；停用後仍可進行手動比較。

### 7. Canvas 改進（預覽）
- **設定**：`chat.canvases.enabled`（可由組織原則設定）。
- Canvas 是你與 Copilot 共同處理計畫、儀表板與其他成品的共用互動介面；本版新增權限提示並改善探索與延續性。
- **canvas 擴充功能的權限**：在 Copilot harness session 中，canvas 擴充功能在初始化特殊權限功能（例如 hooks）前會先徵求同意。
- **尋找並重新開啟 canvas**：Canvas 選單區分 **Running**（執行中）與可建立新執行個體的 **Available**（可用）；Agents 視窗中建立或安裝 canvas 的動作位於 **Discover More**。
- **不需再次提示即可繼續**：回到非使用中的 Copilot harness session 時，canvas 會還原，不必再傳送訊息。
- **更順暢的重新連線**：canvas 提供者重新啟動期間，持續顯示最後一張 canvas 影像並附重新連線指示器。
- **canvas 與聊天保持在一起**：在獨立聊天視窗中，聊天離開視窗時 canvas 索引標籤會關閉，並可隨聊天重新開啟；視窗重新載入後 canvas 也會還原，且不搶走焦點。

### 8. 設定電腦共用（實驗性）
- **設定**：`sessions.chat.experimental.remoteEnvironmentsThisComputer`。
- Agents 視窗中的 Remote Environments 編輯器是管理遠端連線的集中位置；本版可管理這台電腦與其他用戶端共用的方式。
- 無論是否啟用共用，本機 session 都會繼續直接在這台電腦上執行。
- 可透過 GitHub Environments 或 Dev Tunnels 共用，或關閉共用；也可變更其他用戶端看到的電腦名稱。
- 開啟方式：從聊天的 Environment 選擇器、命令選擇區，或標題列 **Remote Connections** 選單（天線圖示）使用 **Manage Remote Environments**；該選單也提供相同的共用選項。

### 9. Agent Host 支援虛擬存放庫
- VS Code 支援虛擬工作區（例如不必複製即可檢視 GitHub 存放庫）。
- Copilot harness 過去無法在虛擬存放庫中運作；本版新增支援，可使用與本機資料夾相同的 Copilot 功能與工作流程。

## 三、聊天

### 1. 在 VS Code 中繼續 Copilot CLI session（實驗性）
- 在 VS Code 外的終端機使用 GitHub Copilot CLI 時，可將 session 移到 VS Code 繼續。
- 在 CLI 輸入 `/code`（Insiders 為 `/code-insiders`）：CLI 結束，VS Code 在該 session 所屬資料夾的視窗中，以 Chat 檢視開啟同一 session；VS Code 未執行時會自動啟動。
- 保留內容：對話記錄、模型與推理強度、模式與權限。
- 需求與限制：
  - `/code` 在 Copilot CLI 中為實驗性功能，需 Copilot CLI 1.0.107 或更新版本，並開啟實驗性功能（`/settings experimental on`）。
  - 僅適用於 CLI 處理程序的權限（如 `--allow-tool` 或為該 session 授予的核准）不會帶過來，CLI 會在交接前列出。
  - 若另一個 Copilot CLI 處理程序仍開著該 session，VS Code 會在開啟前先詢問。
  - 要返回 CLI，執行 CLI 交接時顯示的 `copilot --resume` 命令。

### 2. 可設定的背景傳送動作快速鍵
- 在 Agents 視窗撰寫區按 Ctrl+Enter，可開始新 session 而不開啟它。
- 可在 **Keyboard Shortcuts** 重新繫結或移除 **Chat: Send in Background** 的快速鍵。
- 選用提示會顯示你設定的快速鍵並連結到 **Keyboard Shortcuts**；以 `chat.sendInBackgroundTip.enabled` 啟用（實驗性，預設關閉）。

## 四、MCP

### Skills over MCP（預覽）
- **設定**：`chat.agentHost.mcpSkills.enabled`。
- 支援 SEP-2640 Skills over MCP，讓 MCP 伺服器能自動向模型提供 skills。
- 第一次連線到提供 skills 的 MCP 伺服器時，會詢問是否允許將其加入模型內容。
- 之後模型可與這些 skills 互動，並可在 Agent Customizations 編輯器的 **Skills** 索引標籤看到。

## 五、信任與安全性

### 1. 改進的權限提示
- 過去 Copilot harness 會對網頁擷取、終端機命令、檔案讀取等建議過於寬鬆的工具層級允許權限；例如擷取 URL 的預設動作為「Allow in this Session」，等於讓模型在該 session 中存取任何 URL。
- 現在權限提示更細緻，預設針對特定網域、命令與目錄新增允許權限。

### 2. 在沙箱中遮罩環境變數
- **設定**：`chat.agent.sandbox.credentials.envVars`。
- 可設定在沙箱化 session 中要遮罩、並對 agent 工具隱藏的環境變數；沙箱化工具只收到預留位置值，真正的值只提供給經核准的 HTTPS 目的地。
- 範例：`API_TOKEN` 的值被替換為預留位置值，只有傳往 `injectHosts` 所列主機（`api.example.com`）的對外 HTTPS 要求才會還原真值；傳往其他主機的要求維持預留位置值。

  ```json
  {
    "chat.agent.sandbox.credentials.envVars": {
      "API_TOKEN": {
        "injectHosts": ["api.example.com"]
      }
    }
  }
  ```

- 注意事項：
  - 設定中輸入的是變數名稱，不是機密值。
  - Windows 上，環境變數遮罩需要區域網路存取權。
  - macOS 與 Windows 上，需要作業系統憑證信任的工具，須信任沙箱 CA 憑證。

### 3. 聊天輸入框中的沙箱狀態
- 不必開 Permissions 選單即可得知終端機沙箱是否啟用。
- 在編輯器與 Agents 視窗中，**Sandboxing for terminal** 開啟時，空白聊天輸入框會顯示 **(sandbox enabled)**。
- 切換聊天或變更設定時，預留位置文字會同步更新。

## 八、企業

### 1. 位於企業 Proxy 後方的 Copilot session
- Copilot session 在本機、WSL 或本機 Dev Container 中執行時，會遵循 VS Code 的 Proxy 設定，包括 Proxy 自動設定（PAC）與 Kerberos 驗證。
- 組織路由規則可針對每個目的地選擇不同 Proxy 或直接連線，不必強制所有要求經過單一 Proxy。

### 2. 原則限制的組織說明連結
- 組織可在企業管理設定中設定 `communication.support.url`，將遭封鎖的開發人員導向組織自己的說明頁面。
- 建議指向員工可找到組織 Copilot 使用原則與支援指引的頁面。
- 有效的絕對 HTTP 或 HTTPS URL 會在支援的原則限制（例如已停用的 Agents、組織停用的模型）中加入 **Contact Admin** 連結。

  ```json
  {
    "communication": {
      "support": {
        "url": "https://ai.example.com/your-companys-ai-landing-support-page"
      }
    }
  }
  ```

### 3. canvas 擴充功能的企業控制
- 在 Copilot harness session 中，`strictPluginOnlyCustomization` 原本已限制獨立的 skills、agents、hooks 與 MCP 伺服器；現在也會封鎖來自使用者、專案與 session 目錄的獨立 canvas 擴充功能，讓系統管理員可要求 canvas 擴充功能必須來自符合資格的外掛程式。
- 在企業管理設定中設為 `true`：封鎖所有支援的獨立類別，同時允許符合資格的外掛程式內容。

  ```json
  {
    "strictPluginOnlyCustomization": true
  }
  ```

- 只限制特定類別：將 `true` 改為包含 `"skills"`、`"agents"`、`"hooks"`、`"mcp"`、`"extensions"` 中任意項目的清單。
- **注意**：VS Code 僅支援布林值的 `ChatStrictPluginOnlyCustomization` 原則無法控制 canvas 擴充功能；canvas 擴充功能由 Copilot SDK 管理，須使用上述 Copilot 受管理設定。
