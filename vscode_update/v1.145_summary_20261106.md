# Visual Studio Code 1.145 重點摘要

- 版本：1.145（Stable），目前更新版為 1.145.1
- 發行日期：2026 年 11 月 4 日
- 原文連結：https://code.visualstudio.com/updates/v1_145

---

## 一、版本亮點

本版主軸是讓遠端 agent session 用起來更像本機：在 VS Code 中預覽應用程式與使用 canvas、用 cron 微調自動化排程、降低聊天雜訊，並加入一款 Blobby 小遊戲。

- **遠端 agent**：不離開 Agents 視窗即可從遠端 agent session 預覽應用程式、使用互動式 canvas。
- **自動化**：以 cron 設定內建預設以外的自訂排程。
- **Agent 詳細程度**：可選擇精簡顯示或完整呈現推理與工具呼叫。
- **檔案排除**：排除資料夾的同時保留需要的檔案可見、可搜尋。
- **趣味**：Blobby 平台跳躍遊戲。

## 二、遠端 agent

### 1. 透過遠端 agent host 連線瀏覽（預覽）
- 設定：`workbench.browser.enableRemoteProxy`
- Agent session 在遠端 agent host 上執行時，Agents 視窗的整合式瀏覽器改為透過該主機載入頁面（與遠端工作區既有行為一致）。
- Agent 在遠端機器啟動開發伺服器後，可直接在 Agents 視窗開啟，預覽應用程式、驗證 agent 變更並給予回饋，體驗如同本機 session。
- 網址列會顯示連線來源（例如「Connected via kyles-mbp」）。
- 問題請回報至 VS Code 存放庫。

### 2. 遠端 canvas（預覽）
- 設定：`workbench.browser.enableRemoteProxy`、`chat.canvases.enabled`（後者可由組織原則設定）
- 基於遠端 agent host 連線支援，現在可使用託管在遠端 agent host 上的 canvas。
- 兩個設定都需啟用；問題請回報至 VS Code 存放庫。

## 三、Agents

### 1. 在同一個 session 中混搭 agent harness（預覽）
- 設定：`chat.agentHost.multipleChatProviders.enabled`
- 背景：巢狀 session 可把相關對話集中在一個主 session 中，但過去每個巢狀 session 都沿用父 session 的 harness；想聽其他 agent 意見就得另開 session，失去分組。
- 本版巢狀 session 可使用與父 session 不同的 harness。例如：請 Claude 檢閱 Copilot 聊天寫的計畫，或在同一 session 中並排把相同任務交給 Codex。
- 建立新巢狀 session 時，以 harness 選擇器切換 harness。
- 每個聊天各自擁有模型、agent 與權限層級（依其 harness 而定），彼此變更互不影響。
- 移動聊天會保留歷程並沿用其所選 harness；分支（fork）巢狀 session 會沿用相同組態。
- 使用不同 harness 的聊天，滑鼠停留在其聊天索引標籤或 session 清單列上時會顯示 harness 名稱。

### 2. 本機自動化的 Cron 排程與自訂 agent
- 自動化可隨選或依排程自動執行 agent 任務，免去逐一手動執行。
- **Cron 排程**：選取 **Cron** 輸入五欄位 cron 運算式；對話方塊會驗證運算式並描述產生的排程。
  - 限制：雲端自動化不支援 cron 排程。
- **工作區自訂 agent**：建立或編輯本機自動化時，可選擇所選工作區中的自訂 agent。
- **專注於進行中項目**：已停用的自動化移到收合的 **Disabled automations** 區段，不再遮蔽執行歷程與進行中的自動化。

### 3. 將 canvas 釘選到側邊欄（實驗性）
- 設定：`chat.canvases.enabled`（可由組織原則設定）
- 開啟 canvas 後，選取其上方的 **Add to Sidebar** 按鈕即可釘選到左側側邊欄。
- 離開該 canvas 後，仍可從側邊欄存取。

### 4. Copilot harness
- 持續作為 VS Code 新 session 的預設 harness；建構於 Copilot SDK（讓各 Copilot 產品的行為、功能與改進一致的共用基礎）。
- Harness 選擇器顯示 **Copilot** 表示使用 Copilot harness。
- Session 可在背景執行，並可同時從編輯器視窗與 Agents 視窗存取；透過 Agent Host 執行。
- 新增「從 Local 轉換到 Copilot harness」指南，涵蓋：自訂項目相容性、session 延續性、組織推行與驗證。
- 官方請使用者持續回報，特別是阻礙組織離開 Local harness 的工作流程或整合。
- 相關資源：Copilot harness 使用文件、agent host 架構部落格文章。

### 5. 工作集改進（實驗性）
- 設定：`chat.editor.workingSet.enabled`
- 上一版已為 Copilot harness session 推出工作集，可像 Local harness 一樣對待處理的 agent 編輯選擇保留（keep）或復原（undo）。
- 本版改進：
  - WSL、Dev Containers、SSH 工作區中的檔案，從工作集開啟時會在正確的主機上開啟。
  - 多個工具呼叫平行編輯同一檔案時，工作集會追蹤這些編輯；編輯完成後，編輯器的內嵌檢閱控制項仍可使用。
- 工作集在編輯器視窗中仍為預設啟用；文件有說明其追蹤哪些編輯。

### 6. 無法使用必要沙箱時提供更好的指引
- Agent 沙箱會限制終端機命令可存取的檔案系統與網路資源；組織可透過不允許略過沙箱的受管理設定強制使用。
- 若組織要求沙箱、但機器無法執行，警告橫幅會：
  - 說明終端機命令為何被封鎖及如何解決；
  - 顯示具體原因（例如缺少相依性）；
  - 連結到疑難排解步驟。
- 若帳戶與組織支援雲端 session（實驗性），可考慮改在雲端執行 agent 工具。

## 四、聊天

### 1. 選擇 agent 詳細程度（實驗性）
- 設定：`chat.persistentProgressVerbosity`
- 操作：Chat 檢視 **More Actions** 功能表 > **View Mode**。
- 三種模式：
  - **Conversation**：專注對話；推理與工具呼叫分組成收合區段，置於回應文字區塊之間，可展開檢查。
  - **Verbose**：工具呼叫展開，逐步追蹤；工具群組無內部捲動限制。
  - **Compact**（預設）：執行中可預覽工具呼叫，完成的群組收合為可展開的摘要列。
- 可在同一聊天中切換；只改變顯示方式，不影響情境或 agent 執行的工作。
- 啟用持續進度後，往回捲動時進度指示器會停在聊天輸入框上方；偏好動畫輸入框邊框者可啟用 `chat.progressBorder.enabled`。

### 2. 聊天效能改進
- 重新開啟與瀏覽較長的 Copilot harness 聊天更流暢。
- 重複使用既有的推理標題；還原的工具呼叫中，終端機輸出改為在展開或顯示時才轉譯，而非一次全部轉譯。
- 減少還原與瀏覽長對話時重複的進度更新與版面配置測量。

### 3. 內嵌聊天附件（實驗性）
- 設定：`chat.inlineAttachments.enabled`
- 附件膠囊（pill）插入在提示詞的游標位置，而非輸入框上方獨立一列，讓參考緊鄰所屬指示。
- 附件膠囊可如單一字元般移動經過、選取、刪除；先前的訊息也保留內嵌膠囊。
- 預設值：Insiders 開啟、Stable 關閉。

### 4. 從電腦上任何位置附加檔案
- 過去要提供工作區外的檔案（如桌面上的螢幕擷圖、mockup），必須從檔案管理員拖曳或請 agent 尋找。
- 現在：**Add Context**（`+`）> **Files**，以標準檔案對話方塊選一或多個檔案；沒有工作區的新聊天也可用。
- 限制：雲端 session 中選擇器只列出圖片。
- 沙箱行為（Copilot harness session 啟用沙箱時）：
  - Agent 可讀取附加的檔案與資料夾，即使位於工作區外。
  - 每個附加路徑在 session 剩餘期間可讀，但不可寫入；此存取權不會存入設定。
  - 使用 Manual 權限時，agent 讀取附加檔案前不再詢問。
  - 若組織受管理設定定義了自己的可讀取路徑清單，附件不會加入該清單。

## 五、MCP

### 1. 支援 MCP app 提供的工具
- MCP app 是 MCP 伺服器提供的互動式介面，現在可註冊工具，供語言模型在下一次請求中呼叫。
- 範例：ShaderToy 伺服器讓模型可即時反覆調整著色器。

### 2. 受管理 MCP 允許清單的優先順序
- 對 VS Code 啟動的 MCP 伺服器，企業管理的 `allowedMcpServers` 清單優先於僅限登錄存取；組織可核准伺服器而不必發布到登錄。
- 詳細設定與限制見「企業」章節。

## 六、編輯器體驗

### 1. 在已排除的資料夾中顯示特定檔案
- 設定：`files.exclude`、`search.exclude`
- 在 `files.exclude` 的樣式前加 `!` 前綴，可讓已排除資料夾中的部分內容保持可見。
- 符合的檔案與資料夾會出現在 Explorer、Search 與 Quick Open，即使被其他樣式或 `.gitignore` 排除。
- `search.exclude` 中的例外只套用於 Search 與 Quick Open。
- 範例：排除 `node_modules`，但以 `"!node_modules/@types": true` 保留 `@types`。
- 注意：例外永遠不會隱藏檔案；`!**/node_modules/@types` 這類樣式會在任何深度比對，但可能讓搜尋變慢。

### 2. Mermaid 圖表中的智慧子圖標題
- 邊（edge）不再遮蓋子圖標題；邊會穿過標題時，標題會移到側邊。
- 使用預設 `vscode` Mermaid 佈景主題時，子圖改以外框呈現而非填滿，巢狀子圖更醒目。

## 七、企業

### 1. 組織要求的外掛無法解除安裝
- 問題：組織透過 `enabledPlugins` 等受管理設定要求某個 agent 外掛時，**Customizations** 檢視仍提供 **Uninstall**，但一定失敗並變成同樣會失敗的 **Retry Uninstall**；外掛提供的提示詞、skill、agent、hook 與 MCP 伺服器也一樣。
- 現在：這些外掛及其提供項目的 **Uninstall** 已停用，並在滑鼠停留與鍵盤聚焦時顯示訊息（說明由組織管理）。
- 適用位置：**Browse**、外掛詳細資料、外掛編輯器、外掛與 MCP 伺服器功能表。

### 2. 受管理的 MCP 允許清單優先於僅限登錄存取
- 過去：組織同時限制「僅限登錄」並定義允許清單時，VS Code 仍要求伺服器必須在登錄中，導致允許清單核准但未發布到登錄的伺服器無法執行。
- 現在：企業管理的 `allowedMcpServers` 具最終決定權——符合清單者即使不在登錄也能執行；不符合清單的登錄伺服器會被封鎖。
- 範例設定可同時允許遠端伺服器（`serverUrl`）與本機伺服器（`serverCommand`）。
- 規則：
  - 空清單（`[]`）封鎖所有伺服器；未設定清單則照舊套用登錄限制。
  - 使用者與工作區允許清單無法將伺服器加入企業清單。
  - `deniedMcpServers` 與關閉 MCP 仍優先於允許清單。
  - 建議優先使用 `serverUrl`、`serverCommand` 規則；`serverName` 比對的是伺服器作者自選的標籤。
- 適用範圍：僅限 VS Code 啟動的 MCP 伺服器，不含由 Agent Host 管理的伺服器。

## 八、擴充功能貢獻：GitHub Pull Requests（0.176.0）

- PR 概觀時間軸顯示更多事件：標籤、里程碑與標題變更；檢閱請求與撤銷；草稿與「準備好檢閱」狀態變更；強制推送；分支還原；自動合併變更；合併佇列更新。
- PR 描述範本支援 issue 變數 `${issueTitle}`、`${issueNumber}`、`${issueNumberLabel}`，由「Start Working on Issue」與分支關聯的 issue 填入。
- 堆疊 PR 時，會提示為堆疊中已啟用自動合併的 PR 停用自動合併。
- 完整內容見 0.176.0 changelog。

## 九、擴充功能撰寫：Timeline API 正式定案

- 發布到 Marketplace 的擴充功能可在 Timeline 檢視加入自己的歷程，與 Git 提交和本機歷程並列。
- API：
  - `workspace.registerTimelineProvider`：針對檔案與資料夾註冊提供者。
  - `workspace.registerWorkspaceTimelineProvider`：針對整個工作區註冊。
- 將 `TimelineItem.resourceUri` 設為該項目當時的資源內容，使用者即可用 **Compare Selected** 與其他項目比較。
- 詳見 Timeline API 文件。

## 十、趣味：Blobby 跳躍遊戲（實驗性）

- 在聊天輸入 `/vscode-pet` 顯示 VS Code 寵物 Blobby。
- 在 Agents 視窗新 session 畫面，從 Blobby 的內容功能表選 **Play Jump Game**。
- 操作：按住空白鍵蓄力跳躍，方向鍵瞄準下一個平台。
- 最高分會記錄在該裝置上。

## 十一、已棄用的功能與設定

### 本版新棄用項目（皆為 Local harness）
1. **Install Extension 工具移除**（`#installExtension`）
   - 從聊天建立新工作區時，agent 不再安裝擴充功能，改為把所需擴充功能寫入 `.vscode/extensions.json`，由使用者在 Extensions 檢視檢閱並安裝。
   - 在沒有 Jupyter 擴充功能時執行 Jupyter 筆記本中的 Python 儲存格，核心選擇器會提示安裝。
   - 自訂 agent 或提示檔若參考 `#installExtension`，請移除。
2. **Run VS Code Command 工具移除**（`#runCommand`）
   - 原本仰賴它的內建工作流程已可不靠它運作；例如診斷網路問題時，聊天會請你執行 **Developer: Chat Diagnostics** 並分享報告。
   - 自訂 agent 或提示檔若參考 `#runCommand`，請移除。
3. **工作區建立工具與斜線命令移除**
   - 移除 **Create New Workspace**（`#newWorkspace`，先前為 `#new`）工具、`/new` 斜線命令、Welcome 頁面的 **Generate New Workspace** 連結，以及專用的專案設定 skill。
   - 新做法：開啟空資料夾，在 agent session 中描述想要的專案；agent 以標準工具建立檔案、執行 scaffolding 命令並設定工作（task）。
   - 需從自訂 agent 與提示檔移除的參考：`#newWorkspace`、`#new`、`/new`、`project-setup-info-local`、`project-setup-info-context7`。
   - 已移除的設定：`github.copilot.chat.newWorkspaceCreation.enabled`、`github.copilot.chat.newWorkspace.useContext7`、`github.copilot.chat.useProjectTemplates`。
   - 筆記本建立不受影響。

### 即將棄用的項目
- 無。

## 十二、重要修正

- **#345207**：組織關閉 Claude 或 Codex agent 後，先前選過該 agent 的使用者從 **New Chat**（`+`）、**New Chat Editor**、新視窗只會得到無輸入框的唯讀聊天。現在新聊天會回退為預設 harness，未送出的提示詞會帶過去；原則解除後恢復原本的選擇。
- **#344895**：組織在 GitHub Copilot 原則中把 MCP 存取設為僅限登錄時，原則重新整理失敗（如網路錯誤、速率限制）會讓限制暫時消失直到下次成功。現在 VS Code 會保留最後已知的登錄原則，僅在 GitHub 回報沒有適用登錄時才清除。
