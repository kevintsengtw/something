## Agent

### Copilot harness 與 Local harness 的淘汰

Copilot harness 是我們最新的 agent harness，自 [VS Code 1.143](https://code.visualstudio.com/updates/v1_143#_copilot-harness-as-the-default) 起即為新 session 的預設值。它建構於 Copilot SDK 之上，這是一個共用的基礎，有助於讓各項 Copilot 產品的行為、功能與改進保持一致。Copilot harness 的 session 透過 [Agent Host](https://code.visualstudio.com/docs/agents/concepts/agent-host) 執行，因此你可以讓它們在背景持續執行，並同時從 VS Code 編輯器視窗與 Agents 視窗存取它們。對組織而言，Copilot harness 也會強制執行 Local harness 所不具備的受管理沙箱與權限原則。

感謝所有分享使用 Copilot harness 作為預設值之意見回饋的使用者。你們的回饋形塑了 harness 的使用體驗，也將持續引導我們完成接下來這一步。自本版本起，**Local harness 已淘汰，並將於三個月後（2027 年 2 月）移除**：

- **接下來的三個月**：在你遷移工作流程期間，仍可使用 Local harness，但其功能已凍結。新功能與改進將以 Copilot harness 為重心，不保證 Local harness 會支援。
- **三個月之後**：Local harness 將不再提供。VS Code 1.142 中為了[將 Local harness 保留為預設值](https://code.visualstudio.com/docs/enterprise/manage-ai-settings#_keep-local-harness-as-default)而引入的 `vscode.temporaryDefaultToLocalHarness` 企業管理設定，也將一併移除。

由於 Copilot harness 已是新 session 的預設值，你可能不需要採取任何新的動作。若要確認你正在使用 Copilot harness，請在開始新 session 時，於 harness 選擇器中尋找 **Copilot**：

> 圖：harness 選擇器中已選取 Copilot，滑鼠停留說明顯示其與 Copilot SDK 及 Agent Host 整合的螢幕擷取畫面（https://code.visualstudio.com/assets/updates/1_146/harness-copilot-description.webp）

如果你仍在使用 Local harness，請規劃在 2027 年 2 月之前完全改用 Copilot harness。[Local 轉換至 Copilot harness 指南](https://code.visualstudio.com/docs/agents/run/move-to-copilot)涵蓋了自訂項目的相容性、延續既有的 Local 對話，以及組織的推行與驗證。如果遇到任何問題，請[提交 issue](https://github.com/microsoft/vscode/issues) 告訴我們。

### Session 的 Inbox 模式（實驗性）

**設定**：`sessions.list.inboxEnabled`

不必逐一查看每個工作區，就能掌握你的 agent。Inbox 模式讓你在單一檢視中看到哪些需要你關注、哪些仍在執行，以及哪些已可合併。

啟用 `sessions.list.inboxEnabled` 設定（預設為關閉），然後在 Agents 視窗的 sessions 清單中選取 **Grouping > Inbox Mode**。

> 圖：Agents 視窗中 Grouping 選單已選取 Inbox Mode 的螢幕擷取畫面（https://code.visualstudio.com/assets/updates/1_146/sessions-inbox-mode.webp）

需要你關注的 session 會顯示在最上方，位於 **Working**、**Ready to merge**、**On hold** 與 **Done** 群組之上。如果某個 session 可以稍後再處理，可使用 **Dismiss from Inbox**、**Put on Hold** 或 **Snooze** 將其擱置。如果改變主意，請選取 **Undo**。

從 Inbox 中移除 session 並不會將其封存。若要封存，請選取 **Mark Session as Done**。

> 圖：需要關注的 session 顯示在 Inbox 中，位於 Working、Ready to merge、On hold 與 Done 分類之上的螢幕擷取畫面（https://code.visualstudio.com/assets/updates/1_146/sessions-inbox.webp）

### Session 清單的內嵌動作（實驗性）

**設定**：`sessions.list.inlineActions`

直接從 Agents 視窗的 sessions 清單修正失敗的檢查並處理審查意見。啟用此設定（預設為關閉）後，會顯示用於修正檢查、處理意見，或兩者兼具的內嵌動作。

每個動作會在背景將要求傳送給該列的 session 或巢狀 session，而不會開啟它。此設定不會啟用 Agent Merge，也不會變更動作的權限。

> 圖：Agents 視窗 sessions 清單中某個 session 下方顯示 Address Comments 按鈕的螢幕擷取畫面（https://code.visualstudio.com/assets/updates/1_146/inline-session-actions.webp）

### 聊天視窗（預覽）

**設定**：`sessions.chatWindows.enabled`

當同時執行多個聊天時，將它們全部放在同一個 Agents 視窗中，意味著必須在彼此之間切換，並且會看不到你正在等待的那一個。有了聊天視窗，你可以在獨立的視窗中開啟聊天，並安排該視窗，讓聊天、其編輯器與其終端機符合任務需求。

若要在 Stable 版中試用此預覽功能，請啟用 `sessions.chatWindows.enabled`。此功能在 VS Code Insiders 中預設為啟用，在 Stable 版中預設為關閉。

請參閱我們的文件，進一步了解[聊天視窗](https://code.visualstudio.com/docs/agents/run/agents-window#_open-chats-in-separate-windows)。

若要在新視窗中開啟聊天，請在 sessions 清單中的 session 或聊天上按一下滑鼠右鍵，然後選取 **Open in** > **New Window**。你也可以將聊天拖曳出 Agents 視窗以建立新視窗。你可以使用 **Move to Main Window** 命令將其移回。

一個聊天視窗可以容納來自一個或多個 session 的多個聊天：在其標題列中選取另一個 session、從另一個視窗拖曳聊天進來，或選取標題列左側的 **New Session**（Ctrl+N）以在該視窗中開始新的 session。重新啟動 VS Code 後，聊天視窗會連同其聊天與編輯器一起重新開啟。

聊天視窗中的內容是以「部分（part）」來組織的，你可以自由排列這些部分以配合你的工作流程。

- **移動部分：** 拖曳某個部分卡片頂端邊緣的抓取點，將其移到視窗的另一側，或放到另一個部分旁邊。你也可以使用 **Move Part Left**、**Move Part Right**、**Move Part Up** 與 **Move Part Down**。
- **在部分之間移動索引標籤：** 將索引標籤拖曳到另一個部分，或將其放在某個部分的邊緣以分割該部分。使用 **Move Editor to Part** 或 **Move Editor into New Part Left/Right/Above/Below**，即可從命令選擇區執行相同的操作。將編輯器索引標籤拖曳到聊天輸入框上，即可將其作為內容附加到聊天中。
- **放置終端機：** 將終端機拖曳到編輯器或聊天下方，會將 **Terminal Position** 設為 **Under Editor** 或 **Under Chat**。將其放在視窗的底部邊緣則會設為 **Full Width**。你也可以從終端機的 **...** 選單變更位置。
- **切換版面配置：** 使用標題列中的 **Configure Layout**，以並排或堆疊方式顯示聊天、編輯器或兩者。在堆疊版面配置中，**Agents: Toggle Chat Conversation** 會將聊天收合為僅剩輸入框，讓編輯器佔用視窗的其餘部分。

使用 **Developer: Reset Chat Window Layout** 可將視窗恢復為最初開啟時的樣子。

### 在 Agents 視窗中安裝與管理擴充功能（實驗性）

Agent Customizations 的 **Extensions** 區段可讓你選擇哪些已安裝的擴充功能要在 Agents 視窗中執行，而不會變更它們在編輯器視窗中的啟用狀態。過去，新增擴充功能時必須切換到編輯器視窗才能安裝。在本版本中，你可以在不離開 Agents 視窗的情況下尋找、安裝與解除安裝擴充功能：

- **從 Marketplace 安裝**：搜尋時也會查詢 Marketplace，並列出你尚未安裝的相符擴充功能，以及其發行者、安裝次數與評分。安裝擴充功能會將其新增到 VS Code，並在 Agents 視窗中啟用它。若要安裝其他版本（例如發行前版本），請使用 **Install** 旁邊的下拉式選單。
- **安裝前就知道哪些功能無法運作**：若擴充功能提供了檢視、偵錯工具、狀態列項目或逐步解說，卻未宣告支援 Agents 視窗，則會顯示警告並列出不支援的功能。無法安裝的擴充功能（例如因為你的組織不允許）會顯示原因。
- **使用鍵盤快速鍵開啟**：按下 Ctrl+Shift+X 或執行 **Extensions: Manage Extensions** 即可開啟此區段。如果你曾變更編輯器視窗中 Extensions 檢視的快速鍵，你的快速鍵在 Agents 視窗中同樣有效。

> 圖：Agents 視窗中 Extensions 區段的螢幕擷取畫面（https://code.visualstudio.com/assets/updates/1_146/extensions-agents-window.webp）

### 模型比較改進（預覽）

**設定**：`sessions.chat.compareAgents.tools.enabled`

Agents 視窗中的 [Compare Models](https://code.visualstudio.com/docs/agents/run/compare-models) 可讓你在多個模型上執行相同的提示、透過評審（judge）評估其結果，並透過綜合器（synthesizer）結合它們的優點。本版本讓比較更容易設定、整理與自動化：

- **評審並綜合僅限聊天的回應**：不必選取工作區即可新增評審與綜合器。綜合會在你選取 **Synthesize** 時開始，並建立新的聊天，而不會變更原本的嘗試結果。
- **比較 Copilot Fusion**：可為某次嘗試、評審或綜合器選取 Fusion 及其支援的推理強度層級。
- **讓 agent 執行評估（實驗性）**：啟用 `sessions.chat.compareAgents.tools.enabled`，讓 agent 能探索模型、啟動比較，並讀取結果與對話參考，以彙整跨情境的發現。這些工具預設為關閉，且需要啟用 Compare Models。停用它們後，仍可進行手動比較。

### Canvas 改進（預覽）

**設定**：`chat.canvases.enabled`（此設定可由組織原則設定。）

[Canvas](https://code.visualstudio.com/docs/agents/run/canvases) 是共用的互動式介面，讓你與 Copilot 一起處理計畫、儀表板及其他成品。本版本新增了權限提示，並改進了 canvas 的探索與延續性：

- **canvas 擴充功能的權限**：在 Copilot harness session 中，canvas 擴充功能在初始化特殊權限功能（例如 hooks）之前，會先徵求你的同意。
- **尋找並重新開啟 canvas**：Canvas 選單會區分 **Running**（執行中）的 canvas 與你可以建立新執行個體的 **Available**（可用）canvas。在 Agents 視窗中，建立或安裝 canvas 的動作會顯示在 **Discover More** 之下。
- **不需再次提示即可繼續**：當你回到非使用中的 Copilot harness session 時，其 canvas 會還原，而不需要再傳送一則訊息。
- **更順暢的重新連線**：在 canvas 提供者重新啟動期間，最後一張 canvas 影像會持續顯示，並搭配重新連線指示器。
- **讓 canvas 與其聊天保持在一起**：在獨立的聊天視窗中，當聊天離開視窗時，canvas 索引標籤會關閉，並可隨聊天一起重新開啟。視窗重新載入後，canvas 也會還原，且不會搶走焦點。

### 設定電腦共用（實驗性）

**設定**：`sessions.chat.experimental.remoteEnvironmentsThisComputer`

Agents 視窗中的 Remote Environments 編輯器是管理遠端連線的集中位置。在本版本中，你現在可以管理這台電腦與其他用戶端共用的方式。無論是否啟用共用，本機 session 都會繼續直接在這台電腦上執行。

透過 GitHub Environments 或 Dev Tunnels 共用這台電腦，或關閉共用。你也可以變更其他用戶端看到的電腦名稱。

從聊天中的 Environment 選擇器、命令選擇區，或標題列的 **Remote Connections** 選單（天線圖示）使用 **Manage Remote Environments** 開啟此編輯器；該選單也提供相同的共用選項。

> 圖：Remote Environments 編輯器的 This Computer 區段，以 dev-workstation 名稱透過 Dev Tunnels 共用，下方為 Other Environments 表格的螢幕擷取畫面（https://code.visualstudio.com/assets/updates/1_146/remote-environments-this-computer.webp）

進一步了解[讓主機可供遠端存取](https://code.visualstudio.com/docs/agents/run/remote-agent-sessions#_make-a-host-available-for-remote-access)。

### Agent Host 支援虛擬存放庫

VS Code 支援虛擬工作區，讓你可以執行像是[不必複製即可檢視 GitHub 存放庫](https://code.visualstudio.com/docs/sourcecontrol/github#_github-repositories-extension)之類的操作。

Copilot harness 過去無法在虛擬存放庫中運作。在本版本中，我們新增了對虛擬存放庫的支援，因此你可以使用與本機資料夾中相同的 Copilot 功能與工作流程。

## 聊天

### 在 VS Code 中繼續 Copilot CLI session（實驗性）

當你在 VS Code 以外的終端機中使用 [GitHub Copilot CLI](https://github.com/features/copilot/cli) 時，現在可以將 session 移到 VS Code 中繼續進行。

在 CLI 中輸入 `/code`，若是 VS Code Insiders 則輸入 `/code-insiders`。CLI 會結束，而 VS Code 會在該 session 所屬資料夾的視窗中，於 Chat 檢視開啟同一個 session；若 VS Code 尚未執行則會將其啟動。該 session 會保留其對話記錄、模型與推理強度，以及其模式與權限。

`/code` 命令在 Copilot CLI 中屬於實驗性功能。它需要 Copilot CLI 1.0.107 或更新版本，並開啟實驗性功能（`/settings experimental on`）。僅適用於 CLI 處理程序的權限，例如 `--allow-tool` 或你為該 session 授予的核准，不會被帶過來，CLI 會在交接前列出這些權限。如果另一個 Copilot CLI 處理程序仍開啟著該 session，VS Code 會在開啟前先詢問。若要返回 CLI，請執行 CLI 在交接時顯示的 `copilot --resume` 命令。

### 可設定的背景傳送動作快速鍵

**設定**：`chat.sendInBackgroundTip.enabled`

在 Agents 視窗的撰寫區中按下 Ctrl+Enter，即可開始新的 session 而不開啟它。你可以在 **Keyboard Shortcuts** 中重新繫結或移除 **Chat: Send in Background** 的快速鍵。

一則選用的提示會顯示你設定的快速鍵，並連結至 **Keyboard Shortcuts**。可透過 `chat.sendInBackgroundTip.enabled` 啟用（實驗性，預設為關閉）。

### Skills over MCP（預覽）

**設定**：`chat.agentHost.mcpSkills.enabled`

此版本的 VS Code 新增了對 SEP-2640 [Skills over MCP](https://github.com/modelcontextprotocol/ext-skills) 的支援，讓 MCP 伺服器能自動向模型提供 skills。

## 信任與安全性

### 改進的權限提示

Copilot harness 過去會針對網頁擷取、終端機命令與檔案讀取等操作，建議過於寬鬆的工具層級允許權限。例如，擷取 URL 的預設動作是「Allow in this Session」（在此 session 中允許），這會讓模型在該 session 期間存取任何 URL。

現在，權限提示更加細緻，預設會針對特定的網域、命令與目錄新增允許權限。

### 在沙箱中遮罩環境變數

**設定**：`chat.agent.sandbox.credentials.envVars`

為了保護敏感資訊，你可以設定在沙箱化 session 中要遮罩、並對 agent 工具隱藏哪些環境變數。沙箱化的工具會收到預留位置值，而真正的值只會提供給經核准的 HTTPS 目的地。

在此範例中，沙箱會將 `API_TOKEN` 環境變數的值替換為預留位置值。只有在傳送至 `injectHosts` 中所列主機（此處為 `api.example.com`）的對外 HTTPS 要求中，才會還原真正的值。傳送至其他主機的要求會保留預留位置值，不會收到實際的值。

```
{
  "chat.agent.sandbox.credentials.envVars": {
    "API_TOKEN": {
      "injectHosts": ["api.example.com"]
    }
  }
}
```

請在設定中輸入變數名稱，而非機密值。在 Windows 上，環境變數遮罩需要區域網路存取權。在 macOS 與 Windows 上，對於需要作業系統憑證信任的工具，請信任沙箱 CA 憑證。

如需詳細資訊，請參閱[沙箱網路存取](https://code.visualstudio.com/docs/agents/run/agent-sandboxing#_configure-network-access)與[憑證信任](https://code.visualstudio.com/docs/agents/run/agent-sandboxing#_trust-the-sandbox-ca-certificate-on-windows-and-macos)。

### 聊天輸入框中的沙箱狀態

不必開啟 Permissions 選單，即可查看終端機沙箱是否已啟用。在編輯器與 Agents 視窗中，當 **Sandboxing for terminal** 開啟時，空白的聊天輸入框會顯示 **(sandbox enabled)**。當你切換聊天或變更設定時，預留位置文字會保持同步。

> 圖：聊天輸入框預留位置文字顯示為 Chat with Copilot (sandbox enabled) 的螢幕擷取畫面（https://code.visualstudio.com/assets/updates/1_146/sandbox-enabled-placeholder.webp）

## 企業

### 位於企業 Proxy 後方的 Copilot session

Copilot session 在本機、WSL 或本機 Dev Container 中執行時，會遵循 VS Code 的 [Proxy 設定](https://code.visualstudio.com/docs/setup/network)，包括 Proxy 自動設定（PAC）與 Kerberos 驗證。你組織的路由規則可以針對每個目的地選擇不同的 Proxy 或直接連線，而不必強制所有要求都經過單一 Proxy。

### 原則限制的組織說明連結

組織可以在[企業管理設定](https://code.visualstudio.com/docs/enterprise/manage-ai-settings)中設定 `communication.support.url`，將遭到封鎖的開發人員導向組織自己的說明頁面。我們建議將此 URL 指向員工可以找到組織 Copilot 使用原則與支援指引的頁面。有效的絕對 HTTP 或 HTTPS URL 會在支援的原則限制（例如已停用的 Agents 或組織停用的模型）中新增 **Contact Admin** 連結。

例如，在你組織的受管理設定中：

```
{
  "communication": {
    "support": {
      "url": "https://ai.example.com/your-companys-ai-landing-support-page"
    }
  }
}
```

### canvas 擴充功能的企業控制

在 Copilot harness session 中，`strictPluginOnlyCustomization` 原本就會限制獨立的 skills、agents、hooks 與 MCP 伺服器。現在它也會封鎖來自使用者、專案與 session 目錄的獨立 canvas 擴充功能，讓系統管理員可以要求所使用的任何 canvas 擴充功能都必須來自符合資格的外掛程式。

在[企業管理設定](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)中，使用 `true` 可封鎖所有支援的獨立類別，同時允許符合資格的外掛程式內容：

```
{
  "strictPluginOnlyCustomization": true
}
```

若只要限制特定類別，請將 `true` 替換為包含 `"skills"`、`"agents"`、`"hooks"`、`"mcp"` 與 `"extensions"` 中任意項目的清單。

> **注意：** VS Code 僅支援布林值的 `ChatStrictPluginOnlyCustomization` 原則無法控制 canvas 擴充功能。它們由 Copilot SDK 管理，因此請使用上述的 Copilot 受管理設定。

如需原則的詳細資訊，請參閱[企業管理設定參考](https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings)。
