# Visual Studio Code 1.144 重點摘要

- 版本：1.144.0（Stable）
- 發行日期：2026 年 10 月 28 日
- 原文連結：https://code.visualstudio.com/updates/v1_144

---

## 一、版本回顧（GitHub Universe 前的近期成果）

本版以「版本回顧」開場，回顧近期推出的功能（詳見 VS Code Wrapped 部落格文章）：

- **Agent Host**：獨立的處理程序，關閉用戶端後 agent 仍可在本機或遠端持續執行。
- **Agent Host Protocol（AHP）**：借鏡 language server 設計，讓任何用戶端都能與 agent session 互動；VS Code、Copilot CLI、GitHub Copilot App 與 github.com 之間具備 session 延續性。
- **Agents 視窗**：從單一介面管理跨工作區與環境的 agent，可手動啟動或用自動化處理重複性任務。
- **Copilot harness 為預設**：與 Copilot Code Review、Copilot CLI、Copilot App、Copilot Cloud session 使用同一個 harness；agent 自訂寫一次即可通用。
- **Claude Code／OpenAI Codex harness**：可改用這些 harness 並搭配 Copilot 訂閱。
- **模型比較（Agent Bake-Off）與 Copilot Fusion**：前者以同一提示詞比較多個模型與 harness；後者自動選擇最佳模型並協調多個模型協作。
- **圖片產生**：在既有視覺能力之外，可直接在聊天中請 agent 產生圖片。
- **Canvas 支援**：建立豐富的互動式 UI 與 agent 互動，並將輸出視覺化。
- **瀏覽器與桌面應用程式**：讓 agent 操作瀏覽器驗證結果，或操作電腦上的應用程式進行自動化。
- **全新 Markdown 編輯器**：可直接編輯渲染後的 Markdown，仍可編輯原始碼。
- **UI 翻新**：重新設計整體外觀，淺色與深色主題皆適用。

## 二、版本亮點

本版主題：讓 agent 工作跨環境持續推進、為每項任務找到合適模型，並掌控變更與工具呼叫。七項亮點：

- **Session 延續性**：在同一處管理遠端，電腦關機時 session 與自動化仍持續執行。
- **Copilot Fusion 與模型比較**：讓 Copilot 選擇並協調模型，或並排比較模型。
- **圖片產生（預覽）**：在聊天中建立與編輯圖片。
- **Computer use（實驗性）**：讓 agent 使用電腦上的桌面應用程式。
- **工作集（實驗性）**：在編輯器中保留或復原 agent 的檔案編輯。
- **Assisted permissions**：通過風險檢查的工具呼叫自動核准，減少中斷。
- **自訂項目市集與 Copilot connectors（預覽）**：探索 skill 與外掛，並把 Slack、Notion 等服務的情境帶入 agent session。

## 三、Session 延續性

### 1. 在雲端執行並延續 Copilot 任務
- Cloud session 讓你從 VS Code 執行 Copilot 任務，不必讓開發機器保持上線；存放庫與工具在 GitHub 基礎架構的受管理環境中執行。
- 從編輯器視窗的 **Chat 檢視**或 **Agents 視窗**可以：
  - 選取 **Cloud** 並選擇 GitHub 存放庫開始任務。
  - 傳送後續指示、回應核准要求、檢閱 agent 的變更。
  - 從 session 清單重新開啟既有 cloud session，延續同一段對話。
- 可從其他 Copilot 用戶端存取，例如在 GitHub.com 或 **GitHub Mobile app** 查看進度後，再回 VS Code 繼續。
- 限制：使用獨立工作區，本機未提交的變更不會自動複製；需付費 Copilot 方案，並受組織原則約束。

### 2. 管理遠端環境
- 新增 **Remote Environments** 對話方塊，集中管理 GitHub Environments、Dev Tunnels、WSL 發行版與 SSH 主機。
- 在環境選擇器底部選取 **Manage Remote Environments**：查看各遠端狀態、連線／中斷連線、選擇哪些遠端要在選擇器中顯示。

### 3. Cloud Automations（預覽）
- 設定：`chat.automations.cloud.enabled`（預設啟用）
- 在 Agents 視窗中建立與管理 Copilot 雲端自動化；在 GitHub 基礎架構上依排程或存放庫事件執行，電腦關機也能運作。
- 建立方式：請 agent 幫你設定，或使用 Automations 檢視的 **Create Automation** 按鈕。
- 可做到：
  - **因應 issue／pull request 事件執行**：例如 issue 指派給你時自動分類（triage）。
  - **與團隊建立共用工作流程**：對所有可存取該存放庫的人可見，並以 Copilot 身分行動。
  - **精確控制執行時機與能力**：限制允許的工具、加入篩選條件，例如被指派帶特定標籤的 issue 時才觸發。

### 4. Agent Host Protocol v1.0
- 發布 Agent Host Protocol 第一版：VS Code 用來與本機及遠端 agent 通訊的協定，雲端自動化也使用它。
- 開放、可擴充，方便為 agent 打造自訂 UI，或打造可接入任何支援此協定之 UI 的 agent 平台。
- 在 Agents 視窗用 **Agents: Add Remote Agent Host...** 加入以 websocket 為基礎的 agent host；執行 `code agent endpoints` 取得編輯器中執行中 agent host 的端點。
- 已以六種語言發布函式庫，agent 很擅長用它們製作用戶端與 host。

## 四、模型

### 1. GitHub Copilot Fusion（正式推出）
- 在模型選擇器選取 **Copilot Fusion**，由 Copilot 智慧路由請求並協調模型。
- 結合 Project HydraFusion 的多模型協調與 Copilot 自動模型選擇的任務感知選擇，平衡效能與成本。
- 每個請求自動決定模型、推理強度與執行模式：簡單任務由單一模型完成；困難任務由一個模型起草、其他模型審查或評論。滑鼠停留在回應下方的強度層級可查看使用了哪些模型。
- 強度層級：**Standard**（日常程式開發）、**High**（要求較高的任務）、**Max**（最複雜的任務）。
- 計費：所使用的每個模型依標準費率計費；2026 年 11 月 30 日前，付費 Copilot 方案使用 Fusion 享 30% 折扣。
- 方案：正式推出；Fusion High 與 Max 提供給 Copilot Pro+、Max、Business、Enterprise 方案。

### 2. 預設比較模型與 harness，並支援更多專案
- 設定：`sessions.chat.compareAgents.enabled`
- 模型比較以同一提示詞在多個模型上執行並排檢閱；Agents 視窗中符合資格的新 session 預設啟用（除非被使用者設定或實驗覆寫）。
- 擴展情境：
  - **不需專案**：從無資料夾的 **Chat** 執行獨立嘗試，不需 Git 存放庫、judge 或 synthesizer。
  - **本機或空的存放庫**：不再需要 Git 遠端與初始提交；無提交的存放庫中，每個隔離嘗試從未被忽略之工作檔案的快照開始，不變更來源分支或索引。
- 快速鍵：在符合資格的聊天輸入框或模型選擇器按 Ctrl+Alt+M 開啟比較設定。
- 設定流程的導覽按鈕改標示目的地：**Configure Judge**、**Configure Attempts**、**Configure Synthesis**，取代通用的下一步／上一步。
- 限制：Dev Containers 不支援模型比較。

### 3. Copilot 中的圖片產生（預覽）
- 設定：`chat.copilot.imageGeneration.model`、`chat.copilot.imageGeneration.watermark`
- Agent 使用 GPT Image 2.5 Flare 依提示詞產生圖片，例如網站圖片、聊天背景、新圖示、網站線框圖；也可加入既有圖片作為情境，請 agent 修改或產生變化版本。
- 預設模型為 GPT Image 2.5 Flare；將 `chat.copilot.imageGeneration.model` 設為 `off` 可停用。
- 需能存取所選模型，且會在對話模型之外額外使用 AI 點數。
- 將 `chat.copilot.imageGeneration.watermark` 設為 `true`，可加入可察覺的 `Made with AI` 浮水印。

## 五、Agent 整合

### 1. Computer use：讓 agent 使用桌面應用程式
- 設定：`chat.agentHost.computerUse.enabled`
- Agent 可看見並控制電腦上的應用程式，處理發生在桌面應用程式（而非程式碼或終端機）中的任務。
- 適用：在你自己的 macOS 或 Windows 機器上執行的 Copilot harness session。
- 開啟方式：任務需要時 agent 會請你允許，或執行 `/computer on`；保持開啟直到執行 `/computer off`。

### 2. Canvases（預覽）
- 設定：`chat.canvases.enabled`
- Canvas 於 1.142 推出，是你與 agent 可共同檢視並更新同一成品的共用互動式介面；本版讓它更易尋找、管理與開啟。
- **在 Agent Customizations 編輯器中管理**：
  - **Canvases** 區段列出目前作用中 Copilot session 可用的 canvas，並依來源分組其 canvas 擴充功能。
  - 需開啟至少有一則訊息的 Copilot session，再從該處開啟 Agent Customizations 編輯器。
  - 在 **Browse** 下選取 **Canvases** 可找到中繼資料標示提供 canvas 的外掛；沒有該中繼資料的 canvas 外掛會出現在 **Plugins** 下。
- **從 Add Context 功能表開啟**：在編輯器或 Agents 視窗的聊天中選取 **Add Context (+)** > **Canvas...**，開啟或重新聚焦可用的 canvas。
- 這是在 **New Chat (+)** > **Canvas**（編輯器視窗）與 **Add Tab (+)** > **Canvas**（Agents 視窗）之外的新入口。

## 六、Agents

### 1. Assisted permissions 正式推出
- 背景：逐一核准工具呼叫很繁瑣；給予完全自主則可能造成非預期動作或安全問題。
- 機制：agent 對每個工具呼叫進行以 LLM 為基礎的風險評估，自動核准低風險呼叫；較高風險或無法判定風險的呼叫仍需使用者明確核准。
- 使用：在權限選擇器選取 **Assisted permissions**。
- 條件：已對 Copilot session 正式推出；需要 Folder isolation；可能受組織限制。

### 2. Session 撰寫器控制項（實驗性）
- 把開始新 session 的關鍵設定集中在頂端，並加入快速鍵。
- **先選擇環境**：
  - 在 Agents 視窗建立新 session 時，用環境選擇器從 **This Computer**、**Cloud**、符合資格的遠端主機或受支援的 Dev Container 中選擇。
  - 其他選項依環境而變，例如本機 session 可指定分支與 worktree 程式碼隔離選項。
  - 停用 `sessions.chat.experimental.environmentPicker` 可隱藏環境選擇器。
- **不需專案即可聊天**：
  - 設定：`sessions.chat.experimental.workspaceOptOut`
  - 將滑鼠停留（或鍵盤聚焦）在工作區選擇器上並選取 `X`，即可取消已選取的工作區，開始無工作區聊天。
  - 對進行中 session 取消時，提示詞與附件會保留；僅適用於支援無工作區聊天的 harness 與環境。
- **減少雜亂**：在 UI 控制項按右鍵選 **Collapse to Icon**，只顯示圖示；保留工具提示與無障礙名稱，選擇會在重新載入與 Settings Sync 間保留。
- **使用鍵盤**：在已聚焦的新 session 聊天輸入框，用 Ctrl+K Ctrl+E／Ctrl+K Ctrl+B／Ctrl+K Ctrl+T／Ctrl+K Ctrl+Y 存取控制項；收合的選項會視需要展開；Sync 快速鍵只移動焦點，按 Enter 才同步。

### 3. Copilot harness 作為預設
- Copilot harness 持續作為新 session 的預設；建構於 Copilot SDK，讓各 Copilot 產品的行為、功能與改進一致。
- Harness 選擇器顯示 **Copilot** 即表示使用 Copilot harness。
- Session 可在背景持續執行，並可從編輯器視窗與 Agents 視窗存取；透過 Agent Host 執行。
- **工作集檢閱檔案編輯（實驗性）**：
  - 設定：`chat.editor.workingSet.enabled`
  - Copilot harness 將透過 agent 工具所做的編輯記錄在工作集中，可像 Local harness 一樣決定保留或復原。
  - 編輯器內嵌 **Keep**／**Undo** 處理個別變更；聊天輸入框上方的工作集可管理檔案與所有待處理變更。
  - 編輯器視窗中預設啟用，但仍為實驗性；設為 `false` 改為顯示 Changes 膠囊按鈕。
  - 限制：透過終端機命令的變更不會出現在工作集；Agents 視窗中請用 **Changes** 檢視捨棄檔案。
- 本版包含更多依使用者回饋所做的改進，歡迎持續提交 issue；相關資源：Copilot harness 文件、agent host 架構部落格文章。

### 4. Copilot harness 中的 Copilot Memory
- Copilot harness session 可使用 Copilot Memory，即 Copilot CLI、Copilot cloud agent、Copilot code review 共用的雲端記憶服務。
- Session 開始時回想相關存放庫事實與你的偏好，工作中儲存新學到的內容，不必每段對話重複情境。
- 兩種範圍：
  - **存放庫事實**：與其他可存取該存放庫的人共享。
  - **使用者偏好**：套用於你所有的存放庫。
- 可直接請 agent 記住慣例或偏好，並在需要時說明範圍（範例：在所有存放庫中記住偏好簡潔的提交訊息主旨）。
- 預設啟用，遵循 GitHub 上的 Copilot Memory 設定與組織原則；可隨時在 GitHub 上檢閱與刪除記憶。

### 5. 管理 worktree 儲存空間（實驗性）
- 設定：`chat.agentSessions.sessionStorageCleanupSuggestion.enabled`
- 延續上一版推出的 worktree 清理，新增更多尋找方式：
  - **查看所有過去的 worktree**：預設選取 **Any time**，同時檢閱近期與較舊的 worktree。
  - **依工作區尋找**：每一列顯示工作區，可用工作區篩選條件縮小範圍；變更篩選會清除選取項目。
- 清理建議啟用且本機 worktree 所在磁碟可用空間少於 5 GB 時，Agents 視窗會在 session 清單下方建議執行清理（不論 worktree 存在時間或數量），並以 **Any time** 開啟清理。

### 6. 在 Agents 視窗中啟用擴充功能
- 擴充功能可直接在 Agents 視窗中執行與啟用／停用。
- 需將 `extensions.experimental.agentsWindowManagement` 設為 `true`。

## 七、Agent 自訂

### 1. Copilot connectors（預覽）
- 將 Slack 討論、Notion 專案情境、Microsoft Learn API 文件等帶入 agent session。
- Copilot connectors 是 GitHub 管理的 MCP 伺服器，不需在本機設定伺服器或進行 MCP 設定。
- 使用步驟：開啟 Browse → 來源功能表選 **Copilot Connectors** → 在服務上選 **Connect** → 在瀏覽器授權。
- 連接一次即可在以同一帳戶登入的受支援 Copilot 用戶端之間重複使用。
- 截圖所列服務：Port、Postman、Sentry、Slack、Statsig、Work IQ。
- 條件：所有 Copilot 方案預設啟用；僅適用於 Copilot harness；Business／Enterprise 需系統管理員啟用 **Editor preview features**；組織 MCP 限制會套用，部分服務需系統管理員核准。

### 2. 探索市集自訂項目（預覽）
- **Browse** 是 Customizations 的新首頁，集結 **GitHub Feed** 以及由你或企業設定之市集中的外掛，可加入 skill、工具與完整工作流程。
- 可探索 **Editor's picks**、**Plan, build, and ship**、**Connect your work**，或依來源、類型搜尋與篩選。
- 開啟方式：開啟 Browse 或執行 **Chat: Open Customizations**。
- 可從 README 或團隊指南連結到 Browse，並附帶搜尋條件（例如篩選為 MCP 伺服器）。
- 限制：GitHub Feed 需受支援的 harness，Local session 無法使用；Copilot Business／Enterprise 需系統管理員啟用 **Editor preview features**。

### 3. GitHub Copilot 自訂 agent 的更豐富編輯體驗
- 為 GitHub Copilot harness 自訂 agent 時，提供自動完成、滑鼠停留提示與驗證：
  - **`model`**：提供 Copilot 模型 ID，可為單一值或依偏好排序的清單。
  - **`tools`**：提供 Copilot 工具別名（`read`、`edit`、`execute` 等）及限定名稱的用戶端與擴充功能工具。
  - **`skills`**：提供可用 skill，附描述與來源資訊。
  - **設定驗證**：Copilot 專屬屬性與巢狀結構（含 hooks 與 agent 範圍的 MCP 伺服器）皆支援；未知的模型、工具、skill 只在探索完成後才標示，避免載入中誤判。
  - **內文功能**：辨識預留位置並顯示提示；標示未知的預留位置，以及僅限 Local 的 `#tool:` 與 `#file:` 參照。

### 4. 自訂 agent 編輯的 harness 感知預設值
- `.agent.md` 沒有 `target` 屬性時，編輯器依目前作用中的自訂 harness 提供自動完成、滑鼠停留提示與診斷。
- 切換 harness 會即時重新整理，不需重新開啟檔案；明確的 `target: vscode` 或 `target: github-copilot` 仍會覆寫預設。

### 5. 分享外掛與自訂項目的連結
- 可在 README 或團隊指南分享深層連結：
  - 新增市集：`vscode://chat-plugin/add-marketplace?ref=owner/repo`
  - 新增市集並安裝指定外掛：`vscode://chat-plugin/install?source=owner/repo&plugin=plugin-name`
  - 以搜尋篩選開啟 Plugins 頁面：`vscode://chat-customizations/open?page=plugins&search=github`
- 新增市集或安裝外掛前 VS Code 會要求確認；動作使用 Copilot harness session，若無可用 session 會先詢問再建立。
- 安全提醒：外掛可在你的機器上執行程式碼，只在信任來源時繼續。
- 可用於外掛 README 的 **Install in VS Code** 按鈕（如 Session timeline 外掛）。
- 支援的頁面還有 `agents`、`skills`、`instructions`、`hooks`、`mcp-servers`、`tools`、`migrations`；省略 `search` 則不帶篩選；用 `vscode-insiders://` 開啟 Insiders。

### 6. 使用斜線命令管理 Copilot 自訂項目
- 在 Copilot harness session 的 Chat 檢視中，輸入 `/plugin`、`/mcp`、`/skills` 加空格查看子命令。
  - **外掛**：列出、安裝、更新、啟用、停用、解除安裝；`/plugin marketplace` 管理市集，`/plugin install` 選擇要安裝的外掛。
  - **MCP 伺服器**：`/mcp show`、`/mcp enable`、`/mcp disable` 加伺服器名稱。
  - **Skills**：`/skills info` 加 skill 名稱。
- 自動完成會建議子命令與相關名稱；可用命令取決於 Copilot 執行階段，結果直接顯示在聊天中。
- 原文附影片示範以 `/plugin install` 從 `vscode-team-kit` 市集安裝 Session timeline 外掛。

## 八、Session 管理

### 1. 在 session 之間移動聊天（預覽）
- 設定：`chat.agentHost.moveChats.enabled`（Stable 需啟用；Insiders 預設開啟）
- 在 Agents 視窗中重新安排對話，不必重新開始或遺失歷程：
  - 拖曳巢狀聊天到另一個 session，或放在其巢狀聊天之間指定位置。
  - 右鍵 **Promote to Session** 讓巢狀聊天獨立成 session，或拖曳到 session 清單空白處。
  - 將單一聊天的 session 拖曳到另一個 session 上，使其成為巢狀。
  - 拖曳或使用 **Move Up**／**Move Down** 重新排序；焦點在 session 清單時可用 Shift+Alt+Up／Shift+Alt+Down。
- 規則與限制：
  - 移動會保留聊天的工作資料夾（既有 worktree 或無工作區聊天的暫存資料夾）；共用 worktree 在其他 session 仍使用時保持可用。
  - 需相同的 agent 與供應者，且目的地必須支援多個聊天。
  - Subagent 對話隨父聊天一起移動，不可單獨移動。
- Session 清單顯示移動進度，移動後提供 **Undo**。

### 2. 為巢狀 session 選擇工作區
- 以往巢狀 session 繼承父 session 工作區；現在可為每個巢狀 session 選擇不同工作區，例如前端與後端聊天在不同資料夾工作，仍保留在同一個 session。
- 選取 **New Nested Session** 開啟附資料夾選擇器的撰寫器（預設為父 session 資料夾）：可選最近使用資料夾、瀏覽其他資料夾，或選 **No Workspace** 使用自己的暫存資料夾。
- Git 存放庫可選 **New Worktree** 與分支，隔離巢狀聊天的檔案變更。
- 巢狀聊天沿用父 session 的 agent 與 host；不支援多工作目錄的 agent 只提供父 session 的資料夾。

### 3. 快速聊天中的巢狀 session
- Agents 視窗的快速聊天支援巢狀 session：在快速聊天選 **+**，或從內容功能表選 **New Nested Session**。
- 用途：後續追問時不混雜不同問題，例如在同一快速聊天下分別探索兩種做法，不需開啟專案資料夾。
- 每個巢狀 session 預設 **No Workspace**，擁有與父快速聊天分開的暫存資料夾；快速聊天保留在 **Chats** 區段。

### 4. Session 群組的自訂圖示與顏色
- 工作區群組、環境群組（含遠端主機）與自訂群組可設定自訂圖示與佈景主題感知的顏色。
- 在群組內容功能表選 **Change Icon...** 或 **Change Color...**；選擇在重新載入與 host 重新連線間保留；**Reset to default** 可分別還原圖示或顏色。

## 九、聊天

### 1. 具備 session 情境的語音對話（實驗性）
- 設定：`agents.voice.enabled`（可由組織原則設定）、`agents.voice.useBYOKVoiceModel`、`agents.voice.sessionAwareness`
- 語音模式讓你在程式設計 agent 工作時口語討論任務；用自己的 API 金鑰搭配 OpenAI 即時模型，可問「我們進行到哪裡？」「哪個 session 需要輸入？」而不啟動程式設計請求。
- `agents.voice.sessionAwareness`（預設啟用）會與 OpenAI BYOK 語音模式分享有範圍限制的簡報：session 標題、回應摘要、待處理提示詞詳細資料、所選模型、附件名稱；不含附件內容。
- 動畫改用單一顏色，營造對話感，可隨時插話。
- GPT Live 對話處理更可預期：
  - Agent 工作時可提問並聽取回答，其他更新排入佇列之後朗讀。
  - 單一問題表單朗讀完整問題；多問題表單一次收集一個編號答案。
  - 工作進行中的新口語程式設計指示以引導（steering）送出，在供應者支援的下一個時機套用，不保證立即中斷；工作期間的純語音交流不保留給之後的請求。

### 2. 在地化語音核准與更清楚的連線狀態（實驗性）
- 設定：`agents.voice.language`
- 以所選語音語言核准或拒絕 GPT Live 工具請求，支援 25 種語言，英文為後援。
- 可用顯示的選項標籤、數字，或在允許時以自由文字回答；模稜兩可的核准仍需明確回答或使用聊天控制項。
- 限制：不會翻譯 agent 提供的問題或選項；「skip」「other」等命令僅限英文。

## 十一、終端機

### Windows 上終端機命令的對話方塊顯示在 VS Code 前方
- 設定：`terminal.integrated.windowsReparentConsoleWindow`
- 問題：部分命令列工具的對話方塊會開在 VS Code 後方，例如 Azure PowerShell `Connect-AzAccount` 的登入選擇器，讓命令看似卡住。
- 解法：比照 Windows Terminal，讓顯示本機終端機的視窗成為該終端機隱藏主控台視窗的擁有者，對話方塊因此開在該 VS Code 視窗前方。
- 條件：需要 `terminal.integrated.windowsUseConptyDll`（預設啟用）；將 `terminal.integrated.windowsReparentConsoleWindow` 設為 `false` 可關閉。

- Assisted 與 Allow All 受組織限制時，保持可見但呈停用並附說明，不再直接消失。

- 組織設定載入緩慢時，進度以內嵌方式顯示在等待中的聊天，不再堆疊通知；背景載入不打斷使用者。

## 十四、擴充功能撰寫

### 使用 OIDC 與 Trusted Publishing 發布擴充功能
- 可從 GitHub Actions 發布到 Visual Studio Marketplace，不必將 PAT 存為存放庫祕密。
- `vsce publish --oidc` 向 GitHub Actions 要求短期 OIDC 權杖，交換為最長 15 分鐘有效的暫時 Marketplace 認證；交換失敗時不會退回使用 PAT。
- 設定步驟：
  1. 在 Marketplace 發行者管理頁面為存放庫與工作流程建立 Trusted Publishing 原則。
  2. 授予發布作業 `id-token: write` 權限。
  3. 在工作流程執行 `vsce publish --oidc`。
  4. 使用支援 OIDC 的 `@vscode/vsce`（如 `4.0.2` 或更新版本）。
- 限制：Trusted Publishing 目前僅支援 GitHub Actions；Azure Pipelines 請繼續透過服務連線使用 Microsoft Entra ID。
- Azure DevOps 全域 PAT 將於 2026 年 12 月 1 日淘汰，建議移轉到上述安全方法。
