# Visual Studio Code 1.142 重點摘要

- 版本：1.142.0（Stable）
- 發行日期：2026 年 10 月 14 日
- 原文連結：https://code.visualstudio.com/updates/v1_142

---

## 一、版本亮點

本版新增供 agent 工作流程使用的共用 canvas、可在不遺失脈絡下移動聊天、擴充 Markdown 編輯器，並讓系統管理員對 agent 權限擁有更多控制。五項亮點：

- **Canvases（預覽）**：以視覺化、可互動的 canvas 在聊天之外與 agent 協作。
- **移動聊天**：在另一個資料夾或新的 Git worktree 延續聊天，不遺失對話歷程。
- **Markdown 編輯器**：貼上圖片、重新命名檔案連結、階層連結導覽等。
- **企業管理**：強制執行 agent 沙箱與權限原則，並控制開發人員可用的權限模式。
- **重新設計的模型選擇器**：快速切換 Copilot 與 BYOK 模型，更直覺地管理投入程度與上下文視窗。

## 二、Agents

### 1. Copilot harness
- 由 Copilot SDK 驅動；Copilot SDK 是各 Copilot 產品共用的基礎，讓行為、功能與改進保持一致。
- 在 VS Code 中透過 Agent Host 執行 session，session 可在背景持續進行，並可同時從編輯器視窗與 Agents 視窗存取。
- 先前已可從聊天輸入框的 harness 選擇器選用；基於大量正面回饋，**正逐步推出為新 session 的預設 harness**。harness 選擇器顯示 **Copilot** 即代表使用 Copilot harness。
- 依回饋在 Copilot harness 中**重新加入 Ask 內建 agent**，提供專屬的唯讀體驗；從 agent 選擇器選取 **Ask** 使用。
- 相關資源：Copilot harness 使用文件、agent host 架構部落格文章；回饋可提交 GitHub issue。

### 2. Canvases（預覽）
- 設定：`chat.canvases.enabled`
- Canvas 是與 agent 協作的互動式介面，開在聊天旁；你與 agent 檢視並更新同一個成品，不必只靠提示詞協調。
- 範例：Kanban canvas 規劃與追蹤實作工作——你可直接建立、移動卡片；agent 可把功能拆成任務、更新狀態、加入新發現的工作。
- 可用位置：VS Code 編輯器視窗與 Agents 視窗；GitHub Copilot app 也支援 canvas 擴充功能。
- 適用條件：VS Code 桌面應用程式中、使用 Copilot harness 的本機 session（預覽）。啟用設定後，以 Copilot harness 開始新 session。
- 每個 canvas 由 canvas 擴充功能提供，兩種開始方式：
  - **建立 canvas 擴充功能**：在聊天輸入 `/create-canvas` 並描述想要的 UI，技能會在工作區建立 canvas 擴充功能並開啟 canvas。
  - **安裝聊天外掛**：目前需透過 GitHub Copilot app 安裝含 canvas 擴充功能的聊天外掛，再切回 VS Code 請 agent 列出並開啟可用 canvas。
- 安裝後也可在 Agents 視窗用 **Add Tab (+)** > **Canvas** 開啟。
- 可探索並安裝社群提供的範例 canvas 擴充功能（awesome-copilot）。

### 3. 在資料夾與 worktree 之間移動聊天
- 先前：在某資料夾調查任務後，若要改在 Git worktree 實作或換到別的儲存庫，必須開新聊天並重建脈絡。
- 現在：在 Agents 視窗請 agent 將目前聊天移到另一個資料夾或新的 Git worktree，**對話歷程完整保留**；已有工作區的聊天也可變更工作區，agent 可把工作隔離到新 worktree。
- 用法：以自然語言提示，例如「Continue this task in a new Git worktree of the current repository before implementing it.」
- 流程：agent 完成目前這一輪 → 移動聊天 → 工作區變更時顯示通知 → 在新位置自動繼續任務。編輯與命令在新位置執行，原本的 checkout 不變。
- 限制：僅適用於使用 **Codex harness** 或 **Interactive 模式下的 Codex**，且只含**一個聊天與一個本機資料夾**的 agent session。前提條件與新位置可用檔案詳見「Move a chat to another folder or worktree」文件。

### 4. Agents 視窗中以 session 為範圍的版面配置（實驗性）
- 設定：`sessions.experimental.layoutScope`（僅限 Agents 視窗），變更後需重新載入視窗。
- 背景：先前切換 session 時，編輯器可見度、詳細資訊、面板可見度等版面設定在各 session 間共用，對習慣「每個工作區記住版面」的使用者可能造成干擾。
- 可選值：
  - `session-shared`（預設，現行行為）：session 與其巢狀 session 共用相同編輯器與選取的面板檢視；編輯器、詳細資訊、底部面板可見度在現有工作區 session 間共用。
  - `chat-shared`：session 與每個巢狀 session 各自保有編輯器與選取的面板檢視；編輯器、詳細資訊、底部面板可見度仍共用。
  - `chat`：session 與每個巢狀 session 也各自保有編輯器與詳細資訊組合，以及底部面板可見度。
- 視窗幾何尺寸、窗格大小與側邊欄目前仍在整個視窗共用。

### 5. 自訂 Agents 視窗的面板版面配置
- 操作：在面板分頁按右鍵 → **Align Panel** → 選擇版面。
  - `Center`：面板對齊在聊天區域下方，為側邊窗格保留更多空間。
  - `Justify`：面板延伸至整個視窗寬度。
- 選擇依設定檔（profile）儲存，最大化或還原面板時保留。

## 三、聊天

### 1. 快速辨識作用中的 harness
- 聊天標題會顯示作用中 harness 名稱（如 **Copilot**、**Codex**），不必開啟 harness 選擇器或在 session 清單上停留滑鼠。

### 2. 停止背景 shell
- 在 Copilot harness session 中，聊天輸入框上方的 **Background Shells** 標籤列出 agent 仍在背景執行的命令。
- 不需要的命令（例如想重跑的測試、跑太久的命令）可直接停止：選取 **Background Shells** → 選取 shell 開啟詳細資訊 → 選取命令旁的 **Stop Shell**。只會結束該命令，shell 從清單移除。
- 無障礙：可用鍵盤操作 **Stop Shell**，螢幕閱讀器會在 shell 停止時通知。
- 限制：僅適用於**附加的 shell**（agent 在目前請求中執行者）；**分離的 shell** 獨立於 agent 執行，無法從此介面停止。
- 其他改進：詳細資訊在命令上方顯示 shell 完整描述（即使清單中被截斷）；長輸出不再截斷，可在 shell 詳細資訊與聊天回應的終端機輸出中向上捲動查看較早輸出。

### 3. BYOK 自訂端點的具狀態回應
- 若 BYOK 模型使用無狀態的 Responses API，在 `chatLanguageModels.json` 該模型項目設定 `"statefulResponses": false`，每次請求會傳送完整對話歷程。
- 詳見「Custom Endpoint configuration」文件。

### 4. 不再支援 Local harness 的 Windows 沙箱（棄用）
- Local agent session 中終端機命令的 Windows 沙箱已棄用。
- 在 Windows 上需要沙箱執行命令時，改用 Agent Host session；詳見 Agent Host 沙箱文件。

### 5. 重新設計的模型選擇器
- 目的：Copilot 與 BYOK 提供者有許多各擅勝場的模型，新選擇器讓你隨工作變化更容易選擇與切換模型。
- 以**分頁式介面**區分 Copilot 與 BYOK 模型；清單中所選模型會顯示其思考層級與上下文大小。
- 滑鼠停在清單中的模型上時，可進一步設定**思考層級（thinking level）**與**上下文視窗大小**。

## 四、Markdown 編輯器

- **更貼近原始碼的編輯模式**：編輯時每一行原始碼顯示在獨立的視覺行上，結構更易掌握；唯讀模式仍照舊轉譯 Markdown。
- **貼上圖片**：可直接將圖片（如螢幕擷取畫面）貼進 Markdown 編輯器（與文字編輯器既有行為相同），不必手動儲存再插入檔案。
- **重新命名檔案連結**：支援 **Rename Symbol**（F2），就地重新命名檔案連結並反映到整份文件。
- **大綱與階層連結**：整合 Outline 檢視與 breadcrumbs，方便檢視標題結構並跳至段落。
- **複製程式碼區塊**：如同 Markdown 預覽，滑鼠停在程式碼區塊上會顯示複製按鈕，可複製多行片段而不會誤改內容。

## 六、語言：Python

Python Environments 擴充功能在環境探索、直譯器選擇與終端機啟用方面的修正：

- **環境探索**：`uv` 管理的 Python 安裝顯示在 **Global** 下；依路徑選取直譯器會把其虛擬環境加入清單；在 VS Code 外刪除虛擬環境時會更新選取。
- **專案專屬環境**：自動選取優先使用專案本身的虛擬環境（而非巢狀環境）；Conda 環境選取與 Poetry 套件操作遵守專案範圍；背景重新整理不再覆寫較新的直譯器選取。
- **直譯器設定**：修正 `python.defaultInterpreterPath` 中 `${workspaceFolder}`、相對路徑與 `python3` 等命令的解析；專案檢視的環境選取器新增 **Enter Interpreter Path**。
- **終端機啟用**：全域直譯器變更時，shell 啟動時的啟用會更新，環境檔案變更時予以保留；環境檔案通知提供 **Enable for Workspace** 或 **Enable for Folder** 動作。
- **Python 安裝**：需要 `uv` 但未安裝時，設定流程會提議安裝，並在不需重新整理 PATH 的情況下繼續選擇 Python 版本。

## 七、企業

### 1. 自動將受原則管理的聊天移至 Copilot Agent Host
- 觸發條件：組織設定了**非空的 `permissions` 物件**，或 **`sandbox.enabled` 為 `true`**。此時完整聊天 session 必須使用 Agent Host 中的 Copilot harness，以強制執行原則。
- 開啟現有、未封存的 **Local** 聊天時，自動移至 **Copilot**，保留對話記錄與未送出的草稿（含附件）；不會自動送出任何內容；新聊天在目前組織原則下使用一般的模型與權限預設值。
- 只有新聊天成功開啟後才封存原始聊天；移動中切換離開時，原始聊天不變、未開啟的目的地會被移除。
- 原則生效期間：Claude、Codex 與終端機聊天無法使用；編輯器內嵌聊天仍可用於有限的讀取與編輯任務。
- 不會觸發遷移的情況：單獨的空 `permissions` 物件或舊版原則。
- 系統管理員可暫時選擇退出自動遷移（見下一項）。

### 2. 暫時保留 Local harness
- 在統一受管理設定中設定：
  ```json
  {
    "vscode": {
      "temporaryDefaultToLocalHarness": true
    }
  }
  ```
- 效果：**Local** harness 保持可用、停止自動切換到 **Copilot**，並保留明確指定、已記住與目前的 harness 選擇。
- 恢復：將受管理值設為 `false` 或移除。
- 注意：此退出也會覆寫受管理沙箱與權限設定所要求的路由；Local 不會強制執行這些僅限執行階段的規則；Copilot Agent Host session 中的強制執行不變。

### 3. 個別管理 Copilot 權限模式
- 系統管理員可允許 **Assisted** 同時封鎖 **Allow All**，讓開發人員獲得輔助核准而不略過權限檢查；Copilot 權限選擇器會反映組織允許的模式。
- 範例設定（合併到統一受管理設定）：
  ```json
  {
    "permissions": {
      "disableBypassPermissionsMode": "disable",
      "disableAssistedPermissionsMode": false
    }
  }
  ```
  套用後權限選擇器只有 Manual 與 Assisted，沒有 Allow All。
- `permissions.disableAssistedPermissionsMode`：個別限制 **Assisted**。
- `permissions.defaultMode`：只提供起始預設值，不限制使用者可選的模式。
- 舊版 `ChatToolsAutoApprove: false` 仍會同時封鎖 **Allow All** 與 **Assisted**，除非設定明確的受管理模式限制；只設 `permissions.defaultMode` 不會取代此舊版限制。
- 相容性注意：Assisted Permissions 目前與 `permissions.{allow,ask,deny}` 不相容；若有使用 `permissions.allow`／`ask`／`deny`，請設 `"disableAssistedPermissionsMode": true`。下一版將同時支援兩者。

### 4. Windows 數值原則支援 DWORD 值
- Windows 上接受數值的原則支援 DWORD 與 QWORD。
