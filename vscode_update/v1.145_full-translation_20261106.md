## [版本亮點](https://code.visualstudio.com/updates/v1_145#_release-highlights)

本週，你的遠端 agent session 用起來更像在本機一樣。直接在 VS Code 中預覽應用程式並使用 canvas，用 cron 微調自動化排程，並降低聊天中的雜訊。當你需要休息一下時，Blobby 已經準備好陪你玩。

- [遠端 agent](https://code.visualstudio.com/updates/v1_145#_remote-agents)：不必離開 Agents 視窗，就能從遠端 agent session 預覽應用程式並使用互動式 canvas。
- [自動化](https://code.visualstudio.com/updates/v1_145#_cron-schedules-and-custom-agents-for-local-automations)：使用 cron，以內建預設以外的自訂排程執行週期性 agent 任務。
- [Agent 詳細程度](https://code.visualstudio.com/updates/v1_145#_choose-agent-verbosity)：讓聊天保持簡潔，或查看 agent 推理與工具呼叫的完整細節，由你選擇。
- [檔案排除](https://code.visualstudio.com/updates/v1_145#_show-specific-files-in-excluded-folders)：排除資料夾的同時，讓你需要的檔案保持可見且可搜尋。
- [趣味](https://code.visualstudio.com/updates/v1_145#_blobby-jump-game-experimental)：玩一款由 VS Code 寵物 Blobby 主演的平台跳躍遊戲，稍作休息。

已經安裝了嗎？在 VS Code 中使用 **Check for Updates**。若想搶先體驗即將推出的功能，請使用 [Insiders 組建](https://code.visualstudio.com/insiders)。

## [遠端 agent](https://code.visualstudio.com/updates/v1_145#_remote-agents)

### [透過遠端 agent host 連線瀏覽（預覽）](https://code.visualstudio.com/updates/v1_145#_browse-over-remote-agent-host-connections-preview)

**設定**：`workbench.browser.enableRemoteProxy`

當 agent session 在[遠端 agent host](https://code.visualstudio.com/docs/agents/run/remote-agent-sessions) 上執行時，Agents 視窗中的整合式瀏覽器現在會透過該主機載入頁面，就像它在[遠端工作區](https://code.visualstudio.com/updates/v1_125#_browse-over-remote-connections-preview)中已經做到的一樣。當 agent 在遠端機器上啟動開發伺服器時，你可以直接在 Agents 視窗中開啟它來預覽應用程式、驗證 agent 的變更並提供回饋，就像在本機 session 中一樣。

![圖：整合式瀏覽器的網址列，顯示「Connected via kyles-mbp」。](https://code.visualstudio.com/assets/updates/1_145/remote-browser.webp)

啟用 `workbench.browser.enableRemoteProxy` 來試用，並在 [VS Code 存放庫](https://github.com/microsoft/vscode/issues)中回報你遇到的任何問題。

### [遠端 canvas（預覽）](https://code.visualstudio.com/updates/v1_145#_remote-canvases-preview)

**設定**：`workbench.browser.enableRemoteProxy`、`chat.canvases.enabled`（此設定可由組織原則設定）

由於支援遠端 agent host 連線，你現在也可以使用託管在遠端 agent host 上的 [canvas](https://code.visualstudio.com/docs/agents/run/canvases)。

啟用 `chat.canvases.enabled` 與 `workbench.browser.enableRemoteProxy` 來試用，並在 [VS Code 存放庫](https://github.com/microsoft/vscode/issues)中回報你遇到的任何問題。

## [Agents](https://code.visualstudio.com/updates/v1_145#_agents)

### [在同一個 session 中混搭 agent harness（預覽）](https://code.visualstudio.com/updates/v1_145#_mix-and-match-agent-harnesses-in-one-session-preview)

**設定**：`chat.agentHost.multipleChatProviders.enabled`

[巢狀 session](https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions#_run-multiple-chats-in-a-session) 讓你在單一主聊天 session 中把相關的對話放在一起。過去，每個巢狀 session 都會沿用其父 session 的 harness。如果你想聽聽另一個 agent 的意見，就必須另開一個 session，並失去這種分組。

在本版中，巢狀 session 可以使用與其父 session 不同的 harness。例如，請 Claude 檢閱 Copilot 聊天所寫的計畫，或在同一個 session 中並排把相同任務交給 Codex。建立新的巢狀 session 時，使用 harness 選擇器切換到不同的 harness。

每個聊天都有自己的模型、agent 與權限層級，依其 harness 而定。在一個聊天中變更這些設定，不會影響其他聊天。當你移動聊天時，它會保留歷程記錄，並以其所選的 harness 繼續。當你分支（fork）巢狀 session 時，它會以相同的組態繼續。

當某個聊天使用的 harness 與其 session 不同時，將滑鼠停留在它的聊天索引標籤或 session 清單中的對應列上，就會顯示它的 harness 名稱。

啟用 `chat.agentHost.multipleChatProviders.enabled` 即可開始使用。歡迎透過[提交 issue](https://github.com/microsoft/vscode/issues) 告訴我們你的想法。

### [本機自動化的 Cron 排程與自訂 agent](https://code.visualstudio.com/updates/v1_145#_cron-schedules-and-custom-agents-for-local-automations)

與其逐一手動執行 agent 任務，你可以使用[自動化](https://code.visualstudio.com/docs/agents/run/automations)來排程並自動執行它們，可以隨選執行，也可以依設定的排程執行。

本版讓本機自動化更有彈性，並讓 Automations 檢視專注於進行中的工作：

- **使用 cron 排程**：當其他排程預設不夠精確時，選取 **Cron** 來輸入五個欄位的 cron 運算式。對話方塊會驗證運算式，並描述產生的排程。雲端自動化無法使用 cron 排程。
- **使用工作區自訂 agent**：建立或編輯本機自動化時，可從所選工作區中選擇自訂 agent。
- **專注於進行中的自動化**：已停用的自動化會出現在收合的 **Disabled automations** 區段中，因此不會遮蔽執行歷程與進行中的自動化。

![圖：本機自動化的 Cron 排程編輯器。](https://code.visualstudio.com/assets/updates/1_145/cron-automations.webp)

深入了解[建立與管理 agent 自動化](https://code.visualstudio.com/docs/agents/run/automations)。

### [將 canvas 釘選到側邊欄（實驗性）](https://code.visualstudio.com/updates/v1_145#_pin-canvases-to-sidebar-experimental)

**設定**：`chat.canvases.enabled`（此設定可由組織原則設定）

為了更容易存取常用的 canvas，你現在可以將 canvas 釘選在左側側邊欄。要釘選 canvas，請開啟它並選取 canvas 上方的 **Add to Sidebar** 按鈕。即使你離開該 canvas，已釘選的 canvas 仍可在側邊欄中存取。

### [Copilot harness](https://code.visualstudio.com/updates/v1_145#_copilot-harness)

Copilot harness 持續作為 VS Code 中新 session 的預設。它是我們最新的 harness，建構於 Copilot SDK 之上；Copilot SDK 是一個共用基礎，有助於讓各個 Copilot 產品的行為、功能與改進保持一致。

當你開始新 session 時，harness 選擇器中的 **Copilot** 表示該 session 使用 Copilot harness。在 VS Code 中，你可以讓 Copilot harness session 在背景持續執行，並同時從 VS Code 編輯器視窗與 Agents 視窗存取它們。這些 session 透過 [Agent Host](https://code.visualstudio.com/docs/agents/concepts/agent-host) 執行。

為了協助你在既有工作流程中採用 Copilot harness，我們新增了一份[從 Local 轉換到 Copilot harness 的指南](https://code.visualstudio.com/docs/agents/run/move-to-copilot)。內容涵蓋自訂項目相容性、session 延續性，以及組織推行與驗證。

感謝持續形塑這些改進的回饋。請繼續就你的使用體驗[提交 issue](https://github.com/microsoft/vscode/issues)，特別是當某個工作流程或整合讓你的組織無法離開 Local harness 時。

了解如何[使用 Copilot harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses)，或在 [agent host 部落格文章](https://code.visualstudio.com/blogs/2026/08/26/agent-host-architecture)中探索其架構與工作流程。

### [工作集改進（實驗性）](https://code.visualstudio.com/updates/v1_145#_working-set-improvements-experimental)

**設定**：`chat.editor.workingSet.enabled`

上一版，我們為 Copilot harness session 推出了工作集（working set），讓你檢閱待處理的 agent 編輯。你可以**保留（keep）**或**復原（undo）**變更，就像在 Local harness 中一樣。

![圖：Copilot harness session 中的工作集。](https://code.visualstudio.com/assets/updates/1_145/working-set.webp)

我們持續改進 Copilot harness session 中的工作集體驗：

- WSL、Dev Containers 與 SSH 工作區中的檔案，從工作集開啟時會在正確的主機上開啟。
- 當多個工具呼叫平行編輯同一個檔案時，工作集會追蹤這些編輯，而且編輯完成後，編輯器的內嵌檢閱控制項仍可使用。

工作集功能在編輯器視窗中仍為預設啟用。深入了解[使用工作集檢閱 agent 編輯](https://code.visualstudio.com/docs/agents/run/review-code-edits#_review-pending-edits-with-the-working-set)，包括它會追蹤哪些編輯。

### [無法使用必要沙箱時提供更好的指引](https://code.visualstudio.com/updates/v1_145#_improved-guidance-when-required-sandboxing-is-unavailable)

[Agent 沙箱](https://code.visualstudio.com/docs/agents/run/agent-sandboxing)會限制終端機命令可存取的內容，例如檔案系統與網路資源。你的組織可以透過不允許略過沙箱的受管理設定來強制要求使用沙箱。

如果你的組織要求使用沙箱，但你的機器無法執行沙箱，警告橫幅會說明終端機命令為何被封鎖，以及如何解決問題。它會顯示具體原因（例如缺少相依性），並連結到疑難排解步驟。

如果你的帳戶與組織支援[雲端 session（實驗性）](https://code.visualstudio.com/docs/agents/run/cloud-agent-sessions)，可以考慮改在雲端而不是在你的機器上執行 agent 工具。

## [聊天](https://code.visualstudio.com/updates/v1_145#_chat)

### [選擇 agent 詳細程度（實驗性）](https://code.visualstudio.com/updates/v1_145#_choose-agent-verbosity-experimental)

**設定**：`chat.persistentProgressVerbosity`

讓長聊天保持易讀，或在需要了解 agent 的行動時，詳細追蹤它的推理與工具呼叫。開啟 Chat 檢視的 **More Actions** 功能表並選取 **View Mode**：

- **Conversation**：專注於對話。推理與工具呼叫會分組成收合的區段，置於回應文字區塊之間。展開區段即可檢查其細節。
- **Verbose**：以工具呼叫展開的方式追蹤每個步驟，工具群組沒有內部捲動限制。
- **Compact**（預設）：工具呼叫執行時可預覽，完成後的群組會收合為可展開的摘要列。

你可以在不開新聊天的情況下切換模式。這些模式改變的是對話的顯示方式，而不是其情境或 agent 執行的工作。

啟用持續進度（persistent progress）後，當你往回捲動瀏覽某個回應時，作用中的進度指示器會停留在聊天輸入框上方。如果你偏好改用動畫輸入框邊框，請啟用 `chat.progressBorder.enabled`。

### [聊天效能改進](https://code.visualstudio.com/updates/v1_145#_chat-performance-improvements)

更流暢地重新開啟與瀏覽較長的 Copilot harness 聊天。VS Code 會重複使用既有的推理標題，並在你顯示終端機輸出時才轉譯它。還原的工具呼叫中的終端機輸出，會在你展開或顯示時才轉譯，而不是一次全部轉譯。

本版也減少了在還原與瀏覽長對話時，重複的進度更新與版面配置測量。

### [內嵌聊天附件（實驗性）](https://code.visualstudio.com/updates/v1_145#_inline-chat-attachments-experimental)

**設定**：`chat.inlineAttachments.enabled`

讓檔案參考與其他情境緊鄰它們所屬的指示。啟用此設定後，附件膠囊（pill）會插入在提示詞中的游標位置，而不是放在輸入框上方獨立的一列。

附件膠囊可以像單一字元一樣被游標移動經過、選取或刪除。先前的訊息會保留內嵌的膠囊，讓參考與周圍的指示待在一起。

內嵌附件在 Insiders 中預設開啟，在 Stable 中預設關閉。

![圖：聊天輸入框中，檔案與圖片附件膠囊與周圍文字內嵌並列。](https://code.visualstudio.com/assets/updates/1_145/chat-inline-attachments.webp)

### [從電腦上任何位置附加檔案](https://code.visualstudio.com/updates/v1_145#_attach-files-from-anywhere-on-your-computer)

過去，若要把工作區外的檔案（例如桌面上的螢幕擷圖或 mockup）提供給聊天，你必須從檔案管理員把它拖曳進來，或請 agent 去找。現在選取 **Add Context**（`+`）> **Files**，即可用標準檔案對話方塊選擇一或多個檔案，即使在沒有工作區的新聊天中也可以。在雲端 session 中，選擇器只會列出圖片。

![圖：聊天中的 Add Context 功能表，Files 項目位於 Image from Clipboard 與 Screenshot Window 上方。](https://code.visualstudio.com/assets/updates/1_145/chat-attach-files-menu.webp)

在 Copilot harness session 中啟用[沙箱](https://code.visualstudio.com/docs/agents/run/agent-sandboxing)時，agent 可以讀取你附加的檔案與資料夾，即使它們位於工作區之外。每個附加的路徑在 session 剩餘期間都可讀取，但 agent 無法寫入，而且此存取權不會儲存到你的設定中。使用 Manual 權限時，agent 讀取附加的檔案前不再詢問。如果你組織的受管理設定定義了自己的可讀取路徑清單，附件不會被加入該清單。

## [MCP](https://code.visualstudio.com/updates/v1_145#_mcp)

### [支援 MCP app 提供的工具](https://code.visualstudio.com/updates/v1_145#_support-for-tools-provided-by-mcp-apps)

MCP app 是由 MCP 伺服器提供的互動式介面。它們現在可以註冊工具，讓語言模型在下一次請求中呼叫。

例如，[ShaderToy 伺服器](https://github.com/modelcontextprotocol/ext-apps/tree/main/examples/shadertoy-server)讓模型可以即時反覆調整著色器（shader）。

### [受管理 MCP 允許清單的優先順序](https://code.visualstudio.com/updates/v1_145#_managed-mcp-allowlist-precedence)

對於由 VS Code 啟動的 MCP 伺服器，企業管理的 `allowedMcpServers` 清單優先於「僅限登錄」（registry-only）存取，因此你的組織可以核准伺服器，而不必將它們發布到組織的登錄中。設定細節與限制請參閱[企業章節中關於受管理 MCP 允許清單的說明](https://code.visualstudio.com/updates/v1_145#_managed-mcp-allowlists-take-precedence-over-registry-only-access)。

## [編輯器體驗](https://code.visualstudio.com/updates/v1_145#_editor-experience)

### [在已排除的資料夾中顯示特定檔案](https://code.visualstudio.com/updates/v1_145#_show-specific-files-in-excluded-folders)

**設定**：`files.exclude`、`search.exclude`

你可以使用 `files.exclude` 與 `search.exclude` 設定，篩選 Explorer、Search 與 Quick Open 中顯示的檔案與資料夾。

若要讓已排除資料夾的一部分保持可見，請在 `files.exclude` 中的樣式前加上 `!` 前綴。符合的檔案與資料夾會顯示在 Explorer、Search 與 Quick Open 中，即使另一個樣式或 `.gitignore` 排除了它們。`search.exclude` 中的例外只套用於 Search 與 Quick Open。

```json
"files.exclude": {
    "node_modules": true,
    "!node_modules/@types": true
}
```

例外永遠不會隱藏檔案。像 `!**/node_modules/@types` 這類樣式會在任何深度進行比對，但可能讓搜尋變慢。

### [Mermaid 圖表中的智慧子圖標題](https://code.visualstudio.com/updates/v1_145#_smart-subgraph-titles-in-mermaid-diagrams)

[Mermaid 圖表](https://code.visualstudio.com/docs/languages/markdown#_mermaid-diagram-rendering)中的邊（edge）不再遮蓋子圖（subgraph）標題。當邊會穿過標題時，標題會移到側邊。使用預設的 `vscode` Mermaid 佈景主題時，子圖改以外框呈現而非填滿，讓巢狀子圖更醒目。

![圖：含巢狀子圖的 Mermaid 圖表在變更前後的對照：邊不再穿過子圖標題，且子圖改以外框呈現而非填滿。](https://code.visualstudio.com/assets/updates/1_145/mermaid-subgraph-titles-before-after.webp)

## [企業](https://code.visualstudio.com/updates/v1_145#_enterprise)

### [組織要求的外掛無法解除安裝](https://code.visualstudio.com/updates/v1_145#_organization-required-plugins-cant-be-uninstalled)

當你的組織要求使用某個 [agent 外掛](https://code.visualstudio.com/docs/agent-customization/agent-plugins)（例如透過 `enabledPlugins` 受管理設定）時，**Customizations** 檢視過去仍會為它提供 **Uninstall**。該動作一定會失敗，並變成 **Retry Uninstall**，而這個動作同樣會失敗。外掛所提供的提示詞、skill、agent、hook 與 MCP 伺服器也有相同情況。

```json
{
  "enabledPlugins": {
    "my-plugin@my-marketplace": true
  }
}
```

這些外掛及其提供項目的 **Uninstall** 動作現在已停用，並會在滑鼠停留與鍵盤聚焦時顯示訊息。此行為適用於 **Browse**、外掛詳細資料、外掛編輯器，以及外掛與 MCP 伺服器的功能表。

![圖：Browse customizations 中一個組織要求的外掛，其 Uninstall 按鈕已停用，滑鼠停留提示說明該外掛由你的組織管理。](https://code.visualstudio.com/assets/updates/1_145/managed-plugin-uninstall-disabled.webp)

### [受管理的 MCP 允許清單優先於僅限登錄存取](https://code.visualstudio.com/updates/v1_145#_managed-mcp-allowlists-take-precedence-over-registry-only-access)

過去，當組織將 MCP 限制為只能使用其登錄中的伺服器，又在受管理設定中定義了允許清單時，VS Code 仍然要求每個伺服器都必須在登錄中。允許清單已核准、但未發布到登錄的伺服器無法執行。

企業管理的 `allowedMcpServers` 清單現在具有最終決定權。符合清單的伺服器即使不在登錄中也能執行，而不符合清單的登錄伺服器則會被封鎖。例如，下列[企業受管理設定](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)允許一個遠端伺服器與一個本機伺服器：

```json
{
  "allowedMcpServers": [
    { "serverUrl": "https://mcp.example.com/mcp" },
    { "serverCommand": ["node", "approved-server.js"] }
  ]
}
```

- 空清單（`[]`）會封鎖所有伺服器。若沒有此清單，則照舊套用登錄限制。
- 使用者與工作區的允許清單無法將伺服器加入企業清單。
- `deniedMcpServers` 與關閉 MCP 仍優先於允許清單。
- 建議優先使用 `serverUrl` 與 `serverCommand` 規則。`serverName` 規則比對的是由伺服器作者自行選擇的標籤。

> **注意**：此變更適用於由 VS Code 啟動的 MCP 伺服器，不適用於由 Agent Host 管理的伺服器。

### [GitHub Pull Requests](https://code.visualstudio.com/updates/v1_145#_github-pull-requests)

[GitHub Pull Requests](https://marketplace.visualstudio.com/items?itemName=GitHub.vscode-pull-request-github) 擴充功能有更多進展，此擴充功能讓你處理、建立與管理 pull request 與 issue。新功能包括：

## [已棄用的功能與設定](https://code.visualstudio.com/updates/v1_145#_deprecated-features-and-settings)

### [本版新棄用項目](https://code.visualstudio.com/updates/v1_145#_new-deprecations-in-this-release)

#### [Install Extension 工具已從 Local harness 移除](https://code.visualstudio.com/updates/v1_145#_install-extension-tool-removed-from-the-local-harness)

**Install Extension**（`#installExtension`）agent 工具在 Local agent session 中已不再提供。當你從聊天建立新工作區時，agent 不再安裝擴充功能。取而代之的是，它會將專案需要的擴充功能加入 `.vscode/extensions.json`，讓你可以從 Extensions 檢視檢閱並安裝它們。當你在沒有 Jupyter 擴充功能的情況下於 Jupyter 筆記本中執行 Python 儲存格時，核心（kernel）選擇器會提示你安裝它。

如果你的自訂 agent 或提示檔參考了 `#installExtension`，請移除該參考。

#### [Run VS Code Command 工具已從 Local harness 移除](https://code.visualstudio.com/updates/v1_145#_run-vs-code-command-tool-removed-from-the-local-harness)

**Run VS Code Command**（`#runCommand`）agent 工具在 Local agent session 中已不再提供。原本仰賴它的內建工作流程，現在不需要它也能運作。例如，當聊天診斷網路問題時，它會請你執行 **Developer: Chat Diagnostics** 並分享報告。

如果你的自訂 agent 或提示檔參考了 `#runCommand`，請移除該參考。

#### [工作區建立工具與斜線命令已從 Local harness 移除](https://code.visualstudio.com/updates/v1_145#_workspace-creation-tool-and-slash-command-removed-from-the-local-harness)

**Create New Workspace**（`#newWorkspace`，先前為 `#new`）agent 工具與 `/new` 斜線命令在 Local agent session 中已不再提供。Welcome 頁面上的 **Generate New Workspace** 連結也不再提供。專用的專案設定 skill 已移除。

若要建立專案，請開啟一個空資料夾，並在 agent session 中描述你想要的專案。Agent 會使用其標準工具建立檔案、執行 scaffolding 命令並設定工作（task）。

請從你的自訂 agent 與提示檔中移除對 `#newWorkspace`、`#new`、`/new`、`project-setup-info-local` 與 `project-setup-info-context7` 的參考。`github.copilot.chat.newWorkspaceCreation.enabled`、`github.copilot.chat.newWorkspace.useContext7` 與 `github.copilot.chat.useProjectTemplates` 設定也已移除。筆記本的建立方式不變。
