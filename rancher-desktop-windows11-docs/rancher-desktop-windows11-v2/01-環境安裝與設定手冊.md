# 01｜Windows 11 + Rancher Desktop 環境安裝與設定手冊

更新日期：2026-11-06

## 1. 目標與範圍

讓 Windows 11 原生 Visual Studio 2022、Rider、PowerShell 執行 .NET 測試，透過 Rancher Desktop 提供的 Windows Docker Named Pipe 操作 WSL2 中的 **Moby / dockerd**，僅使用 Linux Containers。提供 GUI、Docker CLI、Docker Compose。**不安裝 Docker Desktop**，也不手動在 Ubuntu 安裝另一套 Docker Engine。

## 2. 安裝前檢查

- Windows 11 已更新，BIOS/UEFI 已開啟硬體虛擬化；公司政策允許 WSL2 與 Rancher Desktop。
- 有足夠磁碟空間下載 Linux Images（建議至少預留 30 GB，依 SQL Server/Kafka 數量調整）。
- 建議 RAM 16 GB 起，32 GB 以上較適合同時執行多個資料庫容器；依實際測試負載調整。
- 若電腦先前裝過 Docker Desktop，先確認它已停止；避免兩套 runtime 同時佔用 Docker Context/Named Pipe。無須為了安裝 Rancher Desktop 而先刪除所有舊資料，應先備份必要的 volumes。

PowerShell（系統管理員）：

```powershell
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsBuildNumber
wsl --version
wsl --status
wsl --list --verbose
```

## 3. 安裝 WSL2，並將 Ubuntu 放在 D 槽指定目錄

### 3.1 先釐清 Ubuntu 與 Rancher Desktop 的資料位置（重要）

這次的新增需求是：**Ubuntu 24.04 的 WSL2 發行版必須安裝在 `D:\docker\wsl\ubuntu-24.04`**。建議將 `D:\docker\wsl\` 作為根目錄，分別存放不同發行版，而不是讓所有發行版共用同一個安裝目錄。

但 **Rancher Desktop 並不使用這個 Ubuntu 發行版來執行 Moby**：它會自行建立、管理專屬的 WSL 發行版與容器資料。把 Ubuntu 放到 D 槽，**不等於** Rancher Desktop 的 Images、Volumes、Container 資料也搬到 D 槽。若目標是避免 Docker 容器大量佔用 C 槽，還必須另外確認 Rancher Desktop 的資料磁碟位置；見 3.5 節。

建議目錄規劃：

```text
D:\docker\wsl\
├── ubuntu-24.04\         # 使用者自行安裝的 Ubuntu WSL2
├── backups\             # WSL 匯出備份（視空間需求）
└── rancher-data\         # 僅為預留規劃，非 Rancher Desktop 自動使用的路徑
```

### 3.2 安裝 WSL 平台（不先安裝預設 Ubuntu）

在 **PowerShell（系統管理員）** 執行：

```powershell
wsl --install --no-distribution
wsl --update
wsl --set-default-version 2
wsl --version
wsl --status
```

依提示重新開機。建立資料夾：

```powershell
New-Item -ItemType Directory -Force 'D:\docker\wsl\ubuntu-24.04' | Out-Null
```

### 3.3 全新安裝 Ubuntu 24.04：優先使用 `--location`

新版 WSL 支援 `wsl --install` 的 `--location` 選項時，可執行：

```powershell
wsl --list --online
wsl --install -d Ubuntu-24.04 --location 'D:\docker\wsl\ubuntu-24.04'
wsl --list --verbose
```

**必須先檢查本機 `wsl --help` 是否列出 `--location`**；不同 WSL 版本不一定支援。若命令不支援，不要直接改成一般的 `wsl --install -d Ubuntu-24.04`（那可能會裝回預設 C 槽位置），請採用 3.4 節的匯入方式。首次啟動後完成 Linux 使用者初始化，並確認 `VERSION` 為 `2`：

```powershell
wsl -d Ubuntu-24.04
wsl --list --verbose
```

### 3.4 `--location` 不支援時：透過 `wsl --import` 指定 D 槽

取得 **可信任的 Ubuntu 24.04 WSL rootfs tar**（須符合公司軟體來源政策），例如暫存於 `D:\docker\downloads\ubuntu-24.04-rootfs.tar`。先確認來源與架構，再執行：

```powershell
wsl --import Ubuntu-24.04 'D:\docker\wsl\ubuntu-24.04' `
  'D:\docker\downloads\ubuntu-24.04-rootfs.tar' --version 2
wsl --list --verbose
wsl -d Ubuntu-24.04
```

**注意**：`--import` 建立的發行版通常以 `root` 作為預設登入使用者；它不像 Store 安裝版一定會自動進行建立一般使用者的精靈。進入 Ubuntu 後建立帳號並設定預設使用者：

```bash
adduser developer
usermod -aG sudo developer
printf '[user]\ndefault=developer\n' > /etc/wsl.conf
```

將 `developer` 換成團隊規範的 Linux 使用者名稱，接著在 Windows PowerShell 執行：

```powershell
wsl --terminate Ubuntu-24.04
wsl -d Ubuntu-24.04 -- whoami
```

如果已有 Ubuntu 安裝在 C 槽，**不要直接搬動 `ext4.vhdx` 或先執行 `wsl --unregister`**。應先 `wsl --export` 備份，再 `wsl --import` 到新目錄，驗證內容完整後才考慮移除原發行版；匯入時需使用不同的發行版名稱以避免衝突。`wsl --unregister` 會永久刪除該發行版的資料。

### 3.5 Rancher Desktop 的 WSL 資料位置：獨立驗證

**不要把 `D:\docker\wsl\ubuntu-24.04` 當成 Rancher Desktop 的 Docker 資料目錄。** Rancher Desktop 會管理自己的 WSL 發行版；實際名稱、磁碟檔位置及可否透過 GUI 指定儲存位置，依 Rancher Desktop 版本而異。

在安裝 Rancher Desktop **前後** 分別記錄：

```powershell
wsl --list --verbose
Get-ChildItem "$env:LOCALAPPDATA\rancher-desktop" -Recurse -Filter '*.vhdx' `
  -ErrorAction SilentlyContinue | Select-Object FullName, Length
```

這只是常見路徑的檢查，**不保證涵蓋所有版本的資料檔案**。若要求 Docker Images / Volumes 也必須位於 D 槽，應先確認所安裝的 Rancher Desktop 版本是否提供**官方支援的資料位置設定或遷移流程**，並以實際 `wsl --list` 與 VHDX 路徑驗收；未確認前不得宣稱已達成「所有 Docker 資料都在 D 槽」。**不建議自行對 Rancher Desktop 管理的發行版執行 `wsl --unregister`、手動移動 VHDX 或建立 junction/symlink**，這可能破壞平台狀態或造成容器資料遺失。

### 3.6 重要區分

- **Ubuntu 放 D 槽**：本章 3.3 或 3.4 可達成，供 Linux 工具與其他 WSL 工作使用。
- **Rancher Desktop Docker 資料放 D 槽**：是另一個獨立需求，須依特定 Rancher Desktop 版本的官方支援方式處理。
- **原生 Windows .NET Testcontainers**：仍使用 Rancher Desktop 的 Moby Named Pipe，**不需要**在上述 Ubuntu 另外安裝 Docker Engine。


## 4. 安裝 Rancher Desktop

1. 前往 https://github.com/rancher-sandbox/rancher-desktop/releases ，選定經團隊驗證的穩定版，下載 Windows MSI（例如 `Rancher.Desktop.Setup.X.Y.Z.msi`）。
2. 依公司安裝政策執行安裝。官方說明一般使用者可執行 Rancher Desktop，但安裝 Privileged Service 等元件可能需要系統管理員權限。
3. 首次啟動後，於 **Preferences → Container Engine** 選擇 **moby (dockerd)**。
4. 於 **Preferences → Kubernetes** 取消 **Enable Kubernetes**。
5. 等待初始化完成。不同版本的選單與提示可能略有差異。
6. 需要透過非 localhost 網卡發布容器服務時，可能需要 Privileged Service；本手冊的本機測試只要求 localhost。

若已可使用 `rdctl`，也可透過 PowerShell 執行（以實際版本支援的選項為準）：

```powershell
rdctl set --container-engine.name=moby
rdctl set --kubernetes-enabled=false
```

## 5. 驗證 Windows Docker CLI / Compose

**使用新開啟的 PowerShell**（確保 PATH 已更新）：

```powershell
Get-Command docker, rdctl -ErrorAction SilentlyContinue
docker version
docker info
docker context ls
docker compose version
docker run --rm hello-world
```

驗收重點：`docker version` 同時列出 Client/Server；`docker info` 能顯示 Linux Engine；`docker compose version` 有回應；`hello-world` 成功。若 `docker` 指向其他舊版安裝，先用 `Get-Command docker -All` 與 `where.exe docker` 檢查 PATH，再排除衝突。不要直接刪除未知程式。

## 6. Windows 原生 Testcontainers 的 Docker API

Rancher Desktop 官方 Windows 指引使用：

```powershell
$env:DOCKER_HOST = 'npipe:////./pipe/docker_engine'
Remove-Item Env:DOCKER_CONTEXT -ErrorAction SilentlyContinue
Remove-Item Env:TESTCONTAINERS_HOST_OVERRIDE -ErrorAction SilentlyContinue
Remove-Item Env:TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE -ErrorAction SilentlyContinue
```

這些命令只影響目前 PowerShell 及其啟動的子程序。Windows 原生測試不應設定 `TESTCONTAINERS_HOST_OVERRIDE`；映射 Port 通常使用 localhost。不要把 `DOCKER_HOST` 設成未驗證的 TCP 2375。

注意：**Docker CLI 能運作不代表 Testcontainers 已通過驗收**。必須依第二份文件實測 API、Ryuk 與 Port Mapping。

## 7. 驗證 Linux Container 與 Windows localhost

```powershell
docker run -d --name rd-redis-smoke -p 127.0.0.1:16379:6379 redis:7-alpine
docker ps
docker exec rd-redis-smoke redis-cli ping
Test-NetConnection 127.0.0.1 -Port 16379
docker logs rd-redis-smoke
docker rm -f rd-redis-smoke
```

預期 `PONG` 與 `TcpTestSucceeded : True`。測試使用固定 16379 僅為示範；若該 Port 已占用，換成其他未占用 Port。正式 Testcontainers 測試應使用**動態映射 Port**。

## 8. Docker Compose 範例

建立 `compose.yaml`：

```yaml
services:
  redis:
    image: redis:7-alpine
    ports:
      - '127.0.0.1:16379:6379'
    restart: unless-stopped
```

於該目錄執行：

```powershell
docker compose up -d
docker compose ps
docker compose logs --tail 50
docker compose down
```

`docker compose down` 預設不刪除 named volumes；`docker compose down -v` 會刪除 Compose 管理的 volumes，可能導致資料遺失，請勿作為一般清理指令。

## 9. GUI 管理操作

Rancher Desktop 是本機容器平台及圖形管理入口，可檢視/管理容器、Images 與平台設定；實際容器 Logs、Console、Volumes、Networks、Compose Stacks 的 GUI 功能會依版本不同，**不能預設與 Docker Desktop 或 Portainer 等價**。操作時可搭配：

```powershell
docker ps -a
docker images
docker logs --tail 100 <container-name>
docker exec -it <container-name> sh
docker volume ls
docker network ls
docker compose ls
```

需要更完整的 Web GUI 時，可在 POC 完成後另行評估 Portainer CE；Portainer 並不是必要組件，也不應另外建立第二個 Docker Engine。

## 10. 資源配置

WSL2 記憶體/CPU 可透過 `%USERPROFILE%\.wslconfig` 控制，但此檔設定會影響 **所有 WSL2 發行版**，不是 Rancher Desktop 專用。示例（32 GB 主機的起點，非通用標準）：

```ini
[wsl2]
memory=12GB
processors=6
swap=4GB
```

修改後必須關閉 Rancher Desktop，再執行 `wsl --shutdown`，重新啟動 Rancher Desktop。不要在容器正在寫入資料時強制關閉 WSL。

## 11. 重要限制

- **Ubuntu 安裝路徑與 Rancher Desktop 的容器資料路徑不同**；若 D 槽是強制儲存規範，Rancher Desktop 的資料位置必須另外驗收。

- 不支援 Windows Containers；本方案全部使用 Linux Images。
- SQL Server Linux Image 需確認 CPU 架構、EULA、RAM 需求與版本支援；在 x64 Windows/WSL2 的 Linux AMD64 容器較適合此情境。
- 若公司代理伺服器、VPN、憑證攔截導致 Image Pull 失敗，需走公司核准的代理/CA 設定。
- Rancher Desktop 需要 WSL2；若公司完全禁止 WSL2，則本方案不適用。
