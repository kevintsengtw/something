# 01｜Windows 11 環境安裝與設定手冊（V4）

修訂：2026-11-06｜適用：Windows 11、Windows 原生 Visual Studio / Rider、僅 Linux Containers。

## 1. 安裝前先理解架構（必讀）

**WSL2 是執行平台，Ubuntu 是可選的 Linux 發行版。Rancher Desktop 不需要使用者預先安裝 Ubuntu。**

```text
Windows 11
├─ IDE / dotnet test / xUnit / Testcontainers
├─ Rancher Desktop GUI + docker CLI + Compose
│  └─ Docker API：Windows Named Pipe
└─ WSL2 平台
   └─ Rancher Desktop 專用 WSL Linux 環境
      ├─ Moby（dockerd）+ containerd
      └─ Linux Images / Containers / Volumes
```

Rancher Desktop 的 Windows 應用程式負責 GUI、整合與管理；Moby 是在其管理的 **Linux WSL 環境**中執行，**不是 Windows 原生 Docker Engine，也不是另裝的 Ubuntu**。Windows 原生測試程式透過 Named Pipe 控制容器，再透過 localhost + 映射埠連線到資料庫。

## 3. 儲存架構與 D 槽目標

**本方案不安裝 Ubuntu，也不在 Windows 安裝獨立 Docker Engine。** Rancher Desktop 的 Windows GUI 管理自己的 WSL2 發行版，Moby/dockerd 在該 Linux 環境內執行。要移動的是 **Rancher Desktop 的 WSL 發行版虛擬磁碟**，而非「Moby Windows 安裝資料夾」。

目標路徑：

```text
D:\docker\wsl\
├── rancher-desktop\          # 如此發行版存在，放置執行環境
├── rancher-desktop-data\     # 如此發行版存在，放置持久化資料
└── backups\                  # 搬移前備份
```

**版本差異：** `rancher-desktop-data` 並非每個版本都會出現。務必依 `wsl -l -v` 的實際結果決定搬移對象，不要自行建立或假設存在。搬移後 VHDX 的實際檔名及位置以 WSL 註冊資訊為準。Rancher Desktop Factory Reset 可能重建發行版並回到預設路徑。

### 3.1 為何採用 `wsl --manage --move`

Rancher Desktop 維護者在專案討論中認可使用 WSL 發行版搬移方法，後續回覆提出較新的 `wsl --manage <distro> --move <new_location>` 方法。這屬於 **WSL 層級的搬移**，不是 Rancher Desktop 安裝程式內建的「資料磁碟位置」設定。仍須依安裝版本完成搬移後啟動、更新與資料持久化驗收。

參考：
- https://github.com/rancher-sandbox/rancher-desktop/discussions/6296
- https://learn.microsoft.com/en-us/windows/wsl/basic-commands

## 4. 安裝 WSL2 平台（不安裝 Ubuntu）

PowerShell（管理員）：

```powershell
wsl --install --no-distribution
wsl --update
wsl --version
wsl --status
```

如有提示，重新開機。BIOS/UEFI 虛擬化必須啟用。公司管理的電腦可能需要 IT 核准 Windows 功能與虛擬化設定。

**不要執行 `wsl --install -d Ubuntu`；也不需要在 Ubuntu 安裝 `docker-ce`。**

## 5. 安裝 Rancher Desktop

1. 從官方發行頁下載 Windows MSI：https://github.com/rancher-sandbox/rancher-desktop/releases
2. 依公司 IT 核准流程安裝。Windows 安裝可能需要管理員權限；官方說明有可選的 Privileged Service，未安裝時主機服務曝光範圍可能受限於 `127.0.0.1`。
3. 首次啟動選 **Moby / dockerd**，不是 containerd。
4. **停用 Kubernetes**，避免額外資源消耗。
5. 啟用 Rancher Desktop CLI PATH 整合；若已安裝其他 docker.exe，檢查 PATH 衝突。
6. 確認 GUI 可以顯示 Images、Containers；GUI 不等同 Portainer 全部功能，CLI 是必要的管理補充。

## 6. 首次初始化後：將 Rancher Desktop WSL 搬移到 D 槽（必要步驟）

**順序不可顛倒：先啟動 Rancher Desktop，選擇 Moby、停用 Kubernetes，等待初始化完成，再關閉並搬移。** 不需要 Ubuntu，也不需要 `apt install docker-ce`。

### Step 1｜列出實際 WSL 發行版及確認版本

在 PowerShell 執行：

```powershell
wsl --version
wsl --help
wsl --list --verbose
```

確認 WSL 支援 `--manage <DistributionName> --move <Location>`。若 `wsl --help` 未顯示該功能，先執行 `wsl --update`，更新後重新確認；仍不支援時**暫停搬移**，不要改用會刪除發行版的 `--unregister` 指令。`wsl --list --verbose` 應至少能看到 `rancher-desktop`；`rancher-desktop-data` 只在確實存在時才搬移。

### Step 2｜確認 D 槽可用空間與建立備份

```powershell
Get-Volume -DriveLetter D
New-Item -ItemType Directory -Force 'D:\docker\wsl\backups'
```

若已有重要 Images/Volumes/Containers，請先以容器層級方法備份必要資料，並於 Rancher Desktop **完全結束且 WSL 停止後**備份發行版：

```powershell
# 先從系統匣選 Quit / Exit Rancher Desktop
wsl --shutdown
wsl --export rancher-desktop 'D:\docker\wsl\backups\rancher-desktop.tar'
# 只有實際存在此發行版才執行：
# wsl --export rancher-desktop-data 'D:\docker\wsl\backups\rancher-desktop-data.tar'
```

匯出需要足夠磁碟空間；備份檔包含容器資料，應依公司規範保護。若為全新空白環境，可將匯出列為選用，但正式團隊遷移應備份。

### Step 3｜關閉 Rancher Desktop、停止 WSL

```powershell
wsl --shutdown
wsl --list --verbose
```

**確認 Rancher Desktop GUI 已完全退出，且相關發行版狀態為 `Stopped`**。不要只關閉 GUI 視窗卻讓背景程序繼續運作。

### Step 4｜執行搬移（僅對實際存在的發行版）

```powershell
New-Item -ItemType Directory -Force 'D:\docker\wsl'

# 先搬移持久化資料發行版（僅在 wsl -l -v 確認存在時執行）
wsl --manage rancher-desktop-data --move 'D:\docker\wsl\rancher-desktop-data'

# 再搬移執行環境
wsl --manage rancher-desktop --move 'D:\docker\wsl\rancher-desktop'
```

**如果只列出 `rancher-desktop`，請跳過第一條 `rancher-desktop-data` 搬移命令。** 目的目錄應為可供 WSL 使用的空位置；若路徑已存在且有檔案，不要覆蓋。每次搬移後確認命令成功，再進行下一個；失敗時停止，保留備份並先調查錯誤。

### Step 5｜確認登錄路徑及 VHDX 實際位置

```powershell
Get-ChildItem 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss' |
  ForEach-Object {
    Get-ItemProperty $_.PSPath |
      Where-Object { $_.DistributionName -like 'rancher-desktop*' } |
      Select-Object DistributionName, BasePath
  }

Get-ChildItem 'D:\docker\wsl' -Recurse -Filter '*.vhdx' |
  Select-Object FullName, Length
```

**驗收標準：** 所有實際存在的 Rancher Desktop WSL 發行版 `BasePath` 都位於 `D:\docker\wsl\` 之下；並能在 D 槽找到對應虛擬磁碟。這不代表 Rancher Desktop Windows 應用程式或暫存檔完全不占用 C 槽。

### Step 6｜重新啟動並做持久化驗收

啟動 Rancher Desktop，確認仍使用 Moby 且 Kubernetes 停用。PowerShell：

```powershell
docker version
docker info --format '{{.OSType}} | {{.ServerVersion}}'
docker compose version
docker run --rm hello-world
docker pull redis:7-alpine
docker image ls
wsl --list --verbose
```

重新結束並啟動 Rancher Desktop 後再次檢查 `docker image ls`，確認剛下載的 Redis Image 仍存在；再重查 `BasePath` 是否仍指向 D 槽。接著執行文件 02 的 Testcontainers、Redis、MsSql、Ryuk 驗收。

### 搬移失敗時的原則

- **禁止直接刪除或手動拖曳使用中的 `.vhdx`。**
- **禁止為了重試而執行 `wsl --unregister`**；此命令會刪除發行版資料。
- 先檢查 WSL 版本、發行版是否停止、D 槽可用空間與權限、目標路徑是否已存在。
- 若已搬移但 Rancher Desktop 無法啟動，保留備份、收集日誌，不要直接 Factory Reset。
- Rancher Desktop 更新或 Factory Reset 後重新驗證 `BasePath`；Factory Reset 可能使資料被清除並重新建立於預設位置。

## 7. 驗證 Docker CLI / Engine / Compose

```powershell
where.exe docker
docker version
docker info
docker context ls
docker compose version
docker run --rm hello-world
wsl --list --verbose
```

`docker info` 應顯示 Linux Server；如果指向 Docker Desktop 或其他遠端 Engine，先排除 Docker Context／環境變數衝突。

## 8. Windows 原生 Docker API

建議先使用 Rancher Desktop 預設 Docker API 設定；如需明確指定，可在**啟動 IDE 之前**的 PowerShell 測試：

```powershell
$env:DOCKER_HOST = 'npipe:////./pipe/docker_engine'
Remove-Item Env:DOCKER_CONTEXT -ErrorAction SilentlyContinue
Remove-Item Env:TESTCONTAINERS_HOST_OVERRIDE -ErrorAction SilentlyContinue

docker version
```

Named Pipe 名稱及可用性應以實際 Rancher Desktop 版本驗證；不要同時設定互相衝突的 DOCKER_HOST、DOCKER_CONTEXT。**Windows 本機執行 Testcontainers 通常不應設定 TESTCONTAINERS_HOST_OVERRIDE**，先使用 Testcontainers 自動偵測。

## 9. 驗證 Linux Container 的 Windows localhost 連線

```powershell
docker run -d --name rd-redis-check -p 127.0.0.1:16379:6379 redis:7-alpine
docker exec rd-redis-check redis-cli ping
Test-NetConnection 127.0.0.1 -Port 16379
docker rm -f rd-redis-check
```

預期 `PONG`、`TcpTestSucceeded : True`。若失敗，檢查 Rancher Desktop 是否啟動、WSL2 網路、防火牆、Port 衝突。

## 10. 資源與安全

- WSL2 記憶體、CPU 可由 `%USERPROFILE%\.wslconfig` 控制（如有需要，先量測再設定）。
- SQL Server / Kafka 等容器需額外 RAM；不要把 WSL2 記憶體上限設得過低。
- 避免不必要的 `0.0.0.0` Port 發布；優先綁定 `127.0.0.1`。
- 不開放未認證的 Docker TCP 2375；勿將 Docker Socket 暴露給不受信任的程式。
- 映像檔（例如 SQL Server）有其獨立授權條款，應由公司確認。
