# 03｜團隊部署標準、授權審核與故障排除（V4）

## 1. 團隊標準架構

Windows 11 原生 IDE + .NET Testcontainers → Rancher Desktop Windows Named Pipe → Rancher Desktop 專用 WSL2 Linux + Moby。**不安裝 Docker Desktop、不安裝 Ubuntu、不安裝第二套 Docker Engine；僅使用 Linux Containers。**

## 2. 公司授權審核

| 項目 | 結論 | 管控 |
|---|---|---|
| Rancher Desktop | Apache-2.0，允許公司商用 | 保留授權、確認版本與第三方 NOTICE |
| Docker Desktop | 不在本方案中安裝 | 其大型企業訂閱限制不可誤套用到 Rancher Desktop |
| Moby / Docker CLI / Compose | 開源元件，非 Docker Desktop 產品 | 核對所用版本、第三方授權 |
| SQL Server、其他容器映像 | 依映像各自條款 | 交由法務／資安／採購審核 |
| 公司電腦安裝 | 授權允許不等於公司政策允許 | 需經 IT 軟體安裝、虛擬化與資安審核 |

**重要區分：** Rancher Desktop 的 Apache-2.0 授權不因公司員工人數或營收而自動變成付費；Docker Desktop 訂閱條款是另一產品的契約。這不是法律意見，企業正式採購／安裝應由內部法務確認。

## 3. 安裝與儲存政策

- WSL2：`wsl --install --no-distribution`。
- Rancher Desktop：Windows MSI、Moby、Kubernetes Disabled。
- Ubuntu：**不得列為此方案必要步驟**。
- Docker CLI / Compose：使用 Rancher Desktop 配套工具，避免多套 docker.exe 混用。
- D 槽：Rancher Desktop 首次初始化、選擇 Moby 後，**完全結束 Rancher Desktop**，使用支援 `--manage --move` 的 WSL 將實際存在的 `rancher-desktop` 與（如存在）`rancher-desktop-data` 移至 `D:\docker\wsl\`。詳見文件 01 第 6 節。
- 搬移後以 WSL 登錄 BasePath、VHDX 位置、重啟後 Docker Image 持久化及 Testcontainers 驗收四項證據確認；不同 Rancher Desktop 版本可能只有一個發行版。
- 不允許將 `wsl --install -d Ubuntu --location ...` 當作 Rancher Desktop 儲存遷移方案。
- 禁止未備份直接 `wsl --unregister`；這會刪除對應發行版資料。

## 4. 版本與變更控制

記錄 Windows build、WSL 版本、Rancher Desktop 版本、Moby/Docker Server 版本、Compose 版本、.NET SDK、Testcontainers 套件版本、SQL Server 映像 tag、Rancher Desktop 資料位置。升級先在 POC 電腦驗證，完成 Redis、MsSql、Ryuk 與兩套 IDE 測試後再推廣。

## 5. 診斷腳本（PowerShell）

```powershell
$ErrorActionPreference = 'Continue'
Write-Host '=== WSL ==='
wsl --version
wsl --list --verbose
Write-Host '=== Docker CLI ==='
where.exe docker
docker context ls
docker version
docker info --format '{{.OSType}} | {{.ServerVersion}}'
docker compose version
Write-Host '=== Docker environment ==='
Get-ChildItem Env:DOCKER*, Env:TESTCONTAINERS* -ErrorAction SilentlyContinue
Write-Host '=== WSL storage registration ==='
Get-ChildItem 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss' -ErrorAction SilentlyContinue |
  ForEach-Object { Get-ItemProperty $_.PSPath | Select-Object DistributionName, BasePath }
```

**診斷輸出可能包含公司環境資訊，分享前應檢查並遮蔽敏感資料。**

## 6. 故障排除

### Docker Client 能執行，但 Server 無法連線

檢查 Rancher Desktop 是否啟動、Container Engine 是否 Moby、`docker context ls`、`DOCKER_HOST` 是否指向舊 Docker Desktop 或遠端 Engine、Named Pipe 是否存在。

### Testcontainers 找不到 Docker

先執行 `docker version`，再在同一 PowerShell 會話設定 `DOCKER_HOST=npipe:////./pipe/docker_engine` 進行 POC；移除衝突的 `DOCKER_CONTEXT`，不要預設設定 `TESTCONTAINERS_HOST_OVERRIDE`。

### 容器可啟動，但 SQL Server 連不上

確認 `GetMappedPublicPort`、Windows localhost Port、WSL2 網路與防火牆；檢查 SQL Server Log，使用 `SqlConnection.OpenAsync()` 驗證實際就緒；避免固定 Host Port 造成並行衝突。

### Ryuk 失敗

檢查 API 權限、容器網路、公司防毒或端點管制；不要以關閉 Ryuk 作為預設修復。

### C 槽仍被占用

檢查 Rancher Desktop 的 WSL 持久化磁碟 BasePath；安裝在 D 槽的**另一套 Ubuntu 不會移動 Rancher Desktop 資料**。暫停團隊部署，依文件 01 第 6 節檢查 WSL 發行版是否已透過 `wsl --manage --move` 搬移、BasePath 是否位於 D 槽；Factory Reset 後可能需要重新搬移。不要直接移動使用中的 VHDX。

### GUI 不足以管理所有容器功能

使用 `docker ps`、`docker logs`、`docker exec`、`docker volume ls`、`docker network ls`、`docker compose` 補足；若確有需求再獨立評估 Portainer CE 的維運與安全成本。

## 7. 備份、重設與卸載

- 先辨識持久化 Volume、重要映像與測試資料；容器本身通常可重建，但 Volume 未必可重建。
- Rancher Desktop Factory Reset 可能清除容器資源；執行前先備份並確認版本行為。
- `wsl --unregister rancher-desktop` / `rancher-desktop-data` 會刪除相關資料，僅可在備份與變更核准後執行。
- WSL2 虛擬磁碟可能在刪除容器後仍維持較大檔案尺寸；不要直接修改或刪除 VHDX。

## 8. 正式部署驗收門檻

- [ ] 公司法務／資安已審核 Rancher Desktop Apache-2.0 與映像授權。
- [ ] Windows 11、WSL2、Rancher Desktop + Moby 正常；沒有多裝 Ubuntu。
- [ ] Kubernetes 關閉、Docker API 與 Compose 可用。
- [ ] Windows 原生 `dotnet test`、Visual Studio、Rider 測試通過。
- [ ] Redis、MsSql、Ryuk、並行測試完成驗證。
- [ ] **已證明 Rancher Desktop 實際 WSL 發行版及持久化資料位於 D 槽，並完成重啟與資料持久化測試**；若無法做到，正式部署暫緩或由需求方書面接受例外。
- [ ] 有備份／還原與升級回復計畫。

## 9. 搬移作業的團隊標準

1. 固定並記錄 Windows、WSL、Rancher Desktop 版本。
2. 初始化 Moby 並停用 Kubernetes；先確認 `wsl -l -v` 的實際發行版名稱。
3. 退出 Rancher Desktop，停止 WSL；既有環境先備份重要 Volumes 與發行版。
4. 使用 `wsl --manage <name> --move <D 槽路徑>`，**只搬移存在的發行版**。
5. 核對 `HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss` 的 BasePath 與 D 槽 VHDX。
6. 重啟 Rancher Desktop、執行 Docker CLI、Redis、MsSql、Ryuk、Visual Studio 與 Rider 驗收。
7. 升級及 Factory Reset 後重新檢查；未通過驗收不得標記完成。
