# 03｜團隊部署標準、維運與故障排除

更新日期：2026-11-06

## 1. 目的

建立 Windows 11 原生 .NET 開發團隊可複製的 Linux Container 測試環境，避免各開發者自行安裝不同 Docker Runtime、修改危險的 Docker API 設定，或因 IDE 環境變數不一致造成 Testcontainers 測試結果不同。

## 2. 標準化基準

| 項目 | 團隊基準 |
|---|---|
| OS | Windows 11，受公司管理政策約束 |
| IDE | Visual Studio 2022 / Rider |
| .NET | 依專案固定 SDK（8/9） |
| Runtime | Rancher Desktop + WSL2 + moby (dockerd) |
| Kubernetes | Disabled |
| Docker Desktop | 不安裝、不執行 |
| Windows Containers | 不使用 |
| Docker API | `npipe:////./pipe/docker_engine` |
| Testcontainers | 依專案 NuGet lock/中央套件版本控管 |
| GUI | Rancher Desktop；Portainer CE 暫不納入 |
| Images | 固定版本，必要時 pin digest；避免 `latest` |

Rancher Desktop、Docker Engine、Compose、Testcontainers、SQL Server Image 版本必須記錄在 POC 報告中，**不能將未經驗證的最新版直接列為團隊標準**。

## 3. 角色與責任

- 開發者：安裝已核准版本、執行環境檢查、保存測試錯誤資訊。
- 團隊技術負責人：維護版本矩陣、測試樣板、升級驗證與回復策略。
- IT/資安：核准 WSL2、虛擬化、Rancher Desktop、代理/憑證與防火牆政策。
- CI 維護者：另行設計 CI Runtime；不可直接假設桌面環境的設定適用於 Build Agent。

## 4. 建議安裝與驗收流程

1. 檢查硬體虛擬化、WSL2 與公司政策。
2. 安裝 WSL2，不額外安裝 Ubuntu Docker Engine。
3. 安裝團隊核准版本 Rancher Desktop，選擇 Moby、停用 Kubernetes。
4. 執行 Docker CLI/Compose Smoke Test。
5. 驗證 Named Pipe 與 Windows localhost Port Mapping。
6. 執行 Testcontainers POC：Alpine、Redis、SQL Server、Ryuk。
7. 分別驗證 Visual Studio Test Explorer、Rider Unit Tests。
8. 記錄版本、錯誤、驗收結果與例外處理。

## 5. 環境診斷腳本（PowerShell）

存成 `Test-RancherDesktopEnvironment.ps1`，於一般 PowerShell 執行：

```powershell
$ErrorActionPreference = 'Continue'
Write-Host '=== Windows / WSL ==='
[Environment]::OSVersion.VersionString
wsl --version
wsl --status
wsl --list --verbose

Write-Host '=== CLI paths ==='
Get-Command docker, rdctl -All -ErrorAction SilentlyContinue |
    Select-Object Name, Source

Write-Host '=== Docker ==='
docker version
docker context ls
docker info --format '{{.OSType}} | {{.ServerVersion}}'
docker compose version

Write-Host '=== Environment ==='
'DOCKER_HOST','DOCKER_CONTEXT','TESTCONTAINERS_HOST_OVERRIDE',
'TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE','TESTCONTAINERS_RYUK_DISABLED' |
    ForEach-Object {
        [pscustomobject]@{ Name = $_; Value = [Environment]::GetEnvironmentVariable($_) }
    } | Format-Table -AutoSize

Write-Host '=== Docker named pipe ==='
Test-Path '\\.\pipe\docker_engine'

Write-Host '=== .NET ==='
dotnet --info
```

診斷結果可能包含電腦名稱、安裝路徑或其他環境資訊；分享給團隊前請檢查並移除敏感內容。`Test-Path` 對 Named Pipe 的行為可能受 PowerShell/權限影響；最終仍以 Docker API 實際連線為準。

## 6. 常見問題與排除

### 6.1 `docker` 找不到

- 關閉並重新開啟 PowerShell。
- 執行 `Get-Command docker -All`、`where.exe docker`。
- 確認 Rancher Desktop 已完成安裝與 CLI PATH 設定。
- 避免同時使用其他 Docker CLI 的舊 PATH。

### 6.2 `Cannot connect to the Docker daemon`

- 確認 Rancher Desktop 已啟動並完成初始化。
- 確認 Container Engine 是 **moby**，不是 containerd。
- 檢查 `DOCKER_HOST` 是否指向 `npipe:////./pipe/docker_engine`。
- 檢查是否設定了衝突的 `DOCKER_CONTEXT`。
- 先用 `docker version` 驗證，再執行 `dotnet test`。

### 6.3 `Testcontainers could not find a valid Docker environment`

- 從同一個 PowerShell 工作階段執行 `dotnet test`。
- 確認 Testcontainers 的套件版本與執行時環境變數。
- 清除不必要的 `TESTCONTAINERS_HOST_OVERRIDE`、`DOCKER_CONTEXT`。
- 確認 Named Pipe 存在、可存取；如 CLI 成功但 .NET 失敗，保留 Testcontainers 診斷 Log。

### 6.4 Redis / SQL Server 容器 Running，但連線失敗

- 檢查 `container.Hostname` 與 `GetMappedPublicPort()`。
- 確認 Windows localhost Port 可用；檢查 VPN、防火牆、Port 占用。
- SQL Server 檢查 Image 啟動 Log、記憶體、EULA、連線字串及 `OpenAsync()`。
- 不要將 `Running` 等同於服務已 Ready。

### 6.5 Ryuk 無法啟動或清理

- 不要直接設定 `TESTCONTAINERS_RYUK_DISABLED=true`。
- 確認 Docker API、權限與 socket mount 可用。
- 檢查 Testcontainers 與 Ryuk Image 的拉取是否受代理/Registry 限制。
- 確認測試結束後容器是否真的殘留；保存 `docker ps -a` 與測試輸出。

### 6.6 Visual Studio 成功、Rider 失敗（或相反）

- 確認兩個 IDE 的啟動程序是否繼承相同環境變數。
- 完全關閉 IDE 後再從設定好變數的 PowerShell 啟動。
- 確認 .NET SDK、Test Adapter、Run Configuration 與測試平行化設定。
- Rider Docker GUI 連線設定不會自動套用至 xUnit Test Runner。

### 6.7 `docker compose` 不存在

- 執行 `docker compose version`，確認不是誤用舊版 `docker-compose`。
- 確認 Rancher Desktop 安裝的 CLI Plugins 可見。
- 檢查 PATH 與 `%USERPROFILE%\.docker\cli-plugins`。

### 6.8 WSL2 啟動失敗 / 記憶體不足

- `wsl --status`、`wsl --list --verbose`。
- 確認 Windows Features、虛擬化及公司端點政策。
- 檢查 `%USERPROFILE%\.wslconfig` 是否過度限制 RAM/CPU。
- 需要 `wsl --shutdown` 前，先停止測試並正常關閉 Rancher Desktop。

### 6.9 VPN / Proxy / Image Pull 失敗

- 檢查企業代理、Docker Hub 存取、私有 Registry 與憑證鏈。
- 使用公司核准的代理與 Registry Mirror；不要停用 TLS 憑證驗證作為永久解法。
- 針對 SQL Server、Ryuk、Redis 等測試 Image 記錄可存取的 Registry 來源。

## 7. 安全基準

- 禁止對外公開未認證 Docker API（例如 `tcp://0.0.0.0:2375`）。
- 不因為測試失敗就停用 Windows Defender、公司 EDR 或防火牆。
- 優先使用動態 Port；手動 Compose 範例預設只綁定 `127.0.0.1`。
- 不在原始碼或 Compose YAML 提交正式資料庫密碼、Token、私有 Registry 憑證。
- 對 Docker Engine 的存取視同高權限；只提供受信任的開發者。
- 不在共享主機使用 `docker system prune -a --volumes`。

## 8. 升級與回復流程

1. 記錄目前 Rancher Desktop、Docker Server、Compose、WSL、Testcontainers 套件與測試 Images 版本。
2. 備份重要 volumes / 資料；測試容器應可重建，不以容器本身作為備份。
3. 在一台 POC 電腦升級，先驗證 Docker CLI，再執行完整 Testcontainers 驗收。
4. 重複測試至少 3 次，包含 Visual Studio 與 Rider。
5. 確認無異常後再擴大部署；失敗則回到先前已核准版本，必要時依備份還原。
6. **Factory Reset 會影響本機容器/Images/Volumes，未備份前不得執行。**

## 10. GUI 延伸規劃

第一階段使用 Rancher Desktop GUI。若團隊需要更完整的容器 Log、Console、Volume/Network、Stack 管理，可另做 Portainer CE POC；**Portainer 是 GUI 擴充，不是 Docker Engine 替代品**。新增 Portainer 前應評估 Docker Socket 授權、管理員帳號、Port 暴露與資料保存。
